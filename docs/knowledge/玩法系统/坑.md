## 炼丹 / 出行丹药品级（2026-11-17，玩法系统 · 洞府流程）
- **"炼到 80% 多提示炉火失控，最终又练成；一直循环到材料用完才能退出"**（用户报）→ 不是两套进度（评品与"入火候"显示同一个 `g.ratio`）。真因：丹器房的 Space 既是"点朱印 = 开炉"（workshop_v2 `bindSpace`）又是"添火"，一炉结束时玩家还在点 Space，下一下就再开一炉、再扣一份料；上一炉的"炉火失控"提示挂 3 秒，正好叠在新一炉 80% 多的读数上；开炉中 Esc 被 `!this.fire` 吞掉、回洞府只弹"离不得人"，所以出不去 → 炼丹页 Space 要停手 `SPACE_QUIET` = 1.2 秒（距上次按 / 松 Space、距上一炉结束）才开炉；开炉中 Esc / 回洞府 / 切标签都走 `ui.fire.leave(then)` 确认离炉。**一个键在同一页有两个含义时，必须有"冷却 / 停手"隔开，否则连按会触发第二个含义。**
- **复现手法**：Playwright 点一次开炉后循环 `keyboard.down/up("Space")`（90ms），包一层 `cave.emit` 数 `cave:alchemy` 次数——改前 1 次点击 = 5 炉、材料 12→2。
- **回春 / 回气丹的药效不分品级**：局内快捷栏只是 `skills.potions[i].count` 一个数，`usePotion` 读的是固定的 `po.def`；品级只影响灵值（身陨损失、化灵）。带出去吃哪一枚只在结算 `syncPotions` 扣减时才决定。
- **kit.itemCell 的 `.cap` 是 nowrap 绝对定位**，64px 的格子放不下"回春丹·凡 1/1"，相邻格字叠在一起 → 多品级时写两行（名 / 品级 带/有），`.it.mq` 加大行距。

  3. **场景没有 Esc 菜单**：洞府（含心魔劫）、结算页按 Esc 什么都没有——洞府里也就没法进设置 / 回主页；
  4. **两个 window 捕获监听抢同一个 Esc**：功法匣弹层里 `LoadoutUI.key`（取消选中）和 `openLoadout` 的 onEsc（关闭）都在 window 捕获阶段，`stopPropagation` 挡不住同一节点上的其它监听 → 一次 Esc 关两层；暂停 → 设置时链条直接 `pause.toggle(false)`，也是一次关两层；
  5. **新加的层没接进 Esc 链**：F8 调试、构筑面板（`）开着时 Esc 弹出暂停，面板还在；首领入场演出中 Esc 弹暂停；奇遇对话框把 Esc 整个吞掉，无选项的对话也关不掉。
  → 统一修：`src/ui/esc.js` 弹层栈 + 场景兜底（规则见 本项目约定.md「Esc 规则」）。
- **同一节点上的多个监听，`stopPropagation` 不管用**：要么 `stopImmediatePropagation`，要么只留一个入口。esc.js 在模块加载时就注册 window 捕获监听，保证排在所有界面监听之前。
- **只删 DOM 不出栈 → 死层吞掉所有 Esc**：测试清理、`kit.clear` 换场景都会直接移除弹层 → `pushEsc(fn, { el })` 绑根元素，每次按键前清掉已离开 DOM 的层。
- **`block`（截其它键）会抢别人的快捷键**：洞府确认框一开始设了 block，把炼丹"离炉"确认框的 Enter 也截了 → 只有 kit 弹框和 Esc 菜单 block；洞府确认框不 block（洞府界面本来就在 `.cv-modal` 时忽略按键）。
- **Esc 菜单开着时底下场景还在响应**：洞府 `cave.update` 仍读 F、C / M 开设施 → 洞府场景在 `flow.paused` 时不调 `cave.update`；Esc 菜单 block 掉其它键（keyup 放行）。
- **脚本里的"PASS"要确认前提真的成立**：仓库确认框那条改前"通过"，是因为清理函数顺手把仓库页关了；瞄准那条一开始按 R，但练气四层只开 Q / E 两栏，根本没进瞄准。断言里同时记"打开前状态 b"并要求它为真。
- **配方没有 `recipe` 字段就被当成"已会"**（`recipeKnown` 里 `if (!r.recipe) return true`）→ 想"送了才会"的基础配方要加 `gift: true`，判定改为 `!r.gift || flags.recipes[r.id]`（2026-11-17）。
- **`tools/run.mjs` 的测试会争抢 CPU / GPU** → 当前默认 `RUN_MAX=1`，显式同样传 1，所有浏览器回归（含草图）共用 `work/.runslots`，性能绝不并发；别用 `timeout` 包着跑，否则排队期间就被杀，放后台等完成通知再读日志。旧“同时最多 3 个”的描述已作废（2026-11-18，任务1复核）。
