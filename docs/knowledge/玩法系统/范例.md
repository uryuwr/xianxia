# 玩法系统 · 范例

## 事实记录式任务（序章步骤引擎）
- 是什么：`src/game/run/prologue.js` 不按"弹提示 → 等玩家照做"推进，而是一直记录玩家做过的事实（`this.f`：拾取、采集、开箱、击杀、服丹、破盾、闪避、到过的地方…）。每一步的完成条件读事实；玩家提前做过的步骤到了就依次自动勾掉（"早已采得 ✓"），已做过的教学提示不再弹。
- 为什么好：不打断会玩的玩家，也不卡乱跑的玩家；顺序可以乱，测试里专门有"乱序通关"一段。
- 配套：刷怪受小节门槛约束（spawnAllowed），身陨在小节开头满血重来（onDeath）。
- 适用：任何教学、委托、成就类"做到某事"的系统。

## 宣纸手卷结算
- 是什么：`src/ui/screens/result.js`。题头行书大字 + 四字印；手卷从中间展开，段一"人"（立绘、装备、修为）、段二"所得"（按估价打包排格，未鉴定剪影依次揭晓）、段三"账"（用时、撤离点、斩妖、灵潮、遗失、委托、首次所见）、卷首竖排"所得"与带回估价。
- 为什么好：一屏读完一局；揭晓演出给"开盲盒"的爽点；固定 1280×720 舞台整体缩放，三种分辨率排版一致（result_res 场景验证）。
- 截图：`work/shots/result_res_1920x1080.png`。

## Esc 优先级链
- 是什么：两层。①`src/ui/esc.js` 弹层栈（确认框、Esc 菜单、功法匣弹层、F8 调试）：Esc 只给栈顶，`stopImmediatePropagation`；栈空时问场景 `setEscIdle`（返回上一页 / 呼出 Esc 菜单）。②出行局 `src/ui/screens/run.js` 的 `S.onEsc`：储物袋 → 舆图手卷 → 构筑面板 → （首领演出时不响应）→ 打开暂停。
- 为什么好：一次 Esc 只关一层，开着任何界面都不会误弹菜单；新弹层只要 `pushEsc`，不用改各处判断（2026-11-17 用 ui_esc 遍历 62 项验证）。新加浮层要接进栈或这条链，不要各自监听 Esc。

## 功法匣（装配界面）
- 是什么：`src/ui/loadout.js` 的 `LoadoutUI`：立绘下一排栏位（Q / E / R | 右键蓄势斩（只展示）/ T 阵盘 / V 法宝 | 心法 ×2），右侧可收起的功法匣（法术 / 心法 / 法宝 / 阵盘）。拖入、栏间换位、拖出卸下、先点再点、悬停按键直接装入；悬停浮签写伤害、克制倍率、本去处护盾。数据只在 `profile.build`，空栏不自动补。
- 为什么好：用户确认"整体很好"；所有操作都有两种以上方式；同名心法灰显 + "叠"印而不是禁止。
- 复用：`openLoadout(ctx, { from, region, tab, onClose })` 独立弹层（洞府参悟后、心魔试炼前），关闭时存档。
- 截图：`work/shots/loop_flow_loadout.png`、`loop_flow_loadout_note.png`。

## 提示小字条
- 是什么：装配 / 出行准备里的反馈写进固定一行（`LoadoutUI.say(msg, kind)`），2.5 秒淡出，警告朱色、获得泥金色。
- 为什么好：不压内容（用户反馈横幅挡住立绘和功法匣后改的）；位置固定，玩家知道去哪看。测试断言它不和任何内容块相交。

## 局内捡到的消耗品直接进快捷栏
- 是什么：`run.stowConsumable(inst)`；HUD 不用改，快捷栏读 `skills.potions[i].count` 与 `run.carried`。储物袋里双击走 `run.useItem(inst)`。
- 为什么好：捡到即可用，又不破坏身陨规则（`found` 标记）。

## 地上物品 = 交互伪标记（按 F 取）
- 是什么：每件地上物品挂一个 `{ kind: "pickup", verb: "取", pos, label, q }` 伪标记，`run.nearestMark` 把它和宝箱、采集点、撤离点放在一起比距离；交互提示、动词、品级着色全部复用 gather_ui 现有那一套（只补了 VERB / RISE / 着色三处）。按 F 一次取走身边全部，`run.collect` + `run.pickBatch` 合批（一次 "bag"、一条"拾得"）。
- 为什么好：一套交互语言、零新 UI；"走近就吸"变成主动操作后，重活只发生在玩家按键那一帧且只做一次（用户报的自动拾取掉帧）。
- 位置：`src/game/run/pickups.js`、`run.js`（nearestMark / takeGround / collect / pickBatch / onGathered）、`src/ui/gather_ui.js`；测试 `loop_pickup`；截图 `work/shots/loop_pickup_prompt.png`。
- 适用：任何"地上可拿的东西"（以后的掉落、可拾取的场景物）——挂伪标记，不要另写一套靠近检测。

## 委托与奇遇（模块 E）

### 散修白鹭：跨局故事线 + 看得见的好感
- 是什么：一个 NPC 在多局之间推进剧情，阶段存 `profile.flags.bailu = { stage, favour, met, gift }`。初遇（自报家门 → 点亮撤离点 / 赠回春丹 → 回送丹方残页 / 按剑戒备）→ 求助（与她并肩清一窝妖物，她追着妖物挥剑造成伤害）→ 身世（青岚剑派、剑修遗府，给护器符）→ 之后送礼 / 买卖 / 再并肩。阶段只进不退（`{ bailu: n }` 取 max）。第一次遇到奇遇一定是白鹭，保证故事线开头必看到。
- 为什么好：每个选项都有立刻可见的结果（点亮地图、掉东西、好感提示、她真的出手），跨局有"她记得你"的连续感；正剧里带穿越式自嘲的心声（全角括号），不出戏。缺条件的选项置灰并写原因（"缺少回春丹"），而不是隐藏。
- 位置：`src/data/encounters.js`（bailu 节点树）、`src/game/quests/index.js`（open / runNode / pick / startHelp）、`src/ui/quests/dialog.js`、模型 `blender/build_bailu.py`；截图 `work/shots/loop_quests_dialog_choices.png`、`loop_quests_bailu_help.png`。
- 适用：任何跨局 NPC。

### 奇遇·灵田：不打断节奏的正反馈
- 是什么：一片 5–8 株野生灵草 + 淡青灵雾 + "缘"字印章；走近冒一句主角心声（不暂停）；每株就是 run 的普通采集标记，F 即采；品级高的株带 RARITY 色光环；可选"采到第 N 株妖兽扑出"。
- 为什么好：复用现有采集流程（`gather_<key>` 掉落表、拾取、灵草苗、"采药"委托计数），零新交互、零新规则，玩家一眼懂。
- 位置：`src/game/quests/lingtian.js`、数据 `src/data/encounters.js` 的 `lingtian`、掉落档 `src/data/loot.js` 的 `GATHER.lingtian`；截图 `work/shots/loop_quests_lingtian_far.png`、`loop_quests_lingtian_gather.png`。
- 适用：任何"地图上的惊喜"——优先做成现有交互物的组合，而不是新系统。

### 数据驱动的效果词表
- 是什么：奇遇选项的 `effects` 是一张小词表（item / loot / consume / pay / xp / fortune / favour / bailu / flag / heal / spawn / help / meditate / lead / reveal / baopin / note），数值用 `"enc"` + 倍率 `k` 引用评审定的标准量。
- 为什么好：策划改表不碰代码；数值评审一改标准量，所有奇遇跟着变。

## 洞府（模块 C）

### 挂签只在悬停 / 靠近时淡入
- 是什么：3D 建筑上的竖挂签默认透明，鼠标落在该建筑包围盒上（每件东西一个 Box3，射线求交）或主角进交互距离时 0.25s 淡入；红点不放挂签，统一进"今日可办"。`src/ui/cave/index.js update`、`src/game/cave/index.js` 悬停判定、`src/world/cave_scene.js _boxes()`。
- 为什么好：用户要求"建筑上不要常驻文字"，场景干净，信息需要时才出现（2026-11-17）。
- 适用：任何"场景即界面"的据点。

### 今日可办点一下就走过去
- 是什么：每条待办带 `go = { fac, tab, sel, flash }`——走到哪（药园走到药园门口）、开哪个标签、选中什么、让哪个按钮闪两下；途中按移动键可打断。`facilities.js todos()`、`Cave.goTo / open`、`ui.flash`。截图 `work/shots/loop_cave_todo_*.png`。
- 为什么好：玩家不用记"那个按钮在哪页"，一键直达又保留"走过去"的空间感。

### 灵气充盈（炼化给临时增益）
- 是什么：按"本次炼化修为 ÷ 本层所需"分五档，炼化前预览"可得 · 五档：减伤 12% · …"，炼化后石青圆相 + 大字演出；不叠加（高档替换并刷新，低档只续时长）。数据 `recipes.js REFINE.buff`，逻辑 `facilities.js lingqiFor / applyLingqi`，存档 `profile.buffs`。截图 `loop_cave_buff_preview.png / loop_cave_buff_fx.png`。
- 为什么好：没突破的炼化也有即时回报，并且直接作用于下一局。

### 修为常驻加成可见
- 是什么：灵泉页修为条下写"当前修为加成：气血 +12 · 攻击 +2"（`progressBonusStats`），炼化后刷新属性（`applyProfileStats`）。
- 为什么好：炼化的过程收益看得见，不只有突破那一下。

### 化灵 vs 炼化对比
- 是什么：灵泉每件灵物写"炼化 +X / 化灵 Y 石≈Z"，更划算的一边盖朱色"宜"；仓库化灵按钮写"得 石 N"＋小字"≈ 修为 M"。数值保证"化灵再炼化 ≤ 直接炼化"。
- 为什么好：解决用户"灵值干嘛用、先化灵还是直接炼化"的困惑，不用读说明。

### 药园可见、手动采收
- 是什么：3D 小院地块随等级增加，灵草复用采集点造型按 发芽→抽叶→成株→成熟发光 缩放，高年份更大带品级色微光；F 采收时墨点飞进仓库 + "名称 ×数量"浮字（品级色走 `inkReadable`）。同种灵草几何 / 材质只建一次再 clone。

### 仓库博古架
- 是什么：龛的大小 = 物品占格（`packBag`），隔板按龛画（不横穿大件），不自动重排（R / 归置才排），拖拽调序、拖到身上装备；灵石是货币不上架。截图 `loop_cave_storage.png`。

### 首入加载套路
- 是什么：遮罩下"分帧构建 → 并行编译 → 分帧上传 → 设施页首绘 → 整帧 → 揭开"，长任务清零（见 坑.md 洞府一节）。
- 适用：任何场景切换带大建模 / 首次编译的地方。

## 栏位解锁与掉落（玩法系统 · 栏位与残页，2026-11-17）

### 规则单一来源 + 数据现算文案
- 是什么：`slotOpen / slotLockText` 一处定义，局内、洞府、出行准备都调它；提示语"玉佩栏 · 练气五层解锁"的层数从 `PROGRESSION.unlocks` 现算，测试也从数据算期望值，不写死。
- 为什么好：用户报的"局内能装、洞府说不能"就是同一规则写了三份造成的；改解锁层只改数据一处，提示和测试自动跟上。
- 适用：任何"能不能做"的判定（栏位、设施等级、区域开放）。

### 掉落门控只改分配不改总量
- 是什么：`GEAR_SLOT_GATE` 按"距解锁还差几层"给底材降权，被挡的份额转给已开放的栏位；改前改后用 `tools/loot_slot_stats.mjs` 跑同一单局模型对比。
- 为什么好：经济模型（每局装备件数、灵值）不变，数值策划不用重算；解锁节奏和掉落节奏对齐（练一、二不出玉佩，练三法衣满权重）。

## 多岗位方案的可点总览（构筑与成长 v1，2026-11-18）
- 是什么：`docs/design/构筑与成长_v1/index.html`——宣纸底 + 楷体 + 墨色梯度，六个页签（一页总览、五流派切换看★三件 / 栏位 / 成长手感 / 首领打法 / 去哪刷、成长轴与代价阶梯、按"回府"排的时间线、可点选的待选题、落地拆分）。数据全在页内常量，hash 直达，`shoot.mjs` 一键截全部页签。
- 为什么好：用户偏好"可点的 HTML 参考而不是纯文字"；一页能看到四个岗位的结论与分歧，待选题带推荐与出处。截图 `docs/design/构筑与成长_v1/png/*.png`。
- 适用：任何多岗位合写的设计方案的汇总页（沿用主管 `构筑节奏_v1` 的样式）。
