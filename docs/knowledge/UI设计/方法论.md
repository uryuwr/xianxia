# UI 设计 · 方法论（通用方法 + 本项目取值 + 出处）

## 1. 叙事内 / 叙事外 四象限
- 方法：按"是否在游戏世界里"ד是否占据空间"把 UI 分成四类（diegetic / non-diegetic / spatial / meta），在不伤害一致性的前提下尽量用叙事内。
- 本项目取值：天机镜（铜镜 = 手机）、洞府挂签、地图手卷、首次所见竹简放叙事内；生死信息（气血、真气、冷却、撤离读条）必须走叙事外 HUD，够大、够清楚。详见 `docs/UI风格指南_v1.md` §6.1。
- 出处：Fagerholt & Lorentzon, *Beyond the HUD*（2009），见 参考资料.md。

## 2. 小屏信息：列表 / 详情分离（master–detail）
- 方法：小视口只放可扫读的列表（每行 1 个主标题 + 2–3 个关键数），点开后详情放进第二视口；不要在小屏里塞完整表格。
- 本项目取值：天机镜屏 320×560、字号 12.5px，一条境界记录只露 4 项属性增量；详情（14 项属性前 → 后）放在镜外浮签（296px 宽）。

## 3. 动效：空间连续 + 只动合成属性
- 方法：界面从触发它的物件"长出来"、合上时回到那里，玩家能建立"界面在哪"的心智模型；动画只用 transform / opacity，不做大面积 filter / box-shadow 动画。
- 本项目取值：进场 0.42 秒 `--ease-ink`，退场 0.28 秒 ease-in；3D 物件投影到设计稿坐标后写进 CSS 变量（见 范例.md 第 4 条）。

## 4. 数据展示（单值进度 / 累计）
- 方法：一个量用一个色相；数值文字用墨色（文本色），颜色只给图形；不给每个点都标数；多于一个系列才需要图例。
- 本项目取值：累计成长用"墨（起点）+ 泥金（增量）"一笔；增量文字用石绿 `#2c7d57`（与灵泉册页的 +30 一致），变差用朱。

## 5. 草图评审：给用户可选的方向
- 方法：2–3 个风格差异明显的方向 + 并排入口 + 推荐 + 2–4 道具体选择题；每个方向写清楚优缺点（尤其是信息密度、和已定界面是否一致）。
- 本项目经验：用户偏好"意象完整"（这次选了圆镜 A，而不是更好读的册页 B）；推荐里要说明取舍，不替用户做产品决定。

## 6. 信息层级与 45° 俯视可读性
- 层级：生死（气血、撤离、危险）＞ 决策（冷却、灵值、天时）＞ 收获（拾取、修为）＞ 氛围（区域名、题跋）。层级越高越靠近视线、墨越浓、越允许朱色。
- 最坏背景：纸白地面与焦墨崖壁 / 竹林同时存在；关键文字对比度 ≥ 4.5:1（XAG 101），按最差位置算。
- 双层结构：深色线 + 外侧一圈纸色（白天靠墨、夜里靠纸色外描）；小数字两层 3px 纸色 text-shadow，不用黑描边（会和水墨后期轮廓线混）。
- 去饱和检查：品质靠"圆相颜色 + 角标印 + 名称字色"三重区分。

## 7. 交互物与战利品（采集 / 宝箱 / 搜取 / 神识）

### 7.1 交互提示贴在物件上
- 方法：提示锚定在物件上方（世界坐标投影），"F 印 + 动词 + 名称"，名称下一笔同色短划；物件脚下的圆相同时"聚焦"（墨变浓、圈收紧）。同一时刻只有一个提示；读条 / 打断 / 搜取窗口开着时提示收起。
- 为什么：底部通知要眼睛在物件和屏幕底来回跳，还和技能栏抢位置。
- 本项目取值：锚高 灵草 1.25m、宝箱 1.15m、灵光点 1.9m、撤离阵 2.4m、尸体 1.0m；F 印 30px、动词 25px、名称 20px。

### 7.2 价值层级：形制 × 品质色，两个维度分开
- 形制（大小、微粒多少、有无光柱、单 / 双圈）表达"什么种类的点"；颜色只表达"产出物品质"（RARITY）。远处信标（光柱）只给值得绕路的东西。

### 7.3 揭示节奏（搜打撤的"搜"）
- 参考塔科夫、暗区突围、三角洲行动：开容器弹格子、逐格揭示、品质越高转得越久越隆重——把期待做成可感知的时间。
- 两段感知：走到 62% 露形（剪影）、走满显色（本色 + 品质晕）；总时长不变。仙 / 极在笔末"顿一下"只在显示层做（逻辑进度线性）。
- 预感：高属性（神识 ≥ 40）时未探格隐约浮现轮廓——奖励成长、不剧透具体物品。
- 中断：世界不暂停；受击 / 走动立刻收起、进度保留（含当前格已转部分）。

### 7.4 完成反馈三件套
- 原处：一笔圆相收拢 + 钤小印（采 / 启）；去向：物品沿弧线飞入储物袋计数（身后墨点、计数一跳）；名称：浮起"名称 ×数量"或窗口底部"名称 · 品质 · ×数量"。

### 7.5 读条：一笔圆相
- 圆形读条画在物件 / 主角脚下，按进度露出（conic × 圆相 mask，只改 `--v`）；需要时机判定时用一段泥金弧标"运笔时机"；被打断：转朱、抖两下、钤"断"、一行原因，0.95s 淡出。

### 7.6 地上不堆空壳
- 有掉落才留尸；取空立刻化墨（~1.2s）；没取空的留到取空或超上限。

## 8. 图标 / 储物袋（物品 · 技能 · 地图图标，2026-11）

### 8.1 小尺寸靠剪影
- 方法：48px 以下，可辨识度主要来自轮廓（剪影），其次是颜色，最后才是内部细节。先保证剪影唯一，再加细节。
- 本项目取值：物品格约 46px、技能栏约 40px（笔画 ×1.7）、地图 15–24px（实块剪影 + 纸色反白一两笔 + 纸色 shadow，关纸纹颗粒）。每次都在实际尺寸截图验收。

### 8.2 信息通道分离
- 方法：一个视觉通道只承载一类信息，去饱和后仍可区分（XAG 101：色相不能是唯一区分）。
- 本项目取值：图标本色 = "是什么"；圆相色 + 同色晕 + 名称字色 + 仙 / 极角印 = "多稀有"（RARITY）；透明度 + 一笔勾 = "状态"（已清 / 已开 / 已采 / 取空）；朱 = 危险，金 = 撤离 / 宝，墨 = 地物。

### 8.3 技能画意象，不画物件
- 方法：技能没有实体，画效果的形态与方向（月牙剑气、符火、冰棱、盘藤、岩壁、雷纹、落石）；同五行的两招靠意象区分，不靠颜色。五行色只做淡彩，与技能栏圆相色一致；图标占圆相内径约 70%，冷却墨扇 / 秒数 / 按键角标在其上。

### 8.4 模板化 + 参数化，永远有图
- 方法：每类一个笔路模板，物品只填参数（颜色、变体）；模板与渲染器分离（同一份笔路出位图、矢量、剪影）；没有专属规则的新物品退回类别模板，再不行用通用图；运行时查不到则文字兜底。

### 8.5 构建期烘焙图集，运行时只取图
- 方法：程序化生成只在构建期做一次，运行时用 CSS background-position / canvas drawImage / 3D UV 取图，零绘制开销；按使用场景拆图集（主图集、剪影、地图小图集），用不到的不下载。

### 8.6 世界不暂停时的局内面板
- 方法：常驻部分贴边、不进画面中心 60%（主角周围）；详情按需浮出、受击收起；面板边缘给"敌近"提示（朱印 + 方位距离 + 屏幕方向箭头）；袋子开着时与之相关的横幅收进面板状态行。

## 9. 炼器 / 炼丹（丹器房 v2）

### 9.1 制作界面的阅读顺序 = 决策顺序
- 方法：左"选什么"（目录）→ 中"放进去什么"（材料围着器物）→ 右"会得到什么"（成品预览、概率、与身上比）→ 右下"下决心"（朱印）。一屏读完，不翻页。设施本身的升级与配方分开放（器物下沿的铭文 + 独立弹层）。
- 本项目取值：器物区 520×604、插画 360×360；成品卡 330 宽；朱印 88px，Space 等同点印。

### 9.2 预览要让"随机"变成可读的分布
- 方法：随机产出给出**所有可能结果 × 概率 × 后果**（这里是品级分布条 + 每档基础属性 + 与身上比 ▲▼ + 随机词条条数），玩家的选择（主材品级）要实时改变预览。概率小于 1 的档要写数字，不写"可能"。
- 本项目取值：五档 RARITY 一条，会出的档按品质色晕开、写百分比，"极"注"炼器不出"。

### 9.3 失败信息要给出下一步（缺什么、去哪得）
- 方法：错误 / 不足提示要能被识别、诊断并恢复（Nielsen 第 9 条启发式）：不只写"缺"，还要写缺多少、哪里能得，且来源从数据反查、自动跟着掉落表更新。
- 出处：Nielsen Norman Group，*10 Usability Heuristics*，见 参考资料.md。

### 9.4 同类器物用剪影区分
- 方法：先看剪影能不能分清（只看轮廓、去饱和），再加纹饰与颜色；功能不同的物件剪影必须不同（方 vs 圆、带盖 / 带门 / 立耳）。纹饰只是第二层。
- 本项目取值：炼器鼎 = 方腹立耳四足；丹炉 = 圆腹穹盖三足 + 炉门火光 + 钮上丹烟。
- 出处：Mitchell, Francke, Eng，*Illustrative Rendering in Team Fortress 2*（NPAR 2007）——角色辨识首先靠剪影，见 参考资料.md。

## 首领界面（青牙 v2）

### 10.1 战斗中的状态变化走叙事内，文字只做事后记录
- 方法：首领进入新阶段、获得增益等"状态切换"，优先用世界里的变化表达（模型外观、护盾颜色、环境光、音乐），HUD 只保留生死与决策信息（气血、护盾、失衡、读条、可处决）。"第几阶段"这类叙事外文字在战斗中不写，留给战后记录（战报）。
- 本项目取值：青牙转阶段 = 骨甲崩裂 + 青焰 + 遮月 + 木盾换土盾；UI 只上演出黑边；50% 刻痕不带字。用户 2026-11-17 否掉了"二 · 啸月"横幅。
- 出处：Fagerholt & Lorentzon *Beyond the HUD*（叙事内优先，见 §1）；本项目用户反馈。

### 10.2 失衡条（只狼式）：从中间向两端长
- 方法：失衡 / 架势条从中心向两端对称增长，越满越危险（墨浓 + 转朱），满了"断"；回落时变淡（告诉玩家"再不压就掉"）。与气血条上下排列、同宽，读法"上 = 还剩多少，下 = 离破防多近"。
- 本项目取值：狼威 11px 高、448 宽；墨层 opacity .5 → 1，朱层在 p > .55 后叠上（只写一个 `--p`）；回落 ×.62；满 → 全朱 + 中间断开 + 钤"折"。

### 10.3 处决窗口：圆相收拢 = 剩余时间
- 方法：可处决提示锚在敌人头顶（与交互提示同一套"F 印 + 动词"），外圈一笔圆相按剩余窗口收拢（conic 进度 + 轻微缩小），最后 30% 转朱。
- 本项目取值：F 印 36px、"斩"36px 行书朱色、圆相 66px；k = `downLeft / downDur`，没有就按 `execPrompt.dur` 自己倒数。

### 10.4 演出叠加层用真实时间的 CSS 关键帧
- 方法：处决 / 终结这类和镜头慢动作同步的 2D 叠加，用 CSS 关键帧 + 每元素 animation-delay 排时间轴（真实时间，不受世界 timeScale 影响），事件到达时切一次类名；短版用一个负的偏移变量（`--o`）整体平移，不另写一套。擦出（笔锋扫过）用"外层右移 + 内层反向抵消"，只动 transform。"出伤那一刻"的字卡事件（`boss:executeHit`），时间轴只作兜底。

### 10.5 让抽象资源"看得出作用"：涨的时候有来由，满之前有预兆
- 方法：玩家看不懂一个条（用户原话"领悟值是什么作用？没看出来"）时，不加说明文字，而是在**变化发生的那一刻**给三样反馈：①增量本身可见（新涨的那段先亮再沉，像 Hollow Knight / 只狼受击后的"残影段"）；②来由可见（条尾浮一个字说明是哪个动作涨的：断 撞 闪 腾 冻 缠 破 斩 生），小额来源不出字，避免噪音；③临界可见（过 75% 整笔泛朱呼吸 = "再一下就折"）。满了的结果（折 → 可斩）用醒目的印 + 处决提示 + 世界里的地面墨环闭环。首次挑战题签点一句"折其威，可斩"，只说一次。
- 本项目取值：大额阈值 n ≥ 8（狼威上限 100）；亮段 0.42 秒、来源字 0.8 秒；near 呼吸 1.5 秒（opacity .12 ↔ .78）。

## 11. 收集目标的指引（功法来源）

### 11.1 从「缺口」出发，而不是从「图鉴」出发
- 方法：玩家问「下一个去哪打」时，先算他**当前计划**（要去的地方 × 已带的东西）缺什么，再列能补缺口的目标与去处；完整图鉴是第二入口。缺口要落到行动（地点、敌人、容器、概率档），并延伸到局内导航（地图标签）。
- 本项目取值：缺口 = 去处护盾要的克制五行在已带法术里没有；出行准备缺口签 + 舆图小签（方向 C），功法匣来源签补全 12 门（方向 A）。

### 11.2 概率写档位字
- 方法：掉率会调、且玩家关心的是「值不值得绕路」，界面默认写档位（必得 / 常见 / 偶得 / 罕见），阈值写进约定；精确百分比只在详情里给（或不给）。档位要稳定映射，改数值不改字的含义。
- 本项目取值：必得 = 固定 / 首探 / 首杀 / 赠予；常见 ≥30%；偶得 10–30%；罕见 <10%。

## 9. 属性来源拆解（叠加型数值的展示口径）
- 方法：最终值 = (基础 + Σ固定) × (1 + Σ百分比) × Π(1 + 独立乘区)。展示"各来源贡献"时，固定项按原值；百分比项按边际值 `(基础 + Σ固定) × 百分比`（同时写出百分比本身）；独立乘区单独列，不并进条。临时加成（本局 / 条件触发）与常驻分开标，并给"按出行计 / 洞府中"两种口径。
- 本项目取值：来源大类 境 / 器 / 心 / 局；公式出处 `src/core/combat.js Stats.get`；草图 `docs/ui/v2/静室/common.js stat()`。


## 2026-11-18 精细化小样 · 主管复盘

### 场景美术变了，HUD 按最差背景重验
- 方法：HUD 的可读性是"HUD × 背景"的结果，不是 HUD 自己的属性。场景精细化后中间调与纹理增多（瓦垄、皴笔、风化），原来靠"浅纸底 + 墨字 + 白色 text-shadow"成立的对比可能不够；任何美术精细化 / 换着色方案，都要挑**最差背景**（最碎、最接近 HUD 色的区域）重验生死信息（气血、真气、冷却、读条）。
- 本项目取值：对照截图 `docs/art/精细化小样_v1/png/` 的 B_* / C_*（C 写实整体偏亮，见 美术管线 坑 #24）；HUD 色值问题见 坑.md 同名节。

## 2026-11-18 UI 体检 v1 · HUD 可读性实测（UI 设计）

### 按最差背景实测对比度：三张裁片法
- 方法：把 HUD 按原参数叠到目标底图上，对每个关键元素截三张同位裁片——A 前景隐藏（字 `color: transparent`，纸色描边保留；条把整条藏掉）、B 前景染品红并去描边（遮罩）、C 原样；只在遮罩核心像素（品红覆盖率 ≥ 0.7）上算 C 对 A 的 WCAG 对比度，报 **P10**（最差一成像素）和中位数。比"拿字色对背景平均色"准：描边、墨晕、底图纹理都算进去了。
- 门槛：正文 ≥ 4.5:1（XAG 101）；大字（≥ 24px 或 18.66px 粗）与图形元素（血条、预警外缘）≥ 3:1（WCAG 2.1 SC 1.4.3 / 1.4.11）。
- 本项目取值：脚本 `docs/ui/v3/体检_v1/shoot.mjs` + `measure_dom.py`（工具.md）。精细 B 上现状：真气条 P10 2.46、小字 1.1–2.6、预警外缘 1.43；建议后：朱血 4.38、深石青气 4.21、预警 3.76、小字中位全部 ≥ 4.4。
- 出处：WCAG 2.1 SC 1.4.11 Non-text Contrast；XAG 101（参考资料.md）。

### 背景"纹理强度"比平均亮度更能预告问题
- 方法：除了 P5 / P50 / P95 亮度，再量 HUD 分区的边缘检测均值（PIL `FIND_EDGES` 的均值）。纹理强度高时，细描边、细线条、11–12px 小字会被打散，即使平均亮度没变。
- 本项目取值：现状 → 精细 B：天时 5.6 → 29.9、镜下方位 10 → 76、机缘 1.9 → 70、境界 1.8 → 12.7（`measure.py`）。纹理涨 3 倍以上的分区，没底衬的元素一律要重验。

### 颜色语义：敌墨我朱
- 方法：一屏里朱色只给"你的命"和"危险"（预警、狼威临界、残血四缘）；敌人的命用墨（与首领条一致），护盾用技能栏五行色。这样朱一出现就是"和你有关的危险"。
- 本项目取值：2026-11-18 用户选定并已落地——气血朱、敌人血条墨（余迹朱）、精英去紫改朱"精"印、预警朱 + 纸色外描（`docs/ui/v3/体检_v1/落地记录.md`）。

### 残血用余光提示，不只靠血条
- 方法：精细化后画面信息变多，玩家视线在战场中心，左上血条靠"看"不可靠；用屏幕四缘的元信息（风格指南 §6.1 淡朱墨）+ 血条自身状态（字转朱、条呼吸）双通道提示。只动一层全屏渐变的 opacity，跨阈值才切类名。
