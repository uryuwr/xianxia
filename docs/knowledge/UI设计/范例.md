# UI 设计 · 范例

> 设计是什么 → 为什么好 → 位置 / 截图 → 适用场景。优先沿用。§1 采集 / 宝箱 / 搜取 / 神识；其他分区由各自负责人追加。

## 1. 采集 / 宝箱 / 搜取 / 神识

### 1.1 墨封宣纸格 + 神识一笔
- 是什么：容器旁浮起一小幅半透明宣纸（毛边 + 纸纹，约 250×280），格子是储物袋同一种物品签（一笔圆相 + 图标 + 品质晕）；未探查的格子被一团浓墨封住；一缕淡金神识沿圆相一笔绕行（笔尖带光，品质越高越亮）。
- 为什么好：用户主动提了"搜"的期待感需求，并在讨论后定了"神识探查"这个修仙化的说法；形状全部来自风格指南的程序化笔触，没有方框；小而跟随容器，不挡战斗视野。
- 位置：`src/ui/loot_window.js` / `loot_window.css`；草图 `docs/ui/v2/loot_v2/index.html`；截图 `docs/ui/v2/png/搜取_总览.png`、`搜取_v1v2_对比.png`。
- 适用：任何"打开一个装东西的东西"——尸体、宝箱、供案、遗物包、以后的妖巢 / 秘境宝库。

### 1.2 先露形、后显色（两段揭示）
- 是什么：神识一笔走到 62% 墨封化开、露出墨拓剪影；走满一圈换本色、外圈晕品质色，名称在底部浮出 1.2 秒。仙品顿笔泛金，极品朱金迸开 + 顿帧。高神识时墨封下隐约浮现轮廓（预感）。
- 为什么好：同样的时长里多了一拍"猜"——先知道形（剑？玉？）再知道品；与"神识"属性的成长直接挂钩（神识越高越快、越早有预感）；用户确认草图后落地。
- 位置：`src/ui/loot_window.js`（`form()` / `reveal()` / `shape()`）；图集接口 `src/ui/icons.js` 的 `setTagState` / `tagReveal`。
- 适用：鉴定揭晓、抽取、结算逐件揭示。

### 1.3 留尸、取空化墨
- 是什么：有掉落的妖兽倒地定格成淡墨剪影（不投影、不画墨线壳），脚下一圈凡品色淡墨圈，"F 搜"；取空立刻化墨散去（约 1.2s）；没取空的留到取空。
- 为什么好：符合搜打撤的"搜尸"预期，又不让地上堆空壳（用户要求"取空就消失"）；淡墨剪影与场景水墨统一，性能上每具尸体 draw call 减半、不进阴影 pass。
- 位置：`src/game/run/containers.js`（`corpse` / `adopt` / `markEmpty` / `fade`），`src/game/enemies/enemy.js` 的 `keepBody`。

### 1.4 贴在物件上的"F 印 · 动词 · 名称"
- 是什么：所有交互物共用的提示，锚在物件上方；名称按品质色、下面一笔同色短划扫入；物件脚下圆相同时聚焦。
- 为什么好：用户嫌原来的底部通知条丑、离物件远；改后眼睛不用来回跳，所有交互物（采、开、搜、撤、取、探）一套语言。
- 位置：`src/ui/gather_ui.js`（`prompt()`）、`src/ui/gather.css` §1。

### 1.5 采集点三层表现：写意物件 + 脚下一笔圆相 + 灵气微粒
- 是什么：物件 toon + 后期墨线，不自发光；脚下圆相白天是墨线 + 纸色外晕、入夜自动转成灯色线（读关卡的 `uK`）；微粒在顶点着色器里算。形制分种类、颜色按产出物 RARITY。
- 为什么好：去掉"荧光塑料"感（用户原话"灵草 UI 太丑陋"），白天 / 夜里都清楚，远处能按形制一眼分出灵光点与普通灵草。
- 位置：`src/world/markers.js`（`inkEnso` / `spiritMotes` / `decorateGather` / `gatherMarker` / `chestMarker` / `altarMarker`）；截图 `docs/ui/v2/png/灵草采集_对比_*.png`、`采集_品阶总览.png`。

### 1.6 开箱：已开启的箱子留在原地
- 是什么：关卡模型被 `consume` 藏起的同一帧，原位放一只"已开启"的箱子（木色压暗、盖子 0.5s 回弹掀开、墨气涌出）；之后一直保持开启。
- 为什么好：原来开箱后整只消失、留下看不见的碰撞体；现在玩家看得见"开过了"，碰撞也有交代。
- 位置：`src/fx/gather_fx.js`（`openChest`）。

## 2. 天机镜 / 洞府界面

### 2.0 用户认可的基准画面（新面板先对照）
- 灵泉册页 `work/shots/loop_cave_spring.png`；储物袋纸笺定稿 `docs/ui/v2/png/bag_v2_zhijian.png`。新面板的密度、字号、留白、印章用法以这两张为准。

### 2.1 铜镜里的手机（天机镜 v2 · 方案 A，2026-11-17 用户选定）
- 是什么：洞府石案上的铜镜就是林墨的手机。打开后屏幕中间一面圆铜镜（铜色外缘 + 回纹刻度 + 镜钮系朱绳 + 一圈淡金铭文"见日之光天下大明长毋相忘"），镜面里嵌一块"被点亮的宣纸"竖屏（320×560）：状态栏（时辰 / 无服务→墨州一格 / 修为当电量）、裂屏、穿越前城市的淡墨壁纸、一笔圆相画的应用图标（境 忆 迹 舆 + 底栏 讯 拨）。
- 为什么好：现代 × 仙侠混搭但不出戏——手机元素都换成了世界里的东西（时辰、修为、墨州）；道具本身就是界面（叙事内）；用户在三个方向里选了它。
- 位置：`src/ui/cave/mirror_v2.js / .css`；草图 `docs/ui/v2/mirror_v2/a_yuanjing.html`；截图 `docs/ui/v2/png/mirror_v2_a.png`、`work/shots/loop_mirror_v2_*.png`；方案 `docs/ui/v2/天机镜_v2_方案.md`。
- 适用：世界里的物件承载 UI（法宝面板、传讯符）。克制：不做天气、步数、角标数字、玻璃质感。

### 2.2 小屏列表 + 镜外浮签详情（境界录时间轴）
- 是什么：镜中屏里一条时间轴（最新在上），顶部虚线框"下一层预告"（修为进度 + 将得什么）；每条：抬头"练气六层 → **七层**"、时间（第 N 次出行归来 · 时辰；旧存档补的写"旧事"）、4 项主要属性增量、所得印章。点一条，详情写在镜子右侧浮签上：属性"前 → 后 ＋差"（只列有变化的）、所得、耗修为 / 心魔劫、"那一夜亮起的"记忆缩略图、玄机子当时那句话。
- 为什么好：小屏放不下 14 项属性，列表 / 详情分离后屏里只需扫读；"那一夜的记忆 + 玄机子"把数字变成故事；用户选了备忘录写法而不是朋友圈写法。
- 所得印章分类（可复用）：解（栏位，墨印）/ 能（二段跳、闪身、御剑，石绿印）/ 途（区域，石青印）/ 习·悟（法术、心法，泥金印）。
- 适用：任何"历史记录 + 详情"（委托、炼丹、战报）。

### 2.3 累计总览的"墨 + 泥金"一笔进度
- 每项属性一行：起点 → 现在、一笔 `--ink-stroke-bar`（墨段 = 起点占现在的比例，泥金段 = 此后所得）、增量、倍数（×3.6）。数值文字一律墨色，颜色只在笔上。位置：`mirror_v2.js` `_totals("stats")`，截图 `work/shots/loop_mirror_v2_total.png`。

### 2.4 从 3D 物件放大的转场（界面从铜镜里长出来）
- 是什么：把 3D 镜面世界坐标投影到屏幕、换算到 1280×720 设计稿坐标，写进 CSS 变量 `--dx --dy --s0`，关键帧从 `translate(var(--dx),var(--dy)) scale(var(--s0))` 放大到位，合上反向缩回；3D 镜面同时亮屏一下；进场 480ms 后 `ctx.hold3d = true`，合上时恢复。
- 为什么好：空间连续，玩家知道界面"来自"哪件东西；只动 transform / opacity。
- 位置：`CaveScene.mirrorScreen(camera)`（`src/world/cave_scene.js`）、`MirrorV2._build(from)`、`Cave.openMirror()`。适用：丹炉、宝箱等从场景物件打开的面板。

### 2.5 3D 物件"亮屏"提示（不靠常驻红点）
- 镜面竖屏是不投影的透明面片：平时 opacity 0.06↔0.16 呼吸（4 秒）；每 20–40 秒随机亮一次（0.15 秒升到 0.6、停 1.2 秒、0.8 秒淡回）+ 加法微光精灵；有未读 6–8 秒一次 + 朱点；筑基后换泥金。每帧只改几个 opacity（实测 0.0003ms），不加灯。待办仍走"今日可办"。

### 2.6 草图工作流：多方向 + 并排入口 + hash 状态
- 每个方向一个 html，共用 `data.js`（假数据照抄真实成长表）+ `common.js`（内容渲染）+ `base.css`；`index.html` 并排缩略 + 单独查看 + 示意进度切换；状态写在 URL hash（`#p=qi7&app=realm&open=1:7&t=21:40`），截图带 hash 出指定状态。同一套内容块落地时几乎原样搬进游戏。位置：`docs/ui/v2/mirror_v2/`。

## 图标 / 储物袋

### 侧挂纸笺储物袋（局内，2026-11 定稿）
- 是什么：画面右缘一张竖长宣纸（按窗口右边锚定、随 `--mk-scale` 缩放），自上而下一条信息线：标题 + 满载印 + 袋中估价 → 占格条 + 灵石 → 随身（剑 / 衣 / 佩 / 宝 + 行囊）→ 袋中格子 → 贴身锦囊（锦囊小图标组标）| 护身格（"护"印组标）→ 脚下 → 若身陨此地 → 键位；选中物品时详情浮签贴纸笺左外沿、主角头顶上方，带"此件 / 身上 / 差 ▲▼"对比。
- 为什么好：世界不暂停时主角、气血、技能栏都不遮挡；和搜取窗口同材质同物品签；用户在四个方向里选了它。
- 位置：`src/ui/bagui.js`；截图 `docs/ui/v2/png/bag_v2_ingame_*.png`；方案 `docs/ui/v2/储物袋_v2_方案.md`。
- 适用：任何局内、世界不暂停的面板（侧挂 + 浮签 + 敌近提示）。

### 物品签组件 itemTag
- 是什么：一笔圆相 + 水墨图标 + 品质淡晕 + 数量 + 仙 / 极角印；尺寸参数化（40 / 52 / 74）；状态：选中（圆相转朱）、不可用、墨封、剪影（未鉴定）、放不下、新得；`tagReveal` 做剪影 → 显色。
- 为什么好：储物袋、搜取、结算、仓库、炼器同一个签，物品在窗口之间飞来飞去外观不变。
- 位置：`src/ui/icons.js`。适用：所有显示物品实例的地方。

### 未鉴定 = 墨拓剪影
- 同一模板自动推出（并墨、反刻白线、拍墨斑驳），"只见其形、不见其色"，零额外绘制成本。适用：未鉴定、搜取先露形。

### 意象写意技能图标
- 画法术的意象而不是物件（月牙剑气、符纸火焰、冰棱、盘藤、岩壁、雷纹、落石……），五行色只做淡彩且与技能栏圆相色一致；图标占圆相内径约 70%，冷却墨扇 / 秒数 / 按键角标在其上。用户在"意象写意 / 字印 + 意象 / 单字"三方案中选定。
- 位置：`tools/icons/skillicons.js`、`src/ui/skillbar.js`；截图 `docs/ui/v2/png/skillbar_icons_*.png`、草图 `skill_icons_compare.png`。

### 剪影意象地图图标
- 实块剪影 + 纸色反白一两笔 + 纸色 shadow；颜色即信息（朱 = 凶险、金 = 撤离 / 宝、墨 = 地物）；状态统一"变淡 + 一笔勾"、首领已斩"朱斜笔"；精英先画五行盾环再画妖面；图集加载前退回文字印章。用户在"剪影 / 印框 / 文字"三方案中选定。
- 位置：`tools/icons/mapicons.js`、`src/ui/screens/mirror_map.js`；截图 `docs/ui/v2/png/map_icons_ingame_*.png`。

### 方案对比图的做法
- 同一份"局中实况"数据（`docs/ui/v2/mock_bag_v2/data.js`）画所有方向；同一张真实底图；每张图都必须表现同一批状态（满袋、选中对比、锦囊 / 护身区别、身陨风险）；并排给"现状"作对照。用户选方案非常快。

## 炼器 / 炼丹（丹器房 v2）

### 器物为中心的制作界面（方向二"鼎为中心"，用户在 册页 / 鼎 / 长卷 三方向中选定）
- 是什么：整页一张毛边宣纸（3D 暂停 + 压暗，只在纸边透暗影）。左：分类竖签 + 目录（图标签 + 名 + **横排**状态：可炼 / 缺 2 味 · 铁精石 / 尚无器方 · 出处）。中：写意器物（炼器方鼎、炼丹八卦炉），材料签围着它、虚线连到器口，缺的用 `itemTag` 的 `nofit`（朱圈）+"缺 N"。器物下沿一行**鼎铭 / 炉铭**（设施阶、品质下限 / 火候带宽、"升二阶 ›"，点开独立弹层，不进配方卡）。右：成品卡（装备：主材品质四选一 → 五档品质分布条写概率 → 可能品级 × 属性，与身上同部位比 ▲▼）。右下：状态一句 + 朱印，Space 落印；落印 = 按下缩 12% → 器物中心溅墨 + 品级印 + 品质色晕开 → 结果纸签。
- 为什么好：用户的原话诉求是"仪式感 + 投料一眼懂"；四种视觉语言（竹简 / 宣纸卡 / 大单字 / 方印）统一成一套；设施升级从配方卡里拆出去后，读配方不再误以为要蝠翼。
- 位置：`src/ui/cave/workshop_v2.js`（外壳、目录、器物、材料环、何处可得、朱印、盖印、鼎铭、升阶弹层）、`forge_v2.js`、`alchemy_v2.js`、`ding.css`；草图 `docs/ui/v2/forge_v2/b_ding.html`；截图 `docs/ui/v2/png/forge_v2_final_forge.png`、`forge_v2_final_alchemy_fire.png`；方案 `docs/ui/v2/炼器_v2_方案.md`。
- 适用：任何"投入 → 产出"的制作 / 加工界面（以后的制符、布阵、祭炼）。炼丹沿用同版式：火候一笔放炉下，炉门火光随火候变亮。

### 器物插画带锚点（换图不改坐标）
- 是什么：器物插画是笔路模板（`tools/vessels/vessels.js`），每个模板带 `META`：`mouth`（器口，材料连线终点）、`smoke`（丹烟起点）、`fire`（炉门火光矩形）、`base`（器底）。界面把 128 盒坐标换算到器物区（插画 360×360、器底对齐固定 y），动态火光、丹烟、连线都按锚点摆。
- 为什么好：换变体 / 重画时零改坐标；测试能直接断言"火光中心 = 炉门锚点"。
- 位置：`vesselGeo()`（`workshop_v2.js`）、`src/ui/cave/vessel_meta.json`。适用：任何"插画上叠动态效果"的地方。

### 材料位：首味居上、两侧对称、最多 6 味
- 规则：第一味（主材 / 药引）在器口正上方；其余依次左上、右上、左下、右下；6 味时上方改成并排两味；灵石单放器下（炼丹没有药引时首格空出，从两侧排）。`ringPos(n, kind)` / `stoneSlot(kind)`。测试断言 6 味 + 灵石互不重叠、不压成品卡。

### "何处可得"从掉落表反查
- 是什么：点任一味材料弹纸条：名称、有 / 需、何处可得（最多 4 条，按可靠程度：Boss 首杀 / 遗府首探必得 → 妖兽专属掉落 → 精英妖丹 → 采集点 → 区域材料池常见 / 少见 / 灵光宝箱 → 药园可种）。锁定的器方也写出处（"尚无器方 · 山神庙地窖"）。
- 为什么好：缺料不再是死路，给出下一步（可用性启发式"帮助用户识别、诊断并从错误中恢复"）；数据随掉落表自动更新，不手写文案。
- 位置：`src/ui/cave/sources.js` `sourcesOf(id)`。适用：所有显示"缺 / 不足"的地方（升阶弹层已用）。

### 器物变体对比：在真实页面里换图
- 做法：变体写成模板 → `node tools/vessel_gen.mjs` 烘成位图 → `node tools/run.mjs shot_vessels` 在游戏真实页面里逐个换图截图（含"六味材料"、火候进行中）→ `vessels.html` 三列（现状 / 甲 / 乙）+ 原图 + 要点 + "选这个"。用户一轮就选定（方鼎 + 八卦炉）。
- 为什么好：比在草图里摆图可信——密度、遮挡、动态火光都是真的；第一列放现状，差距一眼可见。
- 位置：`docs/ui/v2/forge_v2/vessels.html`、`docs/ui/v2/png/forge_v2_vessels.png`。

## 首领界面（青牙 v2）
