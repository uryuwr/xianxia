# 墨途 · 专业知识库

**规范的完整版见 skill：.claude/skills/role-knowledge/SKILL.md（开工前加载）。**

每个专业岗位（数值、关卡、UI、战斗、性能、美术管线、视频）在这里沉淀**可复用的专业知识**。新开的子 agent 开工前必须先读自己岗位的目录，干完活必须把新学到的东西写回来，避免每次重新学。

## 目录约定
```
docs/knowledge/
  README.md              本文件
  <岗位>/
    方法论.md            业内通行的方法、框架、公式（附出处链接）
    工具.md              装了什么工具、装在哪、怎么跑、踩过的坑
    本项目约定.md        墨途特有的规则、数据格式、文件归属、已定的设计决策
    坑.md                踩过的坑：现象 → 原因 → 规避办法（被推翻的假设也记在这）
    范例.md              本项目做得好、值得沿用的设计（为什么好 + 位置 + 适用场景）
    参考资料.md          读过的书、文章、GDC 演讲、竞品分析（一句话结论 + 链接）
```
岗位目录：`数值策划/`、`关卡设计/`、`UI设计/`、`战斗设计/`、`性能工程/`、`美术管线/`、`宣传视频/`、`玩法系统/`。

## 写作规则
- **写结论，不写流水账**：每条知识是"做法 / 公式 / 判断标准 + 为什么 + 出处"。
- **区分通用与项目特定**：通用方法放 方法论.md；只对墨途成立的放 本项目约定.md。
- **可执行**：工具要写清安装命令、路径、运行命令；公式要写清变量含义和本项目的取值。
- **被推翻就改**：实测与假设不符时，直接修改原条目并在 坑.md 记一笔，不要留下过时内容。
- **控制篇幅**：单文件超过约 300 行就拆分；过期内容删掉。
- 品级只有一套（src/core/items.js 的 RARITY）；新特效/UI 遵守 docs/性能优化_v1.md 第 7 节——这两条是全局约定，各岗位都要遵守。
