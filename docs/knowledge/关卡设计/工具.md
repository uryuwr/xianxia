# 关卡设计 · 工具

## Python 环境
- venv：`docs/review/level/.venv`。它在 .gitignore 里，被清理过一次，需要时重建：
  ```
  cd docs/review/level
  python -m venv .venv
  ./.venv/Scripts/python -m pip install -q -i https://pypi.tuna.tsinghua.edu.cn/simple --prefer-binary numpy matplotlib scipy
  ```
  默认的 PyPI 源会卡住（下载 600 秒以上不动），要用清华镜像。
- 中文字体：matplotlib 用 Microsoft YaHei / SimHei。mathtext 的 `$骨$` 这种写法没有中文字形，要用普通 marker 加 annotate。
- 缓存：`docs/review/level/_cache/`（.gitignore）。

## 游戏内测试（项目根目录）
- `node tools/run.mjs loop_levels`：建 r1、r2、序章，检查点位（可站、不在碰撞体里、可达），以及深水、桥、渡口、御剑、亭子，出截图。截图视角来自 def.views，名字是 `work/shots/loop_levels_<区>_<视角>.png`。
- `node tools/run.mjs loop_flow_levels scene=run`：流程接关卡数据（序章引擎、采集标签、精英、夜潮、巡游、开箱）。
- `node tools/run.mjs num_glows`：灵光点与灵土候选的可站、可达，以及出现概率。

## 典型输出解读
- `loop_levels` 里 `bad: [{kind, inCol: true}]`：点压在碰撞体上（随机树石、古阵、亭柱、五行坛）。改法是挪点，或者在 level.js 的 `reserve` 里让植被避开。
- `reachJ: false` 但 Python 显示可达：Python 不计碰撞体。常见原因是窄桥上摆了物件（五行坛），把桥堵死了。

## 构筑投放分析（2026-11-18，构筑与成长 v1 · 04）
| 脚本 | 作用 | 用法 |
|---|---|---|
| `build_drops.py` | 复刻 level.js 的每局抽取规则：宝箱、灵光箱、亭 2–4 座、残碑 1–2 块、灵光点、精英间距、异种、刷怪轮转取前 spawnPacks 组，以及 mobs 循环或按栖息地随机。在这个基础上模拟三种局型（普通 / 遗府 / 首领）× 三种策略（dusk 540 秒 / night 720 秒 / greedy），输出每局接触数、入夜率、夜明宝箱拿到率；定向刷有按目标、按分区、按流派三种，输出目标段时长、拿到数、落空率、被迫组；另出点位表（入口均值 / 最近入口 / 最近常驻古阵秒数、暴露）和 `PROPOSALS` 提案点的可站、可达校验 | 先导出 `node tools/export_hf.mjs ../../../src/data/levels/r1.js _cache/bld_r1`（r2 同理），再 `./.venv/Scripts/python tools/build_drops.py 600`（约 50 秒）。设 `PROP=1` 时套用 `EXTRA_PAV` 补的亭子。输出 `docs/design/构筑与成长_v1/04_data[_prop].json/.txt` |
| `build_map.py` | 投放图：分区 + 道途色签、道途碑、匣、阵台、主材点、补的亭子 | `./.venv/Scripts/python tools/build_map.py` → `docs/design/构筑与成长_v1/img/04_r1.png / 04_r2.png` |

- 要改的参数都在脚本开头：`DWELL`（停留秒数）、`BUDGET`、`DETOUR`、`DAO`（分区道途）、`TARGETS`、`PROPOSALS`。
- 旧的 `_cache/stele_probe.py`（功法残碑刷点的一次性脚本）已经被 build_drops 的点位表和定向刷取代。
- 控制台是 GBK，中文输出会乱码。看结果读 UTF-8 的 `.txt`，或者用 `PYTHONIOENCODING=utf-8` 加 `sys.stdout.reconfigure(encoding='utf-8')`。
