# 关卡设计 · 本项目约定

## 文件归属
- 关卡岗位负责：`src/data/levels/*.js`、`src/world/**`（heightfield、level、level_mesh、markers、props、terrain、water、veg）、`tools/scenarios/loop_levels.mjs`。B 交付后由关卡接手。
- 不改：`src/game/run/**`（流程 A）、`src/data/enemies.js` / `loot.js`（内容 D 与数值）、UI。需要时用 SendMessage 找对方。

## 坐标与尺寸
- x 向东，z 向南（画面下方），单位米；北是 −z。
- 区域一 220×160，区域二 280×200（区域规划 v2，2026-11-17）。网格 0.5 米，外扩 margin 14。

## 地形数据（def）
- `terraces[{poly, h, w?, rough?, sharp?}]` 台地（取最大）；`pits` 谷地；`ramps[{a 低端, b 高端, width, steps}]` 是唯一能跨崖上下的地方。
- **`hardCliffs: true`**：碰撞网格的崖边是硬台阶，只有坡道 / 石阶能上下，渲染网格仍是平滑的。两张图都开着。
- **`deepWater: true`**：河与池是深水，walk 设为 DEEP_Y = −40，不可站。例外有三种：
  - `bridges`（stone / wood）；
  - 踏石 `style: "stones"`；
  - 浅滩渡口 `rivers[i].fords[{at, r, depth}]`，可涉水，`moveScale` ×0.7。
  - 接口：`level.isDeepWater`、`terrain.isDeepWater`、`level.isFord`、`canStand(x, z, fromY, r, { fly: true })`（御剑）。
- `gorges` 断涧：深切，走不过去；跳点写在 `points.jumps`（需要二段跳，双向）。
- `crags` 峭壁：峭壁会叠加到地形上，用来封缺口、夹石阶、做地标。

## 分区（区域规划 v2，与数值、敌人模块共同约定）
- `zones[{id, name, realm: [最低层, 最高层], baseLevel, danger(=risk), poly, boss?}]`；`level.zoneAt(x, z)` 返回分区对象，重叠时取 danger 高的。
- 敌人等级 = (spawn.baseLevel ?? zone.baseLevel) + clamp(玩家层数 − realm[0], 0, 1)，精英 +1，首领和异种固定，筑基按第 10 层算。
- 入口只放在最浅的分区；首领在最深处，中间至少隔 2 个分区；首领场 30 米内不放刷怪点和精英。
- 关口：r1 是西岭石阶（上北岭）和狼骨门（下狼谷）；r2 是裂谷石桥（进竹海深处）和碧鳞门（下深潭）。改地形后要重跑"封关口 → 深区不可达"的检查。

## 点位（`points`）
- `spawns[{pos, pack, zone, habitat, tier, mobs?, baseLevel?}]`
  - habitat 取值：nest / burrow / grass / water / ruin / rock；tier 取值：low / mid / high。
  - 低阶怪的栖息地：rat burrow/grass，crow nest/rock/ruin，spider ruin/rock，snake grass/water，toad water/rock。
  - 低阶组占比目标：r1 约 40%，r2 约 35%。
  - level.js 按分区由浅到深轮转排序；`def.spawnPlan.packs` 是建议的开局组数。
- `elites{pick, minGap 25, bossClear 30, from[[x, z, {shield}]]}`
  - r1 每局 3 只，r2 4 只，溪畔不放；r2 南半区（z > 20）只有土盾。
  - 午时的巡游精英单独计上限：r1 1 只，r2 2 只，不占开局的 3 / 4 个名额。这是数值策划 2026-11-17 定的，由敌人模块的 eliteBook 实现。之前巡游精英和开局精英共用一个上限，结果巡游精英被悄悄降成普通狼。
- `rares{pick [0,1], chance, from[{pos, sign, note}]}`
  - sign 取值：scorch / frost / bones / bloom / mist；地上会铺贴地墨渍作为暗示。
  - 只放在推荐最低层 ≥ 2（r1）或 ≥ 6（r2）的分区。
- `bossGate{pos, r, zone, boss, text, sub}`：走近时由流程弹提示；text 里的 `{realm}` 由流程用 `enemies.realmLabel` 替换。
- `pavilions{pick [2,4], from[{id, name, pos, ry}]}`：候选全部建亭；运行时 `points.pavilions` 是启用的容器（pos 在亭基石面上）。
- `glows` 灵光点：每种 2 个候选，每局抽 2 个，都在风险 ≥ 3 的分区，或有守卫。
- `chests{pick, glow, glowFrom, from}`：灵光宝箱只从 glowFrom（深区）抽。
- `ruins{pick, fake, from, fakeFrom}`：假阵只从 fakeFrom（离古阵远的中段）抽。
- `encounters[{id, pos, types}]`（bailu / fox / remains / rain）、`relics[{pos, place}]`、`patrols[{path}]`、`night[{pos}]`、`landmarks`。
- `boss`（青牙 v2，和战斗设计共同约定）：`{pos, arena 13, trigger 10, exit, perch, pillars[{id,pos,r}], totems[{id,pos,den}], gates[{id,pos,ry,w}], moonPaths, fence, adds}`。

## 首领专属场景件（`level.bossArena`，2026-11-17 落地）
- 只要 `points.boss` 里有 perch / pillars / totems，level.js 就会建出这些场景件，同时**不再建通用的立石圈**。数据里也不要再放 boulder 卧石。
- 接口（和战斗设计约定）：
  - `pillars[{id, pos, r, col, alive, break()}]`；
  - `totems[{id, pos, den, col, alive, setLit(on), fall()}]`；
  - `rock`（狼王石，碰撞体 id 是 "perch"）；
  - `gates.setOn("mist_n" | "rim" | "all", on)`、`gates.isOn(id)`；
  - `level.setMoonVeil(t)`、`level.moonSpots(t)` → `[{x, z, r}]`；
  - `level.inPit("狼谷", x, z)`。
- 碰撞体增删要用 level.js 里的 `addCol` / `removeCol`。`ctx.colliders` 是激活时从关卡复制过去的一份，两份都要改。
- 外观：先用 markers.js 里的程序化造型（wolfRock、fangPillar、wolfTotem、wolfStone、mistGatePosts）。美术的 glb 放进 `assets/models/props/<id>.glb` 后自动替换，用的是 import.meta.glob，不会产生 404。
  - id 列表：wolf_king_rock、fang_pillar / fang_pillar_broken、wolf_totem / wolf_totem_fallen、wolf_rock、mist_gate。
  - 模型材质按名称前缀换成 toon 材质：rock_ink、rock_pale、bone、cloth_banner、rope、totem_glow。
- 遮月**不加灯**：在天时色调之上，按分量乘 uLight、sun、hemi、背景色和 uPaper。注意 uLight 是 Vector3，按分量乘时不能直接 `.multiply(Color)`。
- 墨雾门复用 `fogWall(poly, ground, { on, k })`，`m.userData.uOn` 控制墨雾升起和散去。
- 首领场半径 ≥ 10 的空地里不放随机小石，免得和石柱混在一起读不清。
- 专属环境层在 `src/world/lair.js`，所有动态量都走共享 uniform（`bossArena.uVeil`、`uThick`、`uMoon`）：
  - `lairDressing`：巢穴散件，包括骨堆王座、狼窝草垫、狼颅、鹿角、爪痕、干血、墨渍、谷壁爪痕，都没有碰撞体。3D 散件只放在狼王石脚下、狼窝旁，以及离谷心 ≥ 10 米的谷边。
    - 美术的散件 glb（bone_long / bone_mid / bone_short / bone_rib、wolf_skull、antler、straw_nest；原点在底面中心）到齐后，会按摆放记录把每类烘焙合并成"每种材质一个网格"，替换掉程序化网格；缺 glb 的类别继续用程序化造型。
    - 程序化骨头和鹿角的原点在一端，摆放记录存的是中心位置（off 偏移）。
  - `veilShade`：谷内暗幕，乘法混合加软边。
  - `pitMist`：谷内低雾。
  - `mistBand`：谷沿柔雾带，向外淡出；setThick 时往谷心卷进来。
  - `moonSpot`：冷青地光、淡光柱和微尘。
- `gates.setThick(k)`：二阶段让雾变浓（墨雾门 uK 最高到 1.9，谷沿雾带往里卷）。这是叙事内的转阶段信号之一，因为用户否掉了转阶段横幅。

## 序章
- 数据在 `src/data/levels/tutorial.js`（= r1 + tutorialLayout），`steps[{seq, id, chapter, pos, goal, hint, say, done, teach, trigger, spawn, loot, gate}]`。
- 敌人只用现有类型，数值不改。精英木盾用宝箱里的金符（`fu_metal`）破，剑气斩仍在第一次回府时学。
- **已由流程组实现**：
  - `src/game/run/prologue.js`：事实记录式步骤引擎，按 seq 推进，忽略 legacy 点；
  - `prologue_ui.js`：序章标题和目标卷轴；
  - 金符拾取后直接进行囊；狼头目守场；
  - `loop_flow` 场景里有 170 多项断言覆盖。
- 改 steps 字段前，先读 prologue.js 看它实际读了哪些字段。`legacy: true` 的 `wolf_last` 点是给旧兜底代码留的，新引擎不读。

## 时长目标
- 单局：r1 ≤ 10 分钟，r2 ≤ 13 分钟。入口到最近古阵 ≤ 30 秒。序章 6–9 分钟。
- 天时：r1 第 9 分钟入暮，r2 第 9 分钟入暮、第 12 分钟入夜。
