# 关卡设计 · 坑

## 水墨后期会把"压暗"洗掉；ShapeGeometry 翻平后会被背面剔除（2026-11-17，狼谷遮月）
- **现象一**：遮月用普通 alpha 混合叠一层深色，或者全局把灯光调暗，截图里谷几乎没变暗，只是变灰。
  - **原因**：`src/render/ink.js` 把亮度用 smoothstep(0.03, 0.82) 映射到墨和纸之间，亮的地面一律饱和成纸色；alpha 混合的深色在映射之后变成灰白。
  - **做法**：用乘法混合（CustomBlending，DstColor × Zero），把亮度压到约 0.25 倍，才能在后期之后读出"暗"。只压谷内（贴地网格加软边），谷外保持原样，对比才明显。
- **现象二**：暗幕网格根本没有画出来。
  - **原因**：`ShapeGeometry` 建在 XY 平面，翻到 XZ 平面以后三角形朝下，单面材质被剔除了。
  - **做法**：设 `side: DoubleSide`，或者直接用网格自己生成顶点（还能逐顶点做软边）。
- **现象三**：月光斑和微尘用加色混合，在亮地面上一片发白，看起来像贴图失败。
  - **做法**：地面那层月光改用普通混合加冷青色；光柱和微尘的加色强度要低；点精灵的尺寸系数按镜头距离约 60 米来定（110 / 视距）。
- **规律**：涉及明暗的效果，**一定要在水墨后期之后截图确认**，不要只看材质参数。另外写了 `tools/scenarios/lv_veil.mjs`，可以逐层开关截图，单独检查暗幕、雾和月光斑各自的效果。

## 首领场地截图与调试：三个容易踩的点（2026-11-17）
- **视角名要加关卡前缀**：def.views 会注册成 `VIEWS["<id>_<name>"]`（见 debug.js），所以要写 `setView("r1_valley_top")`，写成 `setView("valley_top")` 会被静默忽略，截出来是跟随主角的画面。
- **遮月一开全屏变黑**：uLight 是 Vector3，`uLight.value.multiply(color)` 拿到的是 NaN。改法是按分量乘（`mul3`）。
- **专属场地里冒出多余的立石和碎石**：通用的 `arenaMarker` 立石圈（带碰撞体）和随机小石会和石柱、图腾混在一起。有 bossArena 时不建立石圈，大空地里不放小石。

## 信息过时：交付前先核对代码现状（2026-11-17）
- **现象**：区域规划 v2 的汇报里写了"序章需要流程组接新的步骤引擎，接好之前进游戏仍是旧版的 3 只狼"。实际上流程组早就按序章设计 v2 实现了 `prologue.js`、`prologue_ui.js`、金符进行囊和狼头目守场，`loop_flow` 有 170 多项断言覆盖。
- **原因**：汇报沿用了自己几轮之前的判断，没有重新查代码。其他模块在并行开发，状态一直在变。
- **规避**：交付或汇报里凡是写到"某模块还没做 / 需要谁接"，都要先 grep 核对，例如 `grep -rn "steps" src/game/run/prologue.js`、`ls src/game/run/`，或者跑对应的 loop 场景。写进知识库的状态描述也照此办理。

## 崖线渗漏：平滑崖边在 0.5 米网格上会形成可以走的"侧向缓坡"（2026-11-16）
- **现象**：封掉所有坡道以后，r1 仍有 18 处、r2 有 12 处能不走坡道上下台地。狼谷因此四面敞开。
- **原因**：heightfield 用 smoothstep 在 w ≈ 1–1.8 米宽的范围里过渡崖边，还叠了 rough 噪声。崖线方向接近网格行或列时，会出现一串沿着崖边慢慢升高的格子，每格高差都小于 0.55 米。`walk()` 的保崖插值只处理四角高差大于 0.9 的格子，救不了这种情况。只调小 w 和 rough 也只能减少，不能消除。
- **规避**：def 加 `hardCliffs: true`，让碰撞网格的崖边取硬台阶（heightfield 里 hard 网格）；渲染保持平滑。每次改地形都用 `tools/leaks.py` 回归。

## 遗府石台被瀑布缺口"走"下去（2026-11-16）
- **现象**：剑修遗府要二段跳才能上的石台，可以从北脊顺着瀑布缺口一路走下去。
- **原因**：河槽下切加上台地边缘过渡，形成了可以走的斜坡。
- **规避**：在缺口处加 crag 封住。凡是"需要能力才能到"的点，都要检查"不带能力是否到不了"（loop_levels 的 `gateBreak`）。

## 石阶穿过台地窄带，等于给深区开了侧门（2026-11-17）
- **现象**：狼谷北阶从谷底到北岭，中途穿过谷北那条 3.6 米高的台地窄带。从台地走上石阶中段，就能绕过北岭直接下谷。
- **规避**：在石阶两侧加 crag 夹住；再用"封掉关口 → 深区不可达"的检查确认。

## 关口两侧的乱石没盖满（2026-11-17）
- **现象**：r2 用 crag 截断溪谷时，峭壁和竹海崖之间留了 0.7 米宽的缝，人能挤过去。
- **规避**：crag 的 rx 要盖过崖边 1–2 米。crag 的有效半径约为 0.95 × rx，还会被 fbm 噪声削掉一些。

## 教学局方向和目标相反（2026-11-16）
- **现象**：`run.js tutorialSetup` 按固定方向 (1, 0, −0.6) 摆锈剑和狼，结果在溪东北，而破洞府在溪西北。第一次进游戏的人会先往反方向走。
- **规避**：序章的每一步都在数据里给出位置（`tutorialLayout.steps`），不要按方向推算位置。

## 序章内容太少，"一次只教一个概念"教过头了（2026-11-16，用户反馈）
- **现象**：教学局只有 75 米、3 只狼、1 株草，没有宝箱、精英，也没有 UI 标识。用户说"内容很少""UI 上也没体现在教学"。
- **原因**：G6 的引导节奏被理解成"少放内容"。正确的理解是：每个新概念都配一场战斗或一个奖励来教。
- **规避**：序章 6–9 分钟、至少 5 场战斗、难度递增、最后一只精英；每段有标题和目标卷轴。

## 序章敌人在开局就全刷出来（狼首过早刷出）
- **现象**：如果流程在开局一次性按 `tutorialLayout.spawns` 把怪全刷出来，玩家还没学护盾、没拿到金符，就在路边看到了狼首。精英提前出现，引导顺序就乱了。
- **规避**：`tutorialLayout.spawns` 只用于点位检查和植被避让，**刷怪一律按 `steps[].spawn` 的 when 触发**：`reach` 是走近 r 米刷出，`afterPrev` 是上一步完成时刷出，`channel` 是撤离读条开始时刷出。精英那一步走近 15 米才刷，并且排在宝箱（金符）之后。

## 深水改造后要重查连通性
- **现象**：河变成深水后，r1 北脊西段（[8,-48] 一带）成了孤岛；后面扩图又让 r2 北脊东段成了孤岛；r1 灵蚌灵光点被夹在池子和河之间，站不上去。
- **规避**：
  - 用 `water_check.py`（带入口、所有候选点）找孤岛；
  - 用 `detour.py` 比较改造前后的绕路，挑绕路最多的位置补桥、踏石或渡口；
  - 最后跑 `num_glows` 和 `loop_levels` 回归。

## 狼首对凡人偏硬（2026-11-16，待数值确认）
- 现有的 wolf_elite（600 气血、木盾 240）对凡人主角（160 气血）偏硬，估计要打 60–90 秒，三连扑能打掉一半血。序章要配回春丹和金符，身陨沿用"剧情救援"。

## 点位压在碰撞体上
- 常见原因：点和古阵标记、亭柱、宝箱碰撞体重叠；随机的树石压在奇遇点上（level.js 原来没给奇遇 / 遗物 / 异种点做 reserve，已补上）；窄桥上摆了五行坛，把桥堵死。
- 规避：每次改点位都跑 `loop_levels`，看 `bad`。Python 工具不计碰撞体，两者都要跑。

## 地图扩大后，单局全拿的时长会超标
- 地图扩大、内容按比例增加后，"全拿"会到 r1 13 分钟、r2 21 分钟。要用"收手"策略看真实局长；必要时减少 r2 南半区主路上的低阶组数，或缩短遗府内部时长，不要先降怪的血量。

## 扩图后坐标全变，要一次性检查所有候选
- 地形一改，原来合法的点可能落到崖上（例：灵土 [-52,-40] 落在了北岭崖边）。用 `water_check.py`（含巡游节点、异种点、首领门）、`num_glows`、`loop_levels` 三处一起回归。

## 单一随机来源的"在场率"远低于直觉；夜明宝箱只给贪心型（2026-11-18，构筑与成长 v1）
- **现象**：功法 v2 让"山神庙那块碑出落石诀"当作定向刷的来源。实测 pick [1,2] 抽 4–5 块碑，单块碑每局在场只有 0.30–0.39；止水诀 5 页如果只靠北岭碑，要约 13 局，而区域一一共只有 3–4 局（到筑基中位 7–8 局）。
- **另一个现象**：夜明宝箱在 dusk / night 策略下拿到率为 0，贪心型区域一 18%、区域二 100%。挂在夜明宝箱上的心法，对谨慎玩家等于拿不到。
- **规避**：给"定向来源"做设计之前，先用 `build_drops.py` 算"在场率 × 实际拿到率 × 局数预算"。单一随机点只能当补充，要么加偏置（例如道途碑必亮），要么配第二个来源。核心件不要挂在只有贪心策略才碰得到的来源上。

## Python 的 json 不认 numpy.bool_（2026-11-18）
- **现象**：`json.dump` 报 `Object of type bool is not JSON serializable`。原因是 `bool(...) and np.isfinite(...)` 返回的是 numpy.bool_。
- **规避**：整个表达式外面包一层 `bool(...)`。
