# 关卡设计 · 范例

## 用关口把开放地图串成"之"字路线（区域规划 v2）
- **设计**：
  - r1：北岭只能从最西边的西岭石阶上去，狼谷只能从北岭东头的狼骨门下去。入口在西南，所以到青牙要经过溪畔 → 竹林 → 山神庙 → 北岭 4 个分区，纯跑图约 54 秒。
  - r2：用"竹海裂谷 + 唯一的裂谷石桥"和"峡口乱石 + 唯一的碧鳞门"做出同样的结构。
- **为什么好**：解决了用户反馈的"出门就遇到青牙"。地图仍然是开放的，侧区（东麓、乱石岗、东台）都能自由去，只有主线深度被拉长。关口本身就是地标和门槛（界碑、狼骨、桥），可以用来做"此去：…"的提示。
- **位置**：`src/data/levels/r1.js`、`r2.js`（ramps、crags、gorges、bridges）；`docs/review/level/区域规划_v2.md`。
- **适用场景**：任何"首领要在最深处、但地图不大"的区域。做完要用"封关口 → 深区不可达"来验证。

## 序章：一个概念配一场战斗或一个奖励（序章 v2）
- **设计**：6 个小节、6 场战斗（单只 → 两只 → 伏击 → 群战 → 石傀混编 → 木盾精英），依次教移动、拾取、普攻、完美闪避、储物袋、采集、开箱、丹药、护盾（金符）、撤离读条。另有岔路和可选小环，地标是路碑、狼骨、石灯。
- **为什么好**：用户反馈序章"内容太少、看不出在教学"。新版新手约 7 分钟，每 30–60 秒出现一样新东西，所有点位都经过真实地形校验。关卡数据把每一步写全（位置、刷怪、文案、触发条件），流程组照着就能做出步骤引擎和 UI（`prologue.js`、`prologue_ui.js`），中间没有返工。
- **位置**：`src/data/levels/tutorial.js`、`docs/review/level/序章设计_v2.md`、`img/prologue_v2*.png`。
- **适用场景**：任何新系统的引导关。

## 深水 + 多种过河点
- **设计**：河一律是深水，过河点做成多种形态：石桥、木桥、踏石、浅滩渡口（涉水减速），间隔 20–30 米。
- **为什么好**：河成了真正的空间分隔，过河点自然成为路线节点和地标；绕路比 p90 只有 1.04。同时为筑基后的御剑提供了明确的"能飞过去的东西"。
- **位置**：`src/world/heightfield.js`（`_deep`、fords、stones）、`level.isDeepWater`。

## 刷怪点按分区轮转排序
- **设计**：先从风险最高的分区抽 1 组，其余按分区由浅到深轮流排。
- **为什么好**：流程只取前 N 组时，各分区都有怪，不会全落在一个角落。
- **位置**：`src/world/level.js` 的 spawns 排序。

## 首领专属环境：用环境本身表现阶段（青牙狼谷）
- **设计**：转阶段不靠 UI 横幅，靠环境的三个信号：谷内压暗偏冷青（谷外不变，形成对比），墨雾变浓、谷沿雾带往里卷，冷青月光斑出现。巢穴的环境叙事（骨堆王座、狼窝草垫、狼颅鹿角、爪痕血迹）只放在贴地或不挡路线的位置。
- **为什么好**：用户否掉了转阶段横幅，验收第 1 点就是"专属环境"。同机位一阶段和二阶段的截图差别一眼可见，走位和冲撞路线不受影响（`loop_levels` 校验无问题）。
- **位置**：`src/world/lair.js`、`level.js` 的 bossArena；截图 `work/shots/loop_levels_r1_valley_arena*.png`、`loop_levels_r1_valley_play_boss*.png`。
- **适用场景**：碧鳞潭等其他首领场：用同一套暗幕、雾带、光斑和散件，换颜色和散件内容即可。
