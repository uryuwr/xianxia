# 战斗设计 · 范例

本项目做得好、值得沿用的设计。设计说明：`docs/战斗_气势与身法_v1.md`。

## 1. 右键蓄势斩（主动释放 + 半势按比例 + 缓存）
- **是什么**：气势 ≥ 50 就能按右键放（伤害 / 范围 / 剑气距离按比例），满 100 有完整演出；普攻前半段 / 施法 / 闪身中按下先缓存，到可取消时立即放出；瞄准法术时右键只取消瞄准，开着储物袋 / 搜取 / 地图时右键归界面。
- **为什么好**：v1 的"满势后第三段自动接第四段"被用户否决（不能挑时机）。主动 + 半势可放让"小怪群 50 就放一刀清场、精英攒满再放"都成立；缓存让"闪身穿过去、落地右键"成为最顺的手感。
- **位置**：`src/game/player.js` tryCharge / canStartCharge / startCharge / doCharge；右键判定 `src/game/targeting/index.js` handleInput / uiOpen / charge；数据 `src/data/player.js` CHARGE。
- **适用**：任何"攒资源放大招"的设计。

## 2. 势成不流失（资源可携带）
- **是什么**：气势完全不随时间流失（v1.3），满 100 为"势成"受击也不扣；出局 / 新一局清零。
- **为什么好**：用户原话"小怪离精英挺远，打小怪攒的势跑过去就没了"。可携带资源把清小怪变成了为精英战做准备，配合"剑意破盾"让没带克制法术也能破防。
- **位置**：player.js update（无衰减）、构造函数里 `run:start / run:end` 清零。

## 3. 剑意破盾：给新机制一个"身份"
- **是什么**：满势斩命中带护盾的敌人，不看五行直接削护盾上限 35%（首领每段 20%），再按普通倍率结算。
- **为什么好**：护盾系统原本只认五行克制，没带克制法术就很难打；剑意给普攻流一条独立的破盾路线，又不比克制法术快（互补而不是替代）。
- **位置**：player.js chargeHit；数据 CHARGE.shieldCut。

## 4. 伤害对标法术（拟合 base + scale）
- **是什么**：满势一刀 ≈ 同境界剑气斩三道全中的 1.8 倍、半势 ≈ 1 倍；用 `num_charge` 测出各境界剑气斩伤害，拟合出 横扫 75 + 3.45 × 攻击、剑气 40 + 1.88 × 攻击。
- **为什么好**：用户的抱怨是"门槛比法术高，伤害却差太多"，直接拿法术当尺子最好沟通；固定值让低境界也成立。
- **位置**：`tools/scenarios/num_charge.mjs`；设计说明 §3.4 标定表。

## 5. 附灵五行视觉
- **是什么**：墨色笔触为底，刀光 / 剑气外缘一圈五行色、第三段与蓄势斩笔芯五行深调；命中五色墨点；伤害数字前缀小五行字 + 五行描边；剑身流光 + 剑穗换色 + 剑上飘五行微光；HUD 闪身墨点旁一方五行印（悬停讲对各色盾的倍率）；五行坛附灵最后 3 秒闪烁、结束飘"坛力散去"。
- **为什么好**：用户"爆了木属性的剑没感到区别"；做法保持水墨不变霓虹，静止时也看得出。
- **位置**：`src/fx/player_fx.js` ELEM_LOOK / slash / wave；player.js updateImbue / imbueHitFx；`src/game/feedback.js`；`src/ui/imbue.js`。截图 `work/shots/loop_momentum_imbue_*`。

## 6. 刀光对象池
- **是什么**：刀光 8 个、剑气 2 个网格常驻场景，几何体按（半径, 弧度, 笔宽, 方向）缓存，出招只改 uniform；满了复用最早的。
- **为什么好**：集显上每次 new 材质会周期性卡 60–170ms；池化后材质数恒定，`loop_momentum` 断言池大小不变。性能组把它写成了全局规范（`docs/性能优化_v1.md` §7 第 1 条）。
- **位置**：`src/fx/player_fx.js` PlayerFX 构造函数 / slash / wave。

## 7. 闪身冷却 + 完美闪避返还
- **是什么**：1 次充能 2.75 秒，练六起 2 次（成长点）；完美闪身返还 60% 冷却 + 25 气势。HUD 墨点里墨晕按冷却进度扫过，冷却中按 Space 墨点抖一下泛朱。
- **为什么好**：不能无限闪，但会闪的人几乎感觉不到冷却（技巧奖励），第二次充能成为可感知的成长。

## 8. 御剑：把"跃涧"泛化
- **是什么**：筑基后在深水 / 崖边朝对岸按 Space，闪身路线被挡且 12 米内有可站落点 → 踏剑掠过；筑基前提示"水深难渡，需御剑（筑基）"。落点判定只依赖关卡接口 `terrain.isDeepWater`。
- **为什么好**：不新增按键，复用"跃涧"的状态与无敌；和关卡"深水只能走桥"的设计配合，筑基成为探索上的明确解锁。
- **位置**：player.js trySwordFly / flyStand / swordFlyHint；`src/fx/player_fx.js` ride；数据 PLAYER.swordFly。

## 敌人 AI 与预警（敌人模块 D，2026-11-17）

### 9. 数据驱动的招式与预警
- **设计**：每个招式是一条数据，字段包括：
  - 形状：arc / line / circle / projectile，或 at: target 落点圈（multi 多圈）；
  - 节奏：windup / active / recover / cooldown，以及 animHit 命中帧；
  - 位移与连段：lunge、combo；
  - 效果：status / element / summon / buff；
  - 特殊：teleport + hide（潜水突袭）。

  预警由内向外填满，填满即出伤；动画按 animHit / windup 放慢，出手和预警结束对齐。
- **为什么好**：新怪只写数据。首领的特殊招式（水柱四圈、潜水突袭、召狼）都是同一套字段的组合。
- **位置**：`src/data/enemies.js` 文件头的字段说明，`src/game/enemies/enemy.js` 的 startAttack / makeTelegraph / strike。

### 10. 首领输出窗口（RHYTHM）
- **设计**：
  - 大招后摇不转身；大招落空时踉跄；
  - 连出 2–3 招后喘息：头顶冒墨气、出现淡金"隙"字，受击不会被打断；
  - 破盾眩晕 3 秒（精英）/ 2.5 秒（首领）。
- **为什么好**：用户反馈"输出间隙太少、被逼换血"，改完后窗口清楚可读。
- **位置**：enemy.js 的 RHYTHM / wind / recoverTime；截图 `work/shots/tele_closeup_qingya_winded.png`；测试 `loop_content` 的"big-move recovery"等 3 项。

### 11. 首领控制器钩子（给青牙 v2 / 碧鳞重做）
- **设计**：`def.controller(enemy)` 返回控制器，可选实现以下回调：
  - update、pickAttack；
  - onStartAttack / onStrike / onEndAttack；
  - onHit（返回 true 吞掉默认硬直）、onBeforeDamage（排在护盾之后）；
  - onChannelHit / onChannelBreak、onLungeBlocked、onCC(id, dur, { src, tag })（ccMode: poise）、onDeath。

  招式字段 channel / rear / at: "behind"；状态 setState("down" | "cinematic")。
- **为什么好**：首领的特殊机制（失衡、处决、撞柱、读条打断）写在独立文件里，不污染通用 AI；默认行为不变。
- **位置**：enemy.js 文件头注释；回归测试 `loop_content` 的"boss controller hooks"。

### 12. 境界显示（神识看境界）
- **设计**：敌人有境界（等级换算，或数据表 realm）。
  - 大境界高于主角显示"???"（朱色）；
  - 同大境界、层数更高且神识不足（神识 < 层差 × 16）显示"练气?"（淡朱）；
  - 其他情况显示准确境界，例如"练气四层"。
- **为什么好**：用户原话"看不到修为说明神识不够，或者修为差了一个大境界"；神识在战斗里也有了用处。
- **位置**：index.js 的 realmLabel、hpbars.js；测试 `node tools/run.mjs realm_view`。

## 9. 阶段转换用叙事内信号，不用横幅（青牙 v2，2026-11-17 用户拍板）
- **是什么**：青牙进二阶段不弹"二 · 啸月"横幅、首领条上也不写阶段字；3.6 秒演出里叠加五类信号——演出（跃上狼王石长啸、镜头推近约 40%）、外观（骨甲炸裂、背上青光裂缝、眼焰常驻、毛色 0.9 秒压暗泛青）、环境（墨云遮月整谷压暗偏青、两片月光开始漂移、墨雾门与谷沿雾变浓、两圈狼嚎回声墨环）、护盾（木气散尽 → 2.8 秒土盾"重生"：描边壳长出冲过头回落 + 阵纹落定）、节奏（之后移速 +15%、新招）。
- **为什么好**：用户原话"太生硬，不需要。直接通过 boss 的外观变化、护盾变化或者环境变化，让玩家自己判断是否进入了二阶段"。叙事内信号既是信息也是奖励（"我把它逼急了"），且之后常驻、随时可读，横幅只闪一次。
- **怎么做**：信号要多通道冗余（至少外观 + 环境 + 护盾三类同时变），每一类都"常驻可读"而不是只在演出里出现；全部用现有手段（vfx 墨点池、`level.setMoonVeil` 调色不加灯、boss_look 改共享材质参数），不建新 UI。
- **位置**：`src/game/enemies/bosses/qingya.js` startTransition / updateTransition；`src/fx/boss_look.js`（美术管线）；`level.setMoonVeil / gates.setThick`（关卡）；设计 `docs/design/boss_青牙_v2.md` §4.3。
- **适用**：所有首领的阶段转换（碧鳞换段护盾同理：用水面、潭色、鳞片变化表达，而不是文字）。

## 10. 首领控制器 + 同接口的场景件桩（青牙 v2）
- **是什么**：首领逻辑放独立控制器（`src/game/enemies/bosses/qingya.js`），通过敌人模块的通用钩子（`def.controller`、`onCC`、`onChannelHit`、`onBeforeDamage`、`onLungeBlocked`、`setState`）挂上去；场景件按约定接口取 `activeLevel().bossArena`，没有就建同接口的桩（`qingya_arena_stub.js`）。演出用通用时间轴（`execution.js`），只发事件，不建 UI。
- **为什么好**：五个岗位（敌人、关卡、美术、UI、流程）同时开工、互不改对方文件；关卡的正式场景件落地后零改动切换；`boss_qingya` 43 项在桩和正式件上都能跑。
- **适用**：碧鳞、心魔等后续首领；任何"一个系统依赖多个还没交付的岗位"的功能——先定接口、写同接口的桩、用事件对外。

## 11. 法术自带首领参数（功法体系 v2，2026-11-17）
- **是什么**：`SPELLS[id].boss = { poise, chan }`，`strike()` 把法术 id 写进 `spec.spell`，青牙控制器先查它（落石诀打断 1.2、狼威 18），没填的法术仍按五行旧规则。
- **为什么好**：加新法术只改一行数据，首领交互不用改控制器；旧法术行为不变（回归 boss_qingya 不受影响）。
- **位置**：`src/data/skills.js`、`src/game/skills/effects.js` strike、`src/game/enemies/bosses/qingya.js` spellBoss。
- **适用**：碧鳞等后续首领的控制器直接复用 `spellBoss(info)`。

## 12. 指引从掉落表推出来（功法体系 v2）
- **是什么**：`gongfaSources(id)` 扫 SOURCES / 遗府 / 首领 / 境界赠予 / 残碑分区，生成"区域 · 谁 · 残页 / 完本 · 概率档"；功法匣未领悟条目直接显示最具体的一条 + 残页进度。
- **为什么好**：用户原话"没有目标指引""残页多少合成完本没提示"；来源文字不手写，掉落表一改就同步，不会出现"写着山神庙其实不掉"。
- **位置**：`src/game/gongfa.js`；`src/ui/loadout.js` pool / srcLines。
- **适用**：丹方残页（玩法系统已约定共用 pageHint）、任何"集齐 N 个兑换"的物品。

## 13. 法术位移借用闪身状态（skillMove）
- **是什么**：`player.skillMove(dir, dist, dur, { iframe, hide, onEnd })` 复用闪身的 tryMove（崖、深水、碰撞体照挡），不耗充能、不触发完美闪身。
- **为什么好**：位移法术不会成为越过关卡门槛（断涧、深水）的漏洞；藤引 / 地行术共用一套。
- **位置**：`src/game/player.js` skillMove、dash 分支的 `d.skill`。
