# 美术管线 · 范例

> 本项目做得好、值得沿用的设计。

## 1. 一条命令出一只怪：lib_creature.py + build_<name>.py + render_creature.py（敌人模块 D）
- **做法**：
  - 公共库提供网格构建器（loft / ellipsoid / spike / block / sheet）、按部件自动权重、骨架空间关键姿势、烘焙、导出；
  - 每只怪一个 build 脚本，只写三样：造型、骨骼表、关键姿势表；
  - 通用渲染脚本自动按包围盒取景，输出侧视、正视、45° 俯视、游戏距离和动作帧拼图，同时打印校验信息（三角面、包围盒、骨骼、材质、动作）。
- **为什么好**：
  - 新怪从零到进游戏约 1 小时，改造型只改脚本、重跑即可，没有手工 Blender 操作；
  - 校验输出能马上发现缺动画、材质名拼错。
- **位置**：`blender/lib_creature.py`、`blender/build_{golem,bat,vine,serpent,rat,crow,spider,snake,toad}.py`、`blender/render_creature.py`、`assets/previews/<name>_*.png`
- **适用**：所有新怪；同骨架的变体从已有脚本派生，例如 build_crow.py 由 build_bat.py 派生，翼骨和扇翅动作直接复用。

## 2. 异种 = 原模型 + 稀有染色 + 头顶光环（不另建模）
- **做法**：
  - 数据表的 `tint` 按材质名改色（赤狼：火红身、橙鬃、金眼）；
  - `halo` 在头顶加一圈淡淡的异色光环，几何和材质按颜色共享；
  - `nameColor` 让血条名字用品级色。
- **为什么好**：零建模成本，模型一致但一眼就能看出"不一样"；光环用共享的透明材质，不新增着色器变体。
- **位置**：`src/data/enemies.js` 的 chilang / xuanlin_bat，`src/game/enemies/enemy.js` 的 haloGeo / haloMat；截图 `work/shots/new_mobs_chilang.png`。
- **适用**：精英 / 异种 / 剧情特殊个体。

## 3. 首领喘息窗口的表现：骨骼取头位 + 克制的墨气和"隙"字
- **做法**：
  - 喘息时身体随呼吸轻微起伏；
  - 每 0.22 秒从 head 骨冒一小撮淡墨（复用 vfx.burst 粒子池）；
  - 头顶一个淡金色的"隙"字（DOM，复用血条层）。
- **为什么好**：输出窗口一眼可读，又不抢画面；没有新材质和新几何。
- **位置**：enemy.js 的 wind / updateWinded / headPos，hpbars.js 的 hint；截图 `work/shots/tele_closeup_qingya_winded.png`。

## 4. 首领阶段外观 = 多子网格 + 外观辅助模块（青牙 v2，美术管线 2026-11-17）
- **做法**：qingya.glb 里本体 / 一阶段骨甲 / 二阶段裂板裂缝 / 眼焰火芯四个蒙皮子网格共用一副骨骼；`src/fx/boss_look.js` 给控制器 6 个调用（setPhase、armorBurst、crackGlow、update、shield、dispose），护盾外观自动读 `entity.shield`；控制器用 `import.meta.glob` 试探模块存在，美术没交付前跳过。
- **为什么好**：战斗主策只管"什么时候切"，美术管"切成什么样"，双方并行开发互不阻塞；二阶段弱点（裂缝）在 45° 俯视和游戏距离一眼可读（主管验收），新增的护盾外观不新增着色器程序。
- **位置**：`blender/build_qingya.py`、`src/fx/boss_look.js`；截图 `work/shots/look_qingya_{p1_wood,p1,p2_moon,p2_earth,p2_close}.png`，预览 `assets/previews/qingya_topdown45.png`、`qingya_p2_topdown45.png`。
- **适用**：碧鳞（换盾 / 潜水阶段）、后续首领的部位破坏、异种的特殊外观。

## 5. 往已有模型追加动画：逐通道比对证明"旧的没动"
- **做法**：改 build 脚本前先备份 glb（`work/hero_before_exec.glb`），新动画只在 `bake_all` 末尾追加、需要接续的用 `warm_fn` 给起始姿势；重建后 `python tools/glb_anim_diff.py 旧 新`，12 段旧动画 max abs diff = 0。
- **为什么好**：主角是所有系统共用的资产，"不要破坏现有动画"用数据证明而不是靠肉眼；再跑 `node tools/run.mjs hero` 回归（18/18）。
- **位置**：`blender/build_hero.py` execute_*_keys、`tools/glb_anim_diff.py`、`assets/previews/hero_poses_exec.png`。
- **适用**：任何共享模型的增量修改（加动作、加材质分区）。

## 6. 场景件：一状态一文件、同原点、按 id 自动替换程序化占位（与关卡设计约定）
- **做法**：`assets/models/props/<id>.glb`，完好 / 破损各一个文件、原点相同；关卡 `markers.js` 用 `import.meta.glob` 列出存在的文件，有就 `swapPropModel` 换掉程序化占位，没有就用占位；材质按名称前缀换成关卡的三平面笔刷 toon。
- **为什么好**：美术和关卡完全并行，文件放进去即生效、不产生 404；状态切换只是显隐两个节点，没有运行时拆网格。
- **位置**：`blender/build_wolfvalley.py`、`src/world/markers.js`（关卡设计）、截图 `work/shots/look_qingya_valley.png`。
- **适用**：所有可破坏 / 多状态场景件（宝箱开合、阵眼亮灭、桥断）。


## 7. 纯程序精细化小样：同一套资产 × 三种着色 × 现状对比，一个能双击打开的 HTML（美术管线 2026-11-18）
- **做法**：生成器（`tools/art_refine_v1/src/`）现算全部几何与贴图；现状版直接 import 游戏的 temple() / rockGeo / toon / ink.js（不是仿制）；材质工厂让 A / B / C 只换材质；面板实时报 draw call / 三角面 / 贴图显存 / GPU 基准（背靠背 30 帧中位数），切换后自动重测；"游戏预算"开关演示 LOD 能省多少。
- **为什么好**：用户在自己的 RTX 3070 上能同时看到"好看多少"和"贵多少"；对比在同一机位、同一光照、同一后期，结论可信；四宫格截图一眼看差别。
- **位置**：`docs/art/精细化小样_v1/index.html`、`建筑与环境.md`、`png/sheet_{game,close,roof}.png`。
- **适用**：任何"风格 / 画质方案让用户选"的美术提案（先给可点的 HTML，再落地）。

## 8. 屋顶高度场 + 实例化瓦（美术管线 2026-11-18）
- **做法**：见 方法论 §10–11；`tools/art_refine_v1/src/temple.js`（facet / frame / 瓦模板 / 扫掠屋脊 / 吻兽）。
- **为什么好**：45° 镜头下屋顶是画面主体，瓦垄 + 叠压台阶 + 翼角起翘让现状的"一块灰板"变成能读出年代感的屋面（`png/sheet_roof.png`）；所有构件同源取点，改尺寸不会穿帮。
- **适用**：山神庙、山亭、剑修遗府等所有坡屋顶建筑；参数化后可出悬山 / 庑殿 / 攒尖。


## 2026-11-18 精细化小样 · 主管复盘

### 青牙 v2 首版：骨甲分块 + 毛尾 + 鬃毛（观感方向可沿用，面数不可）
- **是什么**：骨甲按块分开（每块有厚度与断面）、尾巴和鬃毛做成成束的毛片，剪影比现版更"狼王"。
- **为什么好**：主管对比现版观感明显提升，剪影信息增加而不是表面噪点增加——这正是"剪影优先"的精细化方向。代价：面数 11.7k / 13.1k，超首领 ≤ 2.5k 约定，落地前须减（毛 / 鬃改少数大片 + 贴图）或报主管放宽。
- **位置**：`blender/refine_v1/build_qingya_v2.py`、`docs/art/精细化小样_v1/assets/qingya_v2.glb`、截图 `docs/art/精细化小样_v1/png/qingya_{game,close,front,side,head,p2}.png`。
- **适用**：首领 / 精英的精细版；对照反例是林墨 v2 首版（细节加在表面而不是剪影上，见 坑"主管复盘"节）。

### 性能实测随方案一起交：perf_3070.json
- **是什么**：小样页面的 `bench()` 在用户同款 RTX 3070 上测现状 / A / B / C / 预算 × 两种分辨率，存成 json（数据见 本项目约定"主管复盘"节）。
- **为什么好**：一眼看出"GPU 帧时不是问题、代价在面数和显存"，避免凭感觉争论；只跑一轮存档，后续引用文件不重跑。
- **位置**：`docs/art/精细化小样_v1/perf_3070.json`（集显 `perf_igpu.json`）。
- **适用**：任何画质 / 风格提案。

## 精细化小样 v1 · 角色 / 怪物（美术管线 art-char，2026-11-18）
### 9. 只换网格不碰动画：执行原 build 脚本拿骨架 + 动作
- **做法**：`lib_refine.load_legacy_hero()` / `load_legacy_creature()` 在内存里执行 `build_hero.py` / `build_qingya.py`（去掉导出），新网格按部件套原权重公式 + 网格平滑后挂到同一副骨架导出。
- **为什么好**：主角 15 段、青牙 27 段动画（含次级动态、命中帧）零改动、零比对成本；`png/hero_slash.png`、`qingya_bite.png` 命中帧截图直接证明变形正常。
- **位置**：`blender/refine_v1/lib_refine.py`。**适用**：任何"换外观不换动作"的升级（异种外观、精英重做、LOD 网格）。
### 10. 对比截图页：每个模型一格、各自镜头、逐格过水墨后期再拼
- **做法**：`docs/art/精细化小样_v1/char_preview/`：同一场景里依次只显示一个模型，按最大包围盒算同一距离，`InkPipeline.render` 后 `drawImage` 拼到 2D 画布；`?set=lAvAvBvC` 选"现状 A / 精细 A / B / C"，`view=game` 用游戏镜头（距 30 米、45°）。
- **为什么好**：现状和新版在同光照、同后期、同大小下对比，用户和主管一眼看出差异；游戏镜头格按真实像素裁切，防止"近景好看、游戏里更脏"。
