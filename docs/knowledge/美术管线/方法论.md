# 美术管线 · 方法论

> 业内通行的做法 + 本项目取值。项目特有规则见 本项目约定.md。

## 怪物建模（低面数 · 风格化 · 程序化）（敌人模块 D，2026-11-17）

### 1. 剪影优先：从 45° 俯视设计轮廓
- 游戏镜头是斜 45° 俯视、约 14–30 米远，怪物在屏幕上只有 40–150 像素。辨识靠**剪影 + 一两处亮色**，不靠细节。
- 每种怪先定一个"俯视轮廓关键词"，再建模：
  - 狼：锯齿背脊；
  - 石傀：倒梯形 + 两块大石拳；
  - 蝠妖 / 鸦妖：张开的"八"字翼；
  - 藤妖：放射根座 + 头顶朱红花；
  - 碧鳞：C 形盘身 + 立起的头颈；
  - 蛛妖：放射的"米"字腿；
  - 山鼠妖：大圆耳 + 细长尾；
  - 寒蟾：宽扁 + 霜白疣点。
- 验收：Workbench 渲染 `<name>_topdown45.png`（85 mm 镜头、方位角 −120°），在灰底上一眼认得出是什么。
- 每只怪只给 1–2 处高饱和亮色（朱红眼、发光符文、头顶红花、金喙），其余都是墨色和低饱和色。水墨画面里亮色就是视觉焦点，也是预警以外的识别标记。

### 2. 低面数造型的三种基本形
- **放样 loft**：沿中心线放椭圆截面，做躯干、腿、尾、蛇身、藤臂。中心线用 Catmull-Rom 插值，截面半径逐环插值。
- **椭球 ellipsoid**：头、眼、关节鼓包、疣粒。
- **笔触尖刺 spike**：扁圆锥，做毛簇、背刺、爪牙、羽毛、叶片。这是"水墨笔触感"的主要来源：一排沿身体方向倾斜的扁刺，比贴图毛发更像毛笔。
- 另有 **block**（切角方块：石头、盔甲）和 **sheet**（双层薄片：翼膜、羽膜，双面可见）。
- 面数取值：低阶怪 550–1000 三角面，标准怪 1–2k，首领 1.6–2.5k。

### 3. 骨骼与蒙皮：按"部件"自动权重
- 每个网格顶点标一个部件名（part），部件映射到 1–N 根骨骼（PART_BONES）。多骨部件按到骨段距离的 4 次方反比，取最近两根骨骼加权。
- 硬表面（石傀）直接一部件一骨骼，刚性绑定，动起来像石块在磨。
- 长身体（蛇、尾、藤臂）按环指定部件，再按距离分段到骨骼链。
- 生物面向 −Y、Z 向上建模，导出 glTF 时 export_yup 自动变成面向 +Z、Y 向上。

### 4. 动画：骨架空间欧拉角 + 关键姿势表
- 每根骨骼一个"骨架空间"欧拉角（度，YXZ 顺序），和骨骼自身朝向无关。写姿势时只想"绕世界 X / Y / Z 转多少"：
  - 指向上方的骨骼绕 +X 正转是前倾；
  - 指向下方的骨骼绕 +X 正转是向后摆；
  - 指向 +X 的翼绕 Y 正转是向下扇。
- 动作写成关键姿势表 `[(时间, pose(...))]`，用 smoothstep 插值；循环动作用正弦加相位滞后（尾、翼、蛇身逐节滞后 0.6–0.9 弧度）。
- **命中帧对齐**：每个攻击动画定一个命中帧时间（animHit），游戏在预警期间按 animHit / windup 放慢播放，保证"出手瞬间 = 预警结束"。动画师只管姿势，节奏由数据表决定。

### 5. NPR 描边：反向外壳（inverted hull）
- 运行时用描边壳：沿法线外扩一点、背面朝外的同网格，渲染成墨色，只有超出剪影的那圈可见。业内标准做法，适合低面数。
- 本项目在 three.js 里实现（src/game/enemies/enemy.js 构造函数），蒙皮网格的描边壳绑同一副骨骼。厚度是世界单位，所以大型首领看起来线更粗，这正好符合水墨"大物粗笔"的感觉。
- 材质按 Blender 材质名在游戏里替换成卡通水墨材质（PALETTE），模型里的颜色只用于预览。

## 敌人预警特效（2026-11-17）
- 预警只用三种形状：扇形 / 直线 / 圆。全部"由内向外填满"，填满的那一刻就是出伤时刻。圆可以落在主角脚下（at: target），也可以多圈同时出现。
- 所有边缘都是柔边：smoothstep 宽度加上 fwidth（约 1.5 像素）抗锯齿，几何边界处透明度为 0。笔触毛糙感用沿边方向缓变的一维值噪声，**不要用 floor 出来的方格 hash**。
- 预警要贴地：网格细分（扇形 20×20、直线 4×20），每帧把顶点贴到地面高度；凹处（河道）不往下贴超过 0.6 米。

## 首领造型与阶段外观（青牙 v2，美术管线 2026-11-17）

### 6. 首领的"压迫感"来自比例，不来自缩放
- 同一只狼放大 2.6 倍仍然像狼；要像"狼王"，改的是比例：腿长 ≈ 躯干中心高度（0.85–0.9 狼单位，竹林狼约 1.05），前肢根部半径 0.16（竹林狼 0.08），胸截面 0.28 × 0.34，颈根 0.21 × 0.25，头 0.17 × 0.18 × 0.14 且前探低于肩线。
- 待机就是剪影：低伏（stand crouch 0.22）、前肢略外撑、头平视；45° 俯视里是"宽肩 + 一排浅色骨板 + 头后一团浅色长鬃"。
- 本项目取值：青牙模型 2.1–2.5k 三角面（一阶段 2376 / 二阶段 2480），游戏 scale 2.2（肩高 2.75 米、体长约 6.8 米，竹林狼 ×2 以上体量）。

### 7. 有厚度的贴体骨板（shell）
- 在躯干椭圆截面上按 (θ, y) 取网格：外层 = 截面外扩 d、内层 = 外扩 d − thick，加一圈边沿面；边沿顶点在 y 和 θ 上随机参差（jag 0.025–0.035），θ = 0 附近再外扩 keel 形成中脊。
- 每块骨板约 80 三角面（7 × 3 网格），比"弧 + 大刺"贵一点，但有厚度、有断面，水墨描边能描出板的边。
- 碎裂态复用同一函数：θ 从 ±0.22 开始（脊线留缝）、两半各自外掀一点，**靠脊线的断面用发光材质（crack_glow）**，中缝再放一条发光锯齿带——"裂开的骨板 + 缝里透青光"一眼可读。见 `blender/build_qingya.py` shell()。

### 8. 阶段外观切换：同一骨架上的多个蒙皮子网格
- 一个 GLB 里放多个蒙皮网格共用一副骨骼（`lib_creature` 用 `mb.cur = "组名"` 分组，导出成 `<名>_<组>` 节点）；运行时按节点名收集几何体、按几何体切显隐（连描边壳一起）。比换模型便宜（不重建骨骼和 mixer），比 morph / 缩放骨骼稳（不和动画打架）。
- 叙事内信号（用户否掉了"二 · 啸月"横幅后，转阶段全靠外观说话）：骨甲崩裂（骨片 + 墨点 + 青光飞散，复用 vfx.burst 池）、毛色 0.9 秒内压暗泛青（保留自发光托底）、眼焰常驻、护盾"长出来"（描边壳宽度 0 → 冲过头 → 回落，0.45 秒）。

### 9. 五行护盾 = 第二层描边壳（不用半透明大球）
- 半透明大球会把本体和地面预警罩成一团（战斗设计坑 #21）。改为在墨线描边外再套一层五行色描边壳：直接用 `materials.js outlineMaterial(宽, 色)`，程序缓存键都是 "jx-outline"，**和普通描边共用一个着色器程序**，五种颜色各一份材质，只改 uniform（宽度随剩余护盾变细、呼吸）。只给剪影主体（主毛、长鬃、骨板）加壳，每个首领 ≤ 4 次额外绘制。
- 脚下阵纹：Canvas 画三道笔断意连的圆环 + 五方三爻，径向渐隐到 0；`MeshBasicMaterial` 透明、不写深度、不投影、按五行色着色、慢转。


## 纯程序精细化：建筑 / 环境（精细化小样 v1，美术管线 2026-11-18）
小样：`docs/art/精细化小样_v1/index.html`，说明 `建筑与环境.md`，生成器 `tools/art_refine_v1/src/`。

### 10. 中式屋顶 = 平面高度场 + 角部修正（不建面片拼接）
- 前后坡 `H = f(zE(x) − |z|) + rise(x, z)`，两山 `H = f(xE(z) − |x|) + rise`；`f(d)` 是举折曲线（d = 到檐口的水平距离），本项目取 `檐口高 + 0.32 d + 0.036 d^2.4`（檐口约 18°、脊下约 47°）。
- 出翘（平面外撇）：`zE(x) = 半深 + 0.45 · sx^2.2`；起翘（升高）：`rise = 0.55 · (sx · sz)^1.5`，sx / sz = 到角部的归一距离（2.2 米内为 0）。两坡在戗脊处天然连续——戗脊线就是"两坡 d 相等"，二分法求。
- 歇山 = 前后坡越过山花挑到博风外皮（XB），两山只铺到山花面（XG），山花是两坡之间的竖墙。所有构件（瓦垄、脊、博风、山花、椽）都从同一组函数取点，所以永远贴合。
- 45° 俯视镜头下屋顶占画面最多：先做瓦垄、檐口曲线、翼角、屋脊兽件；斗拱、棂格、匾额在游戏镜头里被檐口挡住，只给近景。
- 高度：游戏镜头（视角 30°、距 30 米、俯角 45°）下，主角站在建筑正前方时，**建筑最高点到注视点的"屏幕向上距离" ≈ 高度 × cos45° + 纵深 × sin45° 要 ≤ 8 米**才不被画面上沿切掉；山神庙因此整体缩放 0.8（正脊顶约 6.5 米）。

### 11. 瓦件实例化
- 板瓦（凹壳 24 面）/ 筒瓦（半圆壳 32 面）带厚度；垄距 0.30 米，沿坡按**弧长**每路 0.27 米（压七露三），每片下端抬 2.2 厘米 = 叠压台阶（远看"瓦垄有节奏"的关键）；随机微转、缺 1% 筒瓦。瓦垄沿等 x（前后坡）/ 等 z（两山）铺到戗脊截断，由戗脊盖住。
- 每片的实例矩阵：原点 = 坡面点，基 = (横, 坡面法线, 下坡方向)；法线 / 下坡方向用高度场有限差分。实例属性 `aUvOff` 让每片瓦取不同的贴图区域。
- 一座三开间歇山约 3500 片瓦 + 300 个瓦当滴水，4 个 draw call、约 12 万三角面；**瓦片不投影**，屋面整体影子由瓦下垫层投出（集显上瓦片投影约占阴影 pass 一半）。

### 12. 两段式程序化贴图（配方 → 高度场 → 法线 / AO / 缝隙）
- 配方 = 可平铺场函数 `field(uv) → (高度[米], m1, m2, m3)` + 着色函数；第 2 遍一个收尾着色器画三次：albedo（缝隙积灰 = 与一圈均值比较的凹度压暗、凸棱提亮、地平线 AO）、normal（Sobel，按"米 / 像素"物理缩放）、orm（R = 两圈 8 方向地平线 AO，G = 粗糙度，B = 墨线遮罩）。
- 几何体 UV 一律"米"制（按面法线盒投影 / 圆柱展开），贴图 repeat = 1 / 配方米数，全场纹理密度一致、不用展 UV；山石、地面这类无 UV 的体用三向投影（whiteout 法线混合），侧面 v = 世界竖直，层理自然水平。
- 风化分三层叠：贴图层（缝隙积灰、磨损、断纹、地衣、剥落）+ 材质层（世界空间苔 / 雨痕 / 泥溅）+ 几何层（瓦片微乱、缺瓦、石块微倾、瓦松草）。
- 出处：听雨园 `src/materials/baker.js`（MIT © 2026 Wode44398）的两段式思路；本项目重写。

### 13. 三种着色共用一套资产：材质工厂 + 注入
- `look × 模式` 的材质第一次用到时建好缓存，切换只换 `mesh.material`；进场三种模式各真画一帧预热。共享 onBeforeCompile 片段：世界坐标 / 法线、风动、实例 UV 偏移、三向投影、地面配比、风化、接触 AO（顶点属性 aAO）、B 的暗部皴笔（按"出射光 / 固有色亮度"判受光，暗部叠 `TEX.cunfa`）。
- 观感（用户待选）：A 现行 toon 最省、暗部平涂；**B 水墨写意**（法线让 3 阶色阶沿瓦缝 / 石纹断开 = 皴擦感）最像画；C 写实 PBR 过水墨后期后整体偏亮、画意最少。

### 14. 程序化山石：劈理面切割
- 二十面体细分 → 8–11 个随机平面（法线多为水平 + 1 个略斜的顶面）把半径场 `r = min(噪声半径, d / (v·n))` 切成大块面 → 轻微层理台阶 → `toCreasedNormals(32°)`：面与面之间硬棱、面内平滑 = 斧劈皴的块面；三向投影的层理 + 节理贴图提供皴笔"笔路"。比纯 fbm 圆团（像鹅卵石 / 枕头）和满屏 Voronoi 节理（俯视像龟甲）都好。

### 15. 淡彩水墨的取色约束（精细化时最容易跑偏）
- 地面 / 山石要浅：反照率接近宣纸（黄土 0xc4baa2–0xd9d0b9、石 0x9a9d94–0xc6c7ba），暗部靠光照、皴笔和墨线压，不靠固有色；饱和的只留"点色"（朱漆柱、彩画、匾额金字）。第一版地面用写实黄土色 + 草绿，过水墨后期后成了"写实游戏"，被自己打回。
- 草：低饱和浅绿（HSL s 0.16–0.28、l 0.5–0.64），过后期读作墨线草；碎石 / 地衣斑要稀、成团，不然满屏是"砂纸噪点"。


## 2026-11-18 精细化小样 · 主管复盘

### 精致感从哪来（对照听雨园），本项目该借哪部分
- 拆成三个因素看，别归因到显卡：①**投入规模**：听雨园约 10.2 万行 JS 只服务一座静态园林（建模 6.1 万），本项目 src 约 4.1 万行且多数是玩法，原有 blender 脚本约 0.55 万行；②**渲染路线**：PBR + GPU 程序化贴图（高度场 → 法线 / AO / 积灰 / 磨损）+ 一整套屏幕空间后期，本项目是 3 阶 toon + 按材质名替换纯色（`src/game/enemies/enemy.js` PALETTE），模型无贴图；③**题材与镜头**：建筑 / 石 / 植物规则性强、平视近景；本项目是 45° 俯视、约 30 米，主角脸只有十几像素。RTX 5090 只影响运行时与生成耗时，不决定"能不能写出细节"。
- 可借的：几何细节（真瓦、叠压、风化，见 §10–12）和高度场派生贴图——在 toon 管线里同样有效；不借的：PBR 光照与重后期（C 方案过水墨后期后画意最少）。人物不照搬建筑的"雕刻 + 烘焙"，见下一节。
- 出处：参考资料"2026-11-18 精细化小样 · 主管复盘"听雨园条。

### 卡通 / 水墨人物的精细化 = 干净拓扑 + 法线控制，不是雕刻 + 烘焙
- 做法：干净的四边面拓扑（五官处布线跟随结构）→ 脸部法线从一个光滑椭球**传递**（Data Transfer），让 3 阶色阶在脸上只出大块明暗、不出鼻唇沟碎影 → 脸部明暗用**阴影阈值图**（SDF face shadow：按"脸朝向 · 光方向"查表）→ 五官（眉、眼、口）画在笔触贴图上，不靠几何和法线 → 描边只描外轮廓（反向外壳），内线画在贴图里，**不让后期从法线 / 深度突变里找边**。
- 为什么：写实雕刻脸 + 烘焙 AO / 噪点 在 toon 色阶下被放大成皱纹和脏块，后期描边还会把法线贴图突变当成边（林墨 v2 首版的失败，见 坑"主管复盘"节）。
- 剪影优先：游戏镜头下脸只有十几像素，精细化先改剪影（发型、袖摆、腰带、披帛的大形），再谈五官。
- 本项目取值：主角目标 ≤ 8k 三角面、贴图 1024（见 本项目约定）；首领沿用 ≤ 2.5k 约定，超出要报主管。
- 出处：GDC 2015 Motomura《GuiltyGearXrd's Art Style》（顶点法线手调、顶点色阈值、UV 对齐内线、反向外壳）；SDF 脸部阈值图的开源实现（akasaki1211 / ChiliMilk URP_Toon，注明参考原神）。链接见 参考资料.md。

### 精细化方案的代价看面数与显存，不看 GPU 帧时
- 实测（`docs/art/精细化小样_v1/perf_3070.json`，720p，RTX 3070）：现状 0.56 ms / 93 draw call / 6 万面 / 7 MB；精细 A 0.73 ms / 124 / 49 万面 / 25 MB；B 1.27 ms / 124 / 49 万 / 119 MB；C 1.01 ms / 124 / 49 万 / 135 MB。GPU 帧时都远低于 16.7 ms，真正涨的是面数（×8）和贴图显存（×16–18）。
- 判断：评估精细化方案时报"三角面 / 贴图显存 / draw call"三个数，落地靠降细节（LOD、远景去瓦片实例）、贴图降分辨率 / 共用配方、合批；单看 GPU ms 会误判"可以直接上"。

### 美术迭代流程（用户反馈）
- 首版出图先给用户看**头部 + 正面**确认方向，再打磨全身与动作；方向没定前不做全流程（全流程一轮是"构建 → 截图 → 看图 → 改脚本"，主要耗时在这里，不在硬件）。
- 交付前自检必须拦住明显缺陷：五官变形 / 不对称、黑块、碎三角、穿插、破洞；在**游戏镜头**和近景各看一遍，游戏镜头下比现状更脏就不交。

## 精细化小样 v1 · 角色 / 怪物（美术管线 art-char，2026-11-18）

### 距离场（SDF）融合建模 → Surface Nets 高模（适合怪物、衣料、硬表面；人物脸不用，见上节）
- 每个材质组 = 一个连续表面：图元（圆锥胶囊 / 椭球 / 圆角盒 / 椭圆截面放样 / 圆锥链）用多项式 smooth-min `smin(a,b,k) = min(a,b) − h²k/4，h = max(k−|a−b|,0)/k` 融合，`smax` 挖减；每个图元只在自己的包围盒（+k+3 体素）里求值。k 取值：肌肉块 0.05–0.12、毛束 0.012–0.018、五官 0.004–0.01（狼单位 / 米）。
- 位移只在窄带 `|D| < band + 2h` 里加，`band ≥ 2 × 最大位移`，否则窄带边界出假面。
- Surface Nets：每个变号体素放一个点（12 条边的零交点平均），每条变号边连四个体素成四边形；再沿三线性梯度投影 2 次到零面。壳厚至少 3 个体素，否则出非流形 / 破洞。
- 减面前先体素重网格（OpenVDB）成封闭流形，Decimate collapse 才能降到目标面数（不重网格时 Surface Nets 的非流形边会让减面卡在 2–3 倍目标面数、并把局部塌成大平面）。
- 放样 SDF 的段接缝：张开的管子（袖、躯干）逐段最近点 + 截断 t 会在每个接缝出一圈沟 → 中间段向两侧外推半段（半径 / 坐标系线性外推），只有两端封口（`lib_sdf.sd_loft`）。毛束、发束用圆锥链（精确距离）比放样稳。
- 出处：Inigo Quilez《distance functions》《smooth minimum》；0fps《Smooth Voxel Terrain (Part 2)》（Surface Nets）。

### 毛 = 沿毛流场撒的扁毛束（几何），缝 = 墨线
- 基础体粗网格化 → 表面泊松撒点（间距按部位 0.042–0.068 狼单位）→ 每点一束：根埋入皮 0.45r、沿切向毛流伸出、梢部翘起 lift·r、末段下垂 sag、侧弯 curl，截面扁椭圆（厚 0.45 × 宽），梢部半径 0.22r（鬃毛 0.04r 更尖）。毛流场：背向后、侧向后下、腿向下、肘后 / 大腿后飞毛、胸前垂毛、头部短毛，吻部 / 爪 / 小腿不长毛（保持肌肉剪影）。
- 束与束之间的凹缝在曲率图里就是墨线；毛束编号 + 根→梢参数用来上色（梢亮根暗、束间颜色抖动）。青牙约 500 束 + 48 束长鬃，代价是面数（见 坑 #32）。

### 顶点上"画"，再从高模烘到低模（任意数据都能烘）
- 高模顶点上用 numpy 算 AO（Cycles 烘到顶点色）、离散平均曲率、部位遮罩、束编号，由脚本 `paint()` 输出固有色 / 墨 / 粗糙度 / 金属度写成顶点色；高模材质 = 顶点色 → 自发光；低模"选中→活动"烘 EMIT 即得任意数据贴图（与法线一起逐组烘，margin 0，numpy 合成 + 外扩）。
- 曲率按每组 85 分位数归一（与体素尺寸无关）：±1 ≈ 常见起伏，±2.5 以上 = 明显的缝 / 棱；墨线阈值写成 `sstep(1.2, 3.2, −cav)`。
- 不同阶段的子网格（骨甲 / 裂板）烘 AO 时互相隐藏，否则互相遮成黑（`bake_ao_vertex(hide_for=)`）。

### 复用原骨骼与动画：在内存里执行原 build 脚本
- 去掉原脚本末尾的导出调用（或临时替换 `lib_creature.build_creature`）后 `exec`，得到同一副骨架和全部动作，再换网格导出——骨骼名、动画名、命中帧天然一致，原文件不改。
- 新网格蒙皮：顶点按"最近的带 part 标签的建模图元"分部件 → 套原脚本的部件距离权重公式 → 沿网格边平滑 2–6 次（部件融合处不撕裂）→ 每顶点 ≤ 4 骨。

### 卡通人物脸：本项目的落地做法（补充上一节）
- 脸 / 手材质用两阶渐变（`[190, 255]`，暗面只到 75%），配合导出时向椭球靠拢的自定义法线（`soft_normals`，脸前权重 0.75）——正面光下脸基本全亮，没有把脸切两半的硬明暗线；正式的 SDF 阴影阈值图未做。
- 脸 / 手不套反向外壳描边（鼻下、唇缝会穿出黑块），轮廓交给后期深度描边；其余部件描边壳也要随细节变细（主角 0.007、青牙 0.011）。
- 眼、嘴不要留几何开口：去眼球 / 口腔后补洞，再把眼窝、口裂压到前面只留 1–2 mm 浅凹，眼珠 / 瞳孔 / 嘴全画在贴图上（深眼窝会把画上去的瞳孔藏到上眼睑后面）。
