# 美术管线 · 参考资料

## 怪物建模、NPR、敌人特效（敌人模块 D，2026-11-17）
- [Inverse Hull Method（BNPR GitBook）](https://bnpr.gitbook.io/bnpr/outline/inverse-hull-method)：反向外壳描边的标准做法——外扩 + 翻转法线 + 背面剔除；厚度是世界单位，远近粗细会变。本项目的描边壳就是这一套。
- [Chibi Ryu: Realtime Outline & Shading（BlenderNPR）](https://blendernpr.org/chibi-ryu-realtime-outline-shading/)：实时描边 + 卡通着色的完整案例，可以对照描边粗细和色阶数。
- [Cel shading in Blender（geturna）](https://geturna.com/en/guides/cel-shading-blender)：Shader to RGB + ColorRamp Constant 做色阶；游戏里用的是 three.js 的 toon 材质，原理相同。
- [Cel shading（Wikipedia）](https://en.wikipedia.org/wiki/Cel_shading)：卡通着色与描边的来历，以及游戏里"先画放大的黑色背面"这种做法。
- [Red Blob Games: Flow Field Pathfinding](https://www.redblobgames.com/pathfinding/tower-defense/)：一次 BFS / Dijkstra 得到全图距离场，所有敌人共用；敌人寻路（nav.js）沿用这个思路。


## 纯程序建筑 / 环境（精细化小样 v1，2026-11-18）
- 听雨园（Wode44398，MIT，只读克隆 `D:\research_ext\tingyuyuan_src`）：`src/modules/pavilions/roof.js` 用"坡面 facet + 世界空间起翘场 rise(x,z)"建中式屋顶、`tiles.js` 把每片蝴蝶瓦做成带厚度的实例（压七露三、叠压台阶）、`src/materials/baker.js` 两段式 GPU 烘焙（配方高度场 → Sobel 法线 / 地平线 AO / 缝隙积灰 / 边缘磨损）。结论：精致感主要来自"每片瓦是真几何 + 高度场派生的贴图 + 风化"，不是来自 PBR 本身——这几样在 toon 管线里同样有效。
- [Ben Golus · Normal Mapping for a Triplanar Shader](https://bgolus.medium.com/normal-mapping-for-a-triplanar-shader-10bf39dca05a)：whiteout 混合的三向投影法线；山石 / 地面用这套。
- 梁思成《清式营造则例》：举架（越往上越陡）、出翘 / 起翘、歇山收山、斗拱构件名（大斗、瓜拱、万拱、厢拱、翘、昂、升、耍头）——本次屋面曲线与构件命名据此简化。


## 2026-11-18 精细化小样 · 主管复盘
- **听雨园的规模与渲染路线**（[github.com/Wode44398/tingyuyuan](https://github.com/Wode44398/tingyuyuan)，MIT；只读克隆 `D:\research_ext\tingyuyuan_src`，外部不可信数据，只读不运行）：单 HTML、零外部资产，JS 约 10.2 万行（`src/modules` 建模 6.1 万、`src/core` 渲染 3.1 万、`src/materials` 0.5 万，2026-11-18 wc 实数），**只服务一座静态园林**。PBR（clearcoat / sheen / transmission）+ GPU 程序化贴图烘焙（`src/materials/baker.js` 头注释：albedo 含缝隙积灰 / 边缘磨损、高度场 Sobel 法线、ORM 含地平线 AO；配方分辨率 1K–4K，如 `recipes_stone.js` 4096²）+ 屏幕空间与面光源一套后期（`src/core/fx/` 下 contact / gi / camera 等模块，LTC 表见其 README），照片模式用 three-gpu-pathtracer 路径追踪。README："RTX 5090 约 2 分钟"生成整园。结论：精致 = 投入规模 + 渲染路线 + 题材与镜头（建筑 / 石 / 植物规则性强、平视近景），显卡只影响运行与生成耗时。对本项目的取舍见 方法论"精致感从哪来"。
- [GDC Vault · Junya C. Motomura《GuiltyGearXrd's Art Style: The X Factor Between 2D and 3D》（GDC 2015，免费）](https://www.gdcvault.com/play/1022031/GuiltyGearXrd-s-Art-Style-The)；英文讲稿 PDF [ggxrd.com/Motomura_Junya_GuiltyGearXrd.pdf](https://www.ggxrd.com/Motomura_Junya_GuiltyGearXrd.pdf)（封面误写"GDC 2005"）：角色不用法线贴图，靠手调顶点法线控制阴影落点、顶点色控制阴影阈值与描边粗细、内线画在按 UV 对齐的贴图上、外轮廓用反向外壳。是"卡通人物精细化 = 拓扑与法线，而不是雕刻 + 烘焙"的主要出处。
- [Arc System Works · Guilty Gear Toon Line Control Techniques（英文幻灯片）](https://www.docswell.com/s/ASW_Academy/5LVY67-GG-Toonline-Eng)：ArcSys 自 Xrd 起的 3D 格斗都用反向外壳描边；讲硬边与自定义法线对外壳的影响。
- 脸部阴影阈值图（SDF face shadow / Shadow Threshold Map）：米哈游没有官方技术文章，以下为可追溯的开源实现——[akasaki1211/sdf_shadow_threshold_map](https://github.com/akasaki1211/sdf_shadow_threshold_map)（多张"某光角下的明暗图" → 各自求 SDF → 相邻两张按距离插值成一张灰度阈值图，16 bit 输出边缘更顺；算法出处 [ながむしメモ · SDF Based Transition Blending for Shadow Threshold Map](https://nagakagachi.hatenablog.com/entry/2024/03/02/140704)）；[ChiliMilk/URP_Toon](https://github.com/ChiliMilk/URP_Toon) 的 SDF_FaceShadow 模式注明参考原神：运行时用"脸朝向 · 光方向"当阈值采样，要求脸部 UV 左右对称、物体要给出前 / 左方向（左向量决定是否翻转贴图）。
