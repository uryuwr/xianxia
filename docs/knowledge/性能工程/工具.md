# 性能工程 · 工具

全部是项目已有依赖（vite、playwright-core、Playwright 自带 Chromium 1243），无需另装。

## 1. 运行器 tools/run.mjs
`node tools/run.mjs <场景> "<url query>"`，场景在 `tools/scenarios/<名>.mjs`。已屏蔽热更新；`PASS / FAIL` 行计数。
| 环境变量 | 作用 |
|---|---|
| `IGPU=1` | Chromium 加 `--force_low_power_gpu`，在双显卡机器上**用集显渲染**（本机 = Intel UHD 630，常见笔记本 Iris Xe 约快 2–2.5 倍）。Windows 上不带 `=1` 也生效（2026-11 实测；Mac 需要 `=1`） |
| `DPR=1.25` | 页面 `deviceScaleFactor`（模拟系统缩放；必须在建页时给，加载后再用 CDP 改不会改渲染器像素比） |
| `W= H=` | 视口 CSS 尺寸。推荐 `W=1536 H=864 DPR=1.25` = 1080p 屏 125% |
| `HEADED=1` | 有头模式 |
无头 Chromium 帧间隔锁在约 31ms（看不出 60 帧），所以要看 CPU 帧时与 GPU 计时，不看 rAF 间隔。

## 2. 主探针 tools/scenarios/perf_probe.mjs
```
node tools/run.mjs perf_probe "scene=run&region=r1&slot=3"
IGPU=1 DPR=1.25 W=1536 H=864 QUALITY=medium STAGES=open,combat node tools/run.mjs perf_probe "scene=run&region=r2&slot=3"
```
| 变量 | 说明 |
|---|---|
| `STAGES` | `open,veg,combat,night,bag,map,features,switch`（默认除 features） |
| `SEC` | 每段采样秒数（默认 5） |
| `QUALITY` | `high/medium/low`；`orig` = 还原优化前渲染配置（像素比 min(dpr,2) + 原始水墨着色器，读 `work/perf_backup/ink_frag_orig.glsl`） |
| `BENCH=0` | 关掉每段之后的 GPU 背靠背基准 |
| `ABLATE=1`、`ABL_PR=3` | 消融（关阴影 / 阴影更新 / 2048 / 后期拷贝 / 无 MSAA / MSAA2 / RGBA8 / 无草 / 植被不投影 / 无植被 / 像素比 0.75、0.5）；ABL_PR 放大分辨率测逐像素成本 |
| `PROFILE=1` | CDP CPU 采样，按函数自身耗时排行 |
| `CPU=4` | CDP 降速 CPU |
| `TAG / OUT` | 结果 JSON：`work/perf/<region>_<TAG>.json` |
典型输出：
```
STAGE combat: cpu {"p50":3.7,"p95":5.9,"max":15} gpu {...} raf {...} calls 179 tris 497374 alloc 8.25MB/s gcs 1 progs 72 enemies 45
  mods {"render":3.6,"render.shadow":1.2,"enemies":0.98,...}       ← 各模块每帧均值
  worst [{"cpu":10.4,"top":"render=6.0 ..."}]                         ← 最慢 3 帧拆分
  compiles ["78ms:wolf_rig/wolf/wolf_1:MeshToonMaterial"]            ← 当帧新编译的程序（应为空）
  extra {"longTasks":[...],"bench":{"gpu":6.4,...}}
SWITCH cave: {"goMs":323,"maxFrameCpu":103,"longTasks":[...]}
FEAT mirror {...}  /  STAGE feat_corpses_near ...                     ← 新特效开销
```
汇总脚本：`node tools/perf_summary.mjs work/perf/a.json work/perf/b.json`（每段一行）。

## 3. 其他场景
| 场景 | 用途 |
|---|---|
| `perf_tiers` | 同一画面（入口 / 植被最密 / 战斗）orig / 高 / 中 / 低 交替 3 轮，每档背靠背 30 帧 GPU 计时中位数。`IGPU=1 DPR=1.25 W=1536 H=864 TAG=igpu node tools/run.mjs perf_tiers "scene=run&region=r2&slot=3"` → `work/perf/tiers_<r>_<TAG>.json` |
| `perf_parity` | 同一帧：优化 vs 原始水墨着色器逐像素比较 + 同会话 GPU A/B；敌人剔除前后逐像素比较。改后期 / 剔除后必跑 |
| `perf_quality` | 画质档位可运行测试（四档切换生效、设置页、合并写入、自动降档），9 项 |
| `pine_options` / `pine_final` | 迎客松对比与最终截图（美术调整对比的写法范例） |
| `tools/sheet.mjs n1 n2 …` | 把 `work/shots/<n>.png` 两列拼图 → `work/shots/_sheet.png`，标签 = 文件名（可用中文方案名） |

## 4. GPU 计时（EXT_disjoint_timer_query_webgl2）
```js
const ext = gl.getExtension("EXT_disjoint_timer_query_webgl2");
const q = gl.createQuery(); gl.beginQuery(ext.TIME_ELAPSED_EXT, q); /* 渲染 */ gl.endQuery(ext.TIME_ELAPSED_EXT);
// 之后的帧：
if (gl.getQueryParameter(q, gl.QUERY_RESULT_AVAILABLE) && !gl.getParameter(ext.GPU_DISJOINT_EXT)) ms = gl.getQueryParameter(q, gl.QUERY_RESULT) / 1e6;
```
- 同时只能有一个查询处于激活状态（不能嵌套 → 分项成本用消融）。
- CPU 是瓶颈时 ANGLE 的计时会包含等待命令的空隙（≈ CPU 提交时间），独显机上测出来的"GPU"其实是 CPU；要测 GPU 用集显或放大分辨率。
- 没有扩展时退回 `gl.finish()` 前后计时（会阻塞，只在测试里用）。

## 6. 首领战探针与后期参数测试（青牙 v2，2026-11-17）
- **perf_probe `STAGES=boss`**（需 `region=r1`）：`boss_tp`（只进谷，首领不生成）→ `boss_spawn` → `boss_fight1`（入场 + 一阶段，主角对首领放技能）→ `boss_phase2`（转阶段 + 二阶段）→ `BOSSDRAW` 行（暂停后藏首领外观附件 / 狼谷环境，给出常驻 draw call：`look` = 描边壳 + 阵纹 + 眼焰，`env` = 月光斑 + 墨雾门）→ `boss_exec_break` → `boss_exec_final` → `BOSS progs`（整段首领战新建的着色器程序数，应为 0）。`BOSS_SHOTS=1` 处决中截图。
  ```
  IGPU=1 DPR=1.25 W=1536 H=864 QUALITY=medium STAGES=combat,boss TAG=x node tools/run.mjs perf_probe "scene=run&region=r1&slot=8"
  ```
- 每段新增 `rafTop`：帧间隔最长的 3 帧 `{ raf, at（距本段第一帧 ms）, cpu }`。cpu 小、raf 大＝主线程外的等待（GPU 进程里的纹理上传 / ANGLE 着色器生成，**或别的进程在抢同一块显卡**）；`at` 紧跟动作（瞬移、生成、镜头切换）且多次复现才可能是首次绘制，随机出现多半是抢显卡——用 `STAGES=bossfirst` 确认。
- **perf_probe `STAGES=bossfirst`**（单独跑）：确定性的首次绘制成本——暂停主循环、`hold3d`，每个新画面（入口 / 进谷 / 首领生成 / 处决低机位 4 个朝向）先画第一帧再立刻重画 2 帧，`readPixels` 1 像素同步计墙钟，输出 `BOSSFIRST {"valley":{"first","rep","extra"},…,"sumExtra"}`。`extra` ≤ ~15ms 视为噪声。第一个画面（entry）偶尔 450–500ms 是会话里第一次同步读回把排队的工作都等完了，不算。
- **A/B 开关**：`?prewarmBoss=0` 跳过 prewarm 里的首领段（狼谷取景渲染 + 贴图上传），同一机器交替跑 old/new 比较 `boss_tp / boss_exec_break` 的 `rafTop`。
- **perf_boss_ink**（新，7 项）：`node tools/run.mjs perf_boss_ink "scene=run&region=r1&slot=8"`（`QUALITY=high|medium|low` 先切档，截图带档位后缀）。断言：ink 接口存在、参数为 0 时与改动前着色器（`work/perf_backup/ink_frag_pre_boss.glsl`）逐像素一致、留白焦点保留首领、威折处决 desat 0→0.45→0、终结处决 paperFade ≥0.8 且焦点 = 首领 + 主角、结束归零；打印 GPU A/B（改动前 / 参数 0 / 留白 / 去饱和，同会话交替 2 轮中位数）。
- prewarm 日志：`[prewarm] 580ms, programs 78, textures 7, boss qingya moon 2 gates 2`——确认首领段覆盖到了什么。
