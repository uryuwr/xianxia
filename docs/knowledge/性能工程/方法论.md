# 性能工程 · 方法论

> 通用方法 + 本项目取值 + 出处。只对墨途成立的规则见 本项目约定.md。

## 1. 帧预算
- 60 帧 = 16.7ms/帧。CPU（主线程 JS + WebGL 命令提交）与 GPU 并行流水，**帧时 ≈ max(CPU, GPU) + 同步等待**，所以先判断谁是瓶颈再优化。
- 本项目预算（中档、普通集显笔记本）：主循环 JS ≤ 8ms、GPU ≤ 12ms；单个新功能每帧 CPU ≤ 0.3ms、常驻 draw call ≤ 10（同屏峰值 ≤ 30）、大面积透明层 ≤ 1。
- draw call 经验值：three.js 维护者 Don McCurdy 建议 < 100 draw call、< 10 万顶点（[utsubo 100 tips](https://www.utsubo.com/blog/threejs-best-practices-100-tips)）。墨途优化后出行局 80–200（含阴影 pass）。
- 每个投影的平行光 = 再画一遍场景（阴影 pass draw call ≈ 投影物数）。

## 2. 先量化再优化（流程）
1. **分段跑场景**：开阔地 / 植被最密 / 战斗 / 入夜 / 打开界面 / 界面切换，每段取 p50 / p95 / max，不只看平均。
2. **CPU**：包住主循环首尾（`input.update` → `input.endFrame`）算 JS 帧时；各模块 `update` 单独计时；CDP Profiler 按函数自身耗时排行（idle 占比高说明 CPU 不是瓶颈）。
3. **GPU**：`EXT_disjoint_timer_query_webgl2` 包住整帧渲染。低负载时 GPU 会降频，循环内计时偏大 → 用"同一画面背靠背渲染 30 帧取中位数"的**基准**；不同配置对比要**同会话交替多轮**取中位数（集显波动 ±5ms）。
4. **消融（ablation）**：暂停玩法，逐项关掉（阴影 / 阴影更新 / 后期换拷贝 / MSAA / 植被 / 植被投影 / 降分辨率），差值就是该项成本。独显太快测不出逐像素成本时，把像素比拉到 3 让 GPU 成为瓶颈再比。
5. **尖峰归因**：最慢 3 帧的模块拆分 + 当帧新编译的着色器程序（是哪个网格的材质）+ `PerformanceObserver('longtask')`。
6. **每项优化都重测**，留前后数据；无效就回退；画面相关的改动做**逐像素一致性**比较（max diff ≤ 1/255 视为不变）。

## 3. 优化手段的收益排序（墨途实测，集显 UHD 630，1080p@125%）
| 排名 | 手段 | 收益 | 风险 |
|---|---|---|---|
| 1 | 画质档位（分辨率 / MSAA / 阴影尺寸 / 植被密度与投影）+ 自动降档 | 每帧 53→14ms（中）/ 6ms（低） | 画面变化，需用户可选 |
| 2 | 画面外的骨骼角色不画、不推动画（自做剔除替代被关掉的 frustumCulled） | 集显 −19ms，draw call 390→100 | 影子余量要够（半径 3 + 6×体型） |
| 3 | 着色器程序常驻 + 加载时预热 | 消除 60–170ms 编译尖峰 | 加载时间 +0.5s（首局） |
| 4 | 全屏后期里只与屏幕坐标有关的计算预烘焙成贴图 | 集显 −10ms，像素一致 | 精度：影响几何判定的量要用浮点贴图 |
| 5 | 寻路：分桶、扁平队列、加载时预算全图、"能否到达"提前停 | 尖峰 25ms → 4ms | 必须保证结果与原算法一致 |
| 6 | 对象池（特效网格 / DOM 浮字） | 去掉每次 new 材质与几何体 | 池子满了复用最早的 |
| 7 | DOM 只在变化时写、transform 动画 | HUD 每帧 < 0.2ms | — |
| 低 | GC（墨途分配 5–14MB/s，小回收 < 1ms） | 小 | 不值得为此改结构 |

通用规律：**集显上逐像素成本（后期、MSAA、阴影贴图填充）和投影物数量是大头；CPU 上 draw call 数是大头；尖峰几乎都是"第一次"（着色器编译、寻路冷缓存、纹理上传）。**

## 4. 着色器编译（WebGL）
- `getProgramParameter / getProgramInfoLog` 会同步等待编译完成 → 主线程卡顿（[MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)）。
- `KHR_parallel_shader_compile`：先建程序，下一帧轮询 `COMPLETION_STATUS_KHR`，就绪后再首次使用（[Khronos 规范](https://registry.khronos.org/webgl/extensions/KHR_parallel_shader_compile/)）。three.js `renderer.compile()` 同步建程序（并行编译），`program.isReady()` 轮询；`compileAsync` 在 r158+。
- three.js 程序缓存键 = 着色器源码 + 参数（含 **渲染目标的色彩空间**、灯光数量与阴影、蒙皮 / 实例化、`opaque`（即 transparent）、`side`（阴影深度材质的 flipSided）、`customProgramCacheKey`）。**每种变体都要预热**。
- ANGLE(D3D11) 还会按顶点格式 / 输出格式生成 D3D 变体，只有真正画一次才会生成 → 预热要"实际渲染一帧"，不能只 compile。

## 5. 骨骼网格剔除
- three.js SkinnedMesh 的包围球只在第一次用到时按当时姿势算一次，动画走出包围球会被误剔除，所以常见做法是 `frustumCulled = false`（[SkinnedMesh 文档](https://threejs.org/docs/pages/SkinnedMesh.html)、[#11991](https://github.com/mrdoob/three.js/issues/11991)）。代价：全图角色每帧都画、**阴影 pass 也全画**。正确做法：保留 false，但在逻辑层按"位置 + 宽松半径（含影子长度）"对镜头视锥做自己的剔除，并停掉动画推进。

## 6. 阴影
- 阴影成本 ≈ 投影物顶点数 + 阴影贴图填充（尺寸平方）+ 接收面的 PCF 采样。尺寸减半 = 填充 1/4（[shadow map 性能](https://paprika3d.com/docs/guides/threejs-shadow-map-performance)）。
- 小装饰物、透明物、草不投影；静态场景可 `light.shadow.autoUpdate=false` + 需要时 `needsUpdate`（墨途的平行光跟随主角、天时在变，暂不适用）。
- 墨途 4096 时植被投影占 8.5ms（集显），所以低档关植被投影、中档 2048。

## 7. 后期处理
- 全屏 pass 成本 = 像素数 × 每像素 ALU / 采样数。把只依赖 `gl_FragCoord` 的噪声在 resize 时烘成贴图；只在需要的分支里算昂贵函数（如 fbm 只在崖下雾 `low > 0` 时算）；重复采样复用。
- 分辨率：像素比按 `min(devicePixelRatio, 上限) × 档位系数`，Windows 笔记本 125%/150% 缩放很常见，DPR 2 的屏 4 倍像素。

## 8. CPU / DOM / GC
- 热路径不 new（Vector3、数组、闭包、filter/map），用模块级临时变量（[Discover three.js tips](https://discoverthreejs.com/tips-and-tricks/)）。
- DOM：读布局（getBoundingClientRect / offsetWidth / getComputedStyle）会强制重排，不要在写之后读、不要每帧读；值不变不写；动画用 transform / opacity。
- 寻路 BFS：冷缓存（格子、边现算）比热缓存贵 5–10 倍 → 关卡静态就在加载时一次算好；"能不能到"问题不必建整张流场。

## 9. "首次绘制"尖峰不止着色器编译（首领战预热，2026-11-17）
- 第一次画一个物体有三类同步成本：①着色器程序编译 / 链接（three 程序缓存能共享）；②纹理上传（`texImage2D`，主线程，大 Canvas 贴图几十毫秒）；③ANGLE(D3D11) 按程序 + 顶点格式 + 渲染状态生成 HLSL/DXBC（在 GPU 进程，主线程 cpu 看不出来，表现为 rAF 间隔突然几百毫秒）。程序数不变不代表没有首次成本。
- 对策：加载画面里**到目标区域、用会出现的镜头角度真画一帧**（不只 compile），投影灯跟过去（阴影深度变体）；`renderer.initTexture(t)` 预传全部贴图。验证：确定性测"新画面第一帧 vs 立刻重画"的墙钟差（`perf_probe STAGES=bossfirst`，readPixels 1 像素同步——本机 `gl.finish()` 不等 GPU），差值 ≤ 噪声（集显 ~10–15ms）即已覆盖；不要拿单次探针的 rAF 尖峰下结论（共享显卡上别的进程会造成随机长帧）。墨途青牙实测：旧预热已覆盖（程序与狼共用），新预热是"以后改材质也不漏"的保证。


## 10. 美术精细化的代价分布（精细化小样 v1，集显 UHD 630 消融，2026-11-18）
- 满屏的东西最贵：地面换成"法线 + ORM + 三向投影皴笔 + 风化"后单项 7.6 ms → 皴笔改单次俯投影、关掉地面的风化分支后 5.5 ms。**全屏覆盖的材质每多一次采样都按像素数计费**，地面一类的大面积材质只能用最便宜的那一档。
- 阴影 pass 是第二大头（4096 + 全部投影物 6.7 ms）：细碎几何（瓦片、草、碎石）一律不投影，由整体代理（瓦下垫层）投影。
- 实例化几十万三角面在集显上主要是顶点 + 阴影成本：3500 片瓦约 4 ms、1770 丛几何草约 2.5 ms；draw call 不是瓶颈（精细版总共 124 个）。
- 详见 `docs/art/精细化小样_v1/建筑与环境.md` §5–6。
