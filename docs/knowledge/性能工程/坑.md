# 性能工程 · 坑

格式：现象 → 原因 → 规避 → 日期。

## 渲染 / 着色器
1. **战斗里周期性卡 60–170ms（集显），程序数却不涨** → 特效每次 new ShaderMaterial、用完 dispose；最后一个使用者释放后 three 销毁程序，ShaderMaterial 的着色器阶段缓存也删掉，下次换了 id → 缓存键变了 → 重新编译。只给程序加引用计数不够（阶段 id 会变）→ `src/render/perf.js keepPrograms`：每个程序留一个"保活"材质不释放。2026-11-17
2. **预热了还在首次出现时编译** → three 程序缓存键含"当前渲染目标的色彩空间"：在屏幕上 compile 的和画进水墨 RT 的不是同一个程序 → 预热时 `setRenderTarget(ink.rt)`。施法预览叠加层画在屏幕上，单独按屏幕编译。2026-11-17
3. **compile() 后首次使用仍卡** → `getProgramInfoLog` 首次使用时同步等待；ANGLE 还要按顶点格式生成 D3D 变体 → 预热要真正渲染一帧（加载画面盖着）。2026-11-17
4. **敌人第一次倒地 / 留尸时卡** → 改 `material.transparent` 会切 `opaque` 着色器变体 → 预热时每种在场敌人临时切半透明画一次。2026-11-17
5. **加了画面外剔除后，蒙皮的阴影深度变体变成战斗中才编译** → 原来 `frustumCulled=false` 的敌人全图都进阴影 pass，加载时就编译了；剔除后要预热时临时显示。并且预热的 `await` 期间主循环会再次剔除 → 渲染前重新显示，等待期间 `ctx.hold3d=true` 暂停主循环 3D。2026-11-17
6. **`compile()` 漏掉隐藏物体** → 它用 `traverseVisible`；池化的刀光 / 预览网格平时隐藏 → 预热时临时 `visible=true`。2026-11-17
7. **compileAsync 轮询报错 `Cannot read properties of undefined (reading 'isReady')`** → 等待期间材质被 dispose，`currentProgram` 没了 → 自己轮询并容忍 `!pg`，等编译完再 dispose 临时材质。2026-11-17
8. **预热末尾 `gl.finish()` 造成 0.5s 级长帧** → finish 阻塞主线程直到 GPU 做完（集显上首局 ~0.58s）→ 只允许在加载画面里用，帧循环里绝不调用；探针的 finish 退路也会把等待算进帧时（已从 CPU 帧时里扣除）。2026-11-17
9. **全图敌人每帧都画、都进阴影** → 敌人网格和描边壳都 `frustumCulled=false`（防蒙皮包围球过期）→ 逻辑层自己按位置 + 宽松半径做视锥剔除（`EnemyDirector.inView`）。集显 −19ms。2026-11-17

## 美术 / 贴图
10. **迎客松是一团纯黑，调亮材质色无效** → 松针 Canvas 贴图用近黑笔色（#141c19，均值 24/255），颜色 × 贴图仍是黑。排查要点：先看贴图像素均值。2026-11-17
11. **调试时改了材质没反应** → 样张地图（标题背景）里有一份隐藏的同色材质，`traverse` 先找到它 → 用 `traverseVisible` 或按父节点路径过滤。2026-11-17
12. **改一张 Canvas 贴图，草丛也变了样** → `brushTextures()` 里几张贴图共用一个随机数生成器，前一张少用随机数后一张就变 → 改动时补齐原来消耗的随机数个数。2026-11-17
13. **纸纹烘成 8 位贴图后少量像素描边翻转（0.003%）** → 墨线抖动影响采样位置，8 位精度不够 → 影响几何判定的量用 32 位浮点贴图，纯明暗系数用 8 位。2026-11-17

## 测量
14. **独显机上 GPU 计时 ≈ CPU 提交时间，消融结果乱** → CPU 是瓶颈，timer query 包含等待空隙 → 用 `IGPU=1` 集显或 `ABL_PR=3` 放大分辨率。2026-11-17
15. **同一配置两次测 GPU 差 ±5–10ms** → 集显低负载降频、入口随机、敌人随机 → 固定入口（`entries[0]`）、背靠背基准、同会话交替多轮取中位数。2026-11-17
16. **用 CDP 改 deviceScaleFactor 后像素比没变** → 渲染器像素比只在启动时设 → 用 `DPR=` 建页。2026-11-17
17. **消融"关阴影"没效果** → 关卡有自己的平行光，主场景的 `ctx.sun` 进局后被隐藏 → 找当前可见且投影的平行光。2026-11-17
18. **regress 并行跑偶发失败（序章乱序等）** → 两两并行时机器负载高、时序敏感 → 单独重跑确认；其他组正在改的文件可能暂时语法错误（`node --check` 先查，等对方改完）。2026-11-17

## 寻路
19. **战斗中偶发 20–45ms（nav.flow）** → ①新区域冷缓存：格子遍历全部 500 碰撞体、每边 8–11 次采高度；②敌人到不了主角时撤离选点对每个候选点各做一次完整 BFS（最多 27 次）→ 分桶 + 加载时 `prebuild` 全图 + `canReach` 碰到自己就停。2026-11-17

## 透明面片与水墨描边（战斗设计补记，通用规则）
20. **特效面片在画面里是一个带墨线的方框、影子也是方块**（青冥飞剑的剑身灵光）→ 灵光是一块纯色矩形 `PlaneGeometry`（没有贴图，四边不透明），水墨后期按颜色 / 深度差把矩形边缘描成墨线；`traverse` 给整组设了 `castShadow = true`，阴影 pass 不看透明度，投出整块矩形 → 规则：①纯特效面片 `depthWrite = false`、`castShadow = false`、`renderOrder` 放在不透明物体之后；②面片要用四边 alpha 到 0 的贴图（或着色器里按 uv 衰减 / discard），不要用纯色矩形；③用透明贴图做"抠图"形状时加 `alphaTest`（0.3–0.5）；④真需要投影的有形物件用实体网格投影，或配带 alphaTest 的 `customDepthMaterial / customDistanceMaterial`；⑤成组设置 castShadow 时只设实体网格。修复见 `src/fx/skill_fx.js swordMesh`，检查工具 `node tools/run.mjs look_swords "scene=run&region=r1"`（近景截图）。2026-11-17

## 首领战（青牙 v2）预热（性能工程，2026-11-17）
21. **只跑一次探针就把 430ms 帧间隔 / 94ms 渲染帧归因成"首次绘制"（被推翻）** → 首领战基线里进谷有 429ms rAF 间隔、威折处决有一帧 render 92ms + 98ms longtask，当时推测是谷里物体 / 处决低机位远景第一次画（纹理上传 + ANGLE 生成 D3D 着色器）。同条件旧 / 新预热交替复测（`?prewarmBoss=0`）：旧预热 3 次里只有 1 次出现、新预热也偶发 62–234ms；再用确定性测法（`STAGES=bossfirst`：暂停主循环，新画面第一帧 vs 立刻重画，readPixels 同步）测出进谷 / 首领生成 / 处决 4 个朝向的首次绘制额外成本新旧都只有 ≤ ~16ms → 那些长帧是别的进程抢集显。规则：**单次尖峰先用 rafTop 的 `at` 看是否紧跟动作，再用 bossfirst 式"首帧 vs 重画"确认，最后才归因**；`gl.finish()` 在本机不等 GPU（返回 ~2ms），同步计时用 `readPixels` 1 像素。2026-11-17
22. **预热里临时建敌人，`world.add` 的 `spawn` 事件让 shields.js 给它发护盾**（Set 里留引用）→ 建完立刻 `world.remove(entity)` + `shields.drop(entity)`；不挂控制器（`{ ...def, controller: null }`），不进 `E.list`（否则血条、剔除、令牌都会管它）。2026-11-17
23. **并行回归时集显被别的 Playwright 进程占用（本机曾同时 35 个 chrome.exe）**，rAF 间隔出现随机 200ms+ → 性能结论要么单独跑，要么同条件 A/B 交替多轮，看尖峰的 `at` 是否紧跟动作。2026-11-17
24. **改了 UI 走的分支，UI 自己的测试会按旧分支断言**（boss_ui "终结短版"断言 DOM 纸层不透明度，ink.setPaperFade 出现后 UI 改走后期参数）→ 加接口前 grep 调用方与测试里的 `typeof ink.xxx` 分支，两条路都要能过。2026-11-17


## 精细化小样 v1（美术管线补记，2026-11-18）
25. **集显上 EXT_disjoint_timer_query 背靠背计时拿不到结果（GPU_DISJOINT 或一直不 available）** → UHD 630 高负载时常见 → 计时为空就退回"背靠背画 n 帧 + readPixels 1 像素同步"的墙钟（含 CPU 提交，略偏大），并且同一时间只允许一个基准在跑（上一个没完就等，否则并发的基准拿到 null）。见 `tools/art_refine_v1/src/main.js bench()`。2026-11-18
26. **独显（RTX 3070）上的 GPU 毫秒不能代表集显**：同一画面 3070 上 A→B 只多 0.45 ms（1080p×1.5），UHD 630 上多 8 ms → 美术方案的代价一律同时报独显与集显（`perf.mjs igpu`），独显只用来说明"用户自己机器上无压力"。2026-11-18
