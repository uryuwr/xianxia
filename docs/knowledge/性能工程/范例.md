# 性能工程 · 范例（本项目做得好的设计）

## 1. 后期噪声预烘焙（src/render/ink.js）
- **是什么**：水墨后期里只依赖 `gl_FragCoord` 的噪声（色阶分层、墨线抖动、笔锋、飞白、纸纹、暗角）在 `setSize` 时用**同一公式**烘进两张贴图（A 32 位浮点、B 8 位），逐像素只取两次；fbm 只在崖下雾需要时算。
- **为什么好**：集显每帧 39.5 → 29.3ms，`perf_parity` 逐像素最大差 1/255。零画面变化的纯性能收益。
- **适用**：任何全屏 pass 里与世界无关、只与屏幕坐标有关的计算。

## 2. 着色器常驻 + 进局预热（src/render/perf.js、src/render/prewarm.js）
- **是什么**：`keepPrograms` 让每个程序保留一个材质不释放；`prewarm` 在加载画面下把各模块特效摆到镜头前（池化的临时显示、敌人临时切半透明），按水墨 RT 并行编译、等就绪、完整渲染一帧再收走。
- **为什么好**：集显战斗 12 次/5s 长任务 → 0；独显 50ms 编译帧消失。首局加载 +0.55s，之后 20–120ms。
- **适用**：新增特效着色器 → 在 prewarm.js 里加一行构造即可。

## 3. 画质档位 + 自动降档（src/render/quality.js）
- **是什么**：高 / 中 / 低 / 自动；档位 = 像素比上限 × 系数、MSAA、阴影尺寸、可抽稀装饰的密度（固定种子打乱后截断，空间均匀）、植被投影、墨线采样数。自动档按显卡名猜起始档，帧间隔中位数 > 20ms 降一档，只降不升，降到的档记住；自动化测试中不降档。
- **为什么好**：集显 r2 入口 53.6 → 中 14.3 / 低 6.0ms；设置合并写入 `moxian.settings` 不覆盖其他组字段。
- **适用**：新增有显著 GPU 成本的效果，都应挂一个档位开关（`TIERS` 加字段、`sync()` 里应用）。

## 4. 逻辑层视锥剔除（src/game/enemies/index.js updateView/inView、enemy.js animate）
- **是什么**：每帧算一次镜头视锥；角色球心 = 位置 +1m，半径 = 3 + 6×体型（含影子余量），不在视锥里就隐藏根节点、不推进 mixer（时间累计，回到画面一次补上）。尸体同样处理。
- **为什么好**：draw call 390→100；`perf_parity` 证明画面逐像素不变；AI 不依赖动画，玩法不变。
- **适用**：所有 `frustumCulled=false` 的蒙皮角色、留尸、召唤物。

## 5. 寻路预算与提前停（src/game/enemies/nav.js）
- **是什么**：碰撞体按 4 米分桶；加载时 `prebuild(bounds)` 把关卡所有格子与边算好（r2 99ms）；流场只在边变化时作废；`canReach(pos,target)` 碰到 pos 所在格就停。
- **为什么好**：战斗中寻路尖峰 25ms → 4ms，结果与原算法完全一致（同一遍历顺序、同一截断条件）。
- **适用**：任何静态关卡上的网格搜索。

## 6. 他组做得好的（可直接参照）
- **刀光 / 剑气 / 墨痕池化**（src/fx/player_fx.js）：网格常驻、几何按招式缓存、只改 uniform。
- **留尸冻结**（src/game/run/containers.js adopt）：骨骼只算最后一次、`matrixWorldAutoUpdate=false`、`skeleton.update=noop`。
- **搜取窗口**（src/ui/loot_window.js）：进度 CSS 变量 0.5% 限频、尺寸打开时读一次、定位只改 transform。
- **HUD 缓存写入**（src/ui/screens/runhud.js `set/setVar`、src/ui/imbue.js `last`）：值不变不碰 DOM。
- **伤害数字元素池**（src/game/feedback.js）。
- **天机镜底图**（src/ui/screens/mirror_map.js renderBase）：进局时离屏渲染一次，之后 Canvas 0.15 秒重画一次、单次 0.08ms。

## 7. 美术对比的做法（tools/scenarios/pine_options.mjs）
- 运行时临时替换贴图 / 材质 / 后期着色器，同机位截 现状 + 2–3 方案（高、低档各一组），`tools/sheet.mjs` 用中文方案名拼图给用户选，选定后再落地。不改游戏代码就能出对比。

## 8. 演出参数进同一个后期 pass（首领处决留白 / 去饱和，src/render/ink.js，2026-11-17）
- **是什么**：留白 `uFade` + 两个世界空间焦点圆柱（首领、主角，按 `entity.radius/height` 自动定尺寸、只在 fade > 0 时每帧更新位置）、去饱和 `uDesat`，都加在水墨后期原有的 pass 里，`if (u > 0.0)` uniform 分支；不切 `defines`（切了要重编译 / 预热两个变体）。驱动方各管一个：UI（exec_fx.js）推留白曲线，execution.js 推去饱和并在 `finish()` 归零。
- **为什么好**：参数为 0 时与改动前着色器逐像素一致（max diff 0，高 / 中 / 低三档）、集显同会话 A/B 无差别（中档 20.16 / 20.87 / 留白开 20.25 / 去饱和开 19.76ms，噪声内）；0 个新 pass、0 个新 draw call；留白用世界空间圆柱，首领移动 / 镜头环绕时洞跟着走（DOM 纸层的屏幕椭圆洞只在开始算一次）。
- **适用**：任何全屏调色 / 遮罩类演出（受击红边、心魔幻境、入夜冷调）——加 uniform + 分支，不要叠全屏透明 quad。测试写法见 `tools/scenarios/perf_boss_ink.mjs`（改动前着色器存 `work/perf_backup/ink_frag_pre_boss.glsl` 做逐像素对照）。

## 9. 预热里建"纯外观"首领 + 区域取景渲染（src/render/prewarm.js 首领段，2026-11-17）
- **是什么**：首领平时进 40 米才生成，加载时不在场。预热时用真实 `Enemy` 构造（材质与实战完全同参数）但 `{ ...def, controller: null }`、不进 `E.list`、`world.remove` + `shields.drop`；`bossLook` 后把一二阶段部件全部显示、另切一次半透明；关卡环境件（月光斑、墨雾门）临时显示；镜头 + 投影灯移到首领场地按跟随 / 处决机位真画，最后 `dispose`。`?prewarmBoss=0` 可关，便于 A/B。
- **为什么好**：不复制材质构造逻辑（程序键必然一致）、不碰战斗状态；首领战整段新建程序 0、首次绘制额外成本 ≤ 噪声。加载 +约 100–200ms（日志 `arena …ms`）。
- **适用**：碧鳞等后续首领、任何"加载时不在场、出场就要好看"的大件（召唤物、Boss 二形态）。
