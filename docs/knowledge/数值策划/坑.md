# 数值策划 · 坑（踩过的坑、被推翻的假设）

> 格式：现象 → 原因 → 规避办法 · 日期。动手前逐条对照。

## 被实测推翻的假设

1. **"普通怪 2–4 刀，已验证"** → 实测每个境界都是一套三连以内（0.8 秒）。
   - 原因：
     - 目标本身定成了"一套之内"；
     - 敌人每级气血 +27%、等级跟主角层数走，正好抵消主角成长；
     - sim 的 `combat.py` 用的是理想化的有效攻击，没算攻速、顿帧、打断。
   - 规避：TTK 结论必须用 `num_ttk` 实测，不要只信解析公式。· 11-16

2. **"群体是压力来源"** → 不闪避的机器人打 4–5 只一群，掉血 0%。
   - 原因：任何一下普攻都会打断非霸体敌人的蓄力；普攻扇形一次扫中好几只，击退又把怪推开。
   - 规避：评估群战威胁要看"敌人能完整出手几次"，不只看血量和伤害。霸体（`superArmor`）、同时出招数（`maxAttackers`）是更有效的杠杆。· 11-17

3. **"化灵 = 灵值 × 0.5 没问题"** → 化灵再炼化是直接炼化的 10–34 倍（灵蚌珠 35 修为 vs 300 灵石 ≈ 1200 修为）；碧鳞内丹（修为 0）化灵 12000 灵石，可以刷。
   - 原因：
     - 品质倍率（宝 ×10）乘在了"本身品质就写死的物品"上；
     - 化灵对所有类别用同一个比例；
     - 上一轮 sim 根本没建模化灵。
   - 规避：
     - 任何"可以互相转换"的两条资源路径，都要写一条硬不等式（化灵再炼化 ≤ 直接炼化），用脚本遍历全部物品检查；
     - sim 必须建模玩家的套利行为（理性玩家会选收益高的那条路）。· 11-17

4. **"真气预算按掉落减半就够"** → 局内捡到的丹药当局就能用以后，练三仍能放 14 次。
   - 原因：丹药的可用时机变了，供给翻倍。
   - 规避：先问清楚"捡到的东西什么时候能用"，再定掉落率；同时调上限、单颗回复量、掉落率三个杠杆。· 11-17

5. **"开局一刀满势会让精英变快"** → 实测没有变快，有时更慢。
   - 原因：一刀只占精英有效血量的 3–7%；开场先出蓄势斩，推迟了法术爆发。
   - 规避：先用公式估算占比，再用 A/B 实测确认，不要凭直觉加补丁（例如进场清势）。· 11-17

6. **"蓄势斩只占 3–5%"** → 是机器人的 bug（按住左键时右键按不出），修好后实测占 37–70%。
   - 规避：测某个机制的占比之前，先确认机器人真的在用这个机制（数一数事件次数，看是不是 0）。· 11-17

## 工具和测试的坑

- **精英悄悄变成普通怪**：敌人模块的精英规则（每局上限、间距、首领场地）会把被拦下的精英换成同族普通怪，导致测试里"精英 0.05 秒被打死"。
  - 规避：测试刷怪带 `forceElite: true`；结果里打印刷出来的实际类型、气血、tier，一眼就能看出不对。· 11-17

- **机器人卡地形**：主角追怪时走到崖边，之后刷出的怪打不到（0 段 / 20 秒）。
  - 规避：每次刷怪前把主角放回一块事先找好的平地（半径 7.5 米内高差 ≤ 0.35）。
- **单次成群测试波动大**：同配置两次掉血 5% vs 43%。
  - 规避：每种至少跑 2 次取平均，报告里写出每次的值。
- **长时间串跑浏览器会崩溃**（Target crashed）。
  - 规避：区域一、区域二、序章分进程并行跑。
- **别人的系统在测试中途起作用**：流程组的序章步骤引擎（`run.pro`）会对测试里的击杀做反应，导致后续 120 秒全部超时。
  - 规避：测试开始前冻结它（`freezePro()`），并在结果里记下当时的场景和 run 状态，便于排查。
- **硬编码的测试输出**：报告攻速时写成了固定的 1，误以为战斗改动还没落地。
  - 规避：所有显示的数都从运行时读。
- **Python 改文件**：
  - Windows 上用 `io.open` 默认换行，会把 LF 文件写成 CRLF，整文件变成"全改了"；
  - 文件可能是混合换行（别人改过）。
  - 规避：读写用 `newline=''`，替换前检测原换行（`'\r\n' in s`）；改完用 `file` 或 diff 检查。
- **在 `phaseMul` 这类带行尾注释的行后插入新字段**：注释会被挤到新行末尾。
  - 规避：匹配时把行尾注释一起带上。
- **bash 里 heredoc 嵌 node `-e "…"`、文本里带引号**：会报 "unexpected EOF"，而且前面的 python 一行都没执行。
  - 规避：长脚本写成文件再运行（`work/apply_*.py`、`work/check_*.mjs`）。
- **`rollLoot` 的通用解析只解一层**：`GATHER.glow` 指向的 kind 本身也是"按权重抽"时，会掉空（返回 []）。
  - 规避：指向最终的品质档（`xxx_q1`）。
- **改别的组的文件**：委托奇遇组已经先写了 `lingtian`，再追加一个同名条目会被后者覆盖。
  - 规避：改之前 grep 一遍，有就合并到对方的字段里，并在报告里写清楚。

## 设计上的坑

- **"打起来轻松"不等于"不能有压力"**：给标准怪加霸体以后，又要配合闪身冷却改动（1 次充能）复核。否则精英 + 怪群会让练一阵亡率 100%，变成憋屈。
- **按绝对值分档的增益**（例如炼化修为 ≥ 300 给三档），后期永远是最高档。
  - 规避：按"本次 / 本层所需"的比例分档。
- **小境界加成给到 0.5**：突破的属性跳变只剩一半，突破手感变平。用 0.4。

## 构筑与成长 v1（2026-11-18）

- **"按境界排部件"会高估成型**：主管草图把部件挂在"第几层"，但局程里一次回府约升 2 层（第 3 局练三、第 4 局练五、第 5 局练七、第 6 局练九），区域一只有 2–3 局。3–6% 的心法、3–5 页残页在筑基前大多拿不到；"首领首杀给"的件实际到手层 = 首杀那局的**结束层**（青牙要练六后打，带回来已是练八）。
  - 规避：任何节奏判断先跑 `schedule.py` 看"第几局在第几层"，再按局算期望；"每局至少 25% 的概率"才能在筑基前大概率到手。
- **"常见 0.6 / 罕见 0.25"的拍脑袋权重**：真实值是 凝锋诀练八 41%、掌心雷 40%，《流云》《雷引》《回锋》练九 6–12%。夜明宝箱谨慎型几乎为 0（只有贪到入夜的人有），挂在它上面的件对多数人等于没有。
  - 规避：用 `pieces.mjs` 直接调真实 `rollLoot`，并按画像分开看。
- **部件"可用"要同时看栏位**：可用层 = max(拿到那局结束层, 开栏层)。第二心法栏练八、法宝练七（框架 v0.1 改练六）。
- **青牙 v2 有睡眠 / 入场演出 / 场地**：`num_ttk curve=qingya` 刷出的青牙不进战斗，20 秒 0 次普攻、伤害全打在盾上（DPS 30–90，看着像"新配装很弱"）。
  - 规避：首领流程有改动时先看 `basic` 是不是 0、`tries`（它出手次数）是不是 0；流派对比改用 `bcurve=1` 的假人。
- **流派对比时"通用配装"本身就很强**：现状通用（锋锐 + 飞剑）比选了五行 / 身法 / 守御的成型配装还快约 50%。只比较流派之间会漏掉"成型反而变弱"。
  - 规避：流派表里永远带一行"现状通用"作基线。
- **机器人测不到技术件**：完美闪身、止水读招、拂柳 / 凌波都不会触发，身法流被系统性低估（估计约 33%）。报告里要单列"熟练玩家估算"。
- **葫芦吸取按伤害回蓝、没有封顶**：实测练九打单体首领 4.9 真气 / 秒；一群同级小怪一次可回 100–180。任何"按伤害回资源"的件都要有每次封顶。
- **改别人的 heredoc**：bash heredoc 里内嵌很长的中文 Markdown + Python 三引号字符串会报 "unexpected EOF"。规避：长文本先用 Write 写到 `work/` 再用 Python 拼接。
- **加速测试（多步 world.step）时真实时间计时会失真**：主角受击无敌、完美闪身窗口、慢动作、处决演出用 `performance.now()`（真实时间）。8 倍加速时受击无敌 0.4 秒 = 玩法 3.2 秒，"莽"机器人练四打青牙胜率从 0% 变成 92%。
  - 规避：加速时把 `performance.now` 换成只随加速步进走的虚拟时钟，并挡掉主循环自己的步进（`num_qingya_build.mjs` 的做法）；**任何加速方案都先和不加速跑同一格对一次**（莽练四：剩血 82% / 用时 58 秒）。· 11-18
- **Python 默认文本写回会把 LF 换成 CRLF**：`io.open(p,'w')` 不带 `newline=''` 在 Windows 上写出 CRLF，之后按 LF 匹配的补丁全部失败。规避：读写都带 `newline=''`，或用 Node 脚本（`work/_patch_*.cjs`）先 `replace(/\r\n/g, "\n")` 再匹配。· 11-18
