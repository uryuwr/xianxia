# 数值策划 · 工具

> 写给下一位数值策划：装了什么、在哪、怎么跑、输出怎么读。最近更新 2026-11-17。

## 1. Python 环境（模拟、建模、出图）

| 项 | 值 |
|---|---|
| venv 位置 | `docs/review/numeric/.venv`（Windows：`.venv/Scripts/python.exe`） |
| 已装 | numpy 2.5、pandas 3.1、matplotlib 3.11、scipy 1.18、jupyterlab 4.6 |
| 依赖清单 | `docs/review/numeric/sim/requirements.txt` |

安装与重建：

```bash
cd docs/review/numeric
python -m venv .venv
.venv/Scripts/python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r sim/requirements.txt
```

- 中文输出要加 `PYTHONIOENCODING=utf-8`，否则 Windows 控制台会乱码或报错。
- 打开 Jupyter：`.venv/Scripts/jupyter-lab.exe --notebook-dir sim`。只用来探索；结论要回写进 `.py`，保证能复跑。
- 出图的中文字体：`run_all.py` 自动找 `C:/Windows/Fonts/msyh.ttc` 或 `simhei.ttf`。

## 2. 经济 / 进度模拟器（`docs/review/numeric/sim/`）

| 文件 | 作用 |
|---|---|
| `params.py` | 全部参数。见下方参数集列表；标【假设】的字段要尽快用实测回填 |
| `econ.py` | 蒙特卡洛：一次"通关"= 教学局 → 区域一 → 搬迁 → 区域二 → 筑基。每局按画像决定撤离时间、生成战利品、取舍储物袋、算身陨，回洞府后买设施、化灵、重铸、炼化、聚气丹 |
| `combat.py` | TTK、破盾、承伤的解析估算（公式同 `combat.js`）。**只作粗算，以游戏内实测为准** |
| `run_all.py` | 当前 vs 建议，出 c1–c10 图和 `charts/results.json` |
| `tune.py` | 文字版对比 |
| `difficulty.py` | 难度复核：复核前 / 后 + 敏感度（撤离率 −5pt、单局时长 +10%） |
| `economy.py` | 化灵：不化灵 / 现行公式 / 新 HUALING |
| `garden_reforge.py [N] [mp]` | 药园、灵田、重铸、亭子、真气改动后的总账（带 `mp` 参数时只跑后两组） |

`params.py` 里的参数集：
- `CURRENT` / `PROPOSED`：数值评审 v1 的改前 / 改后；
- `REVIEW_BEFORE` / `REVIEW_AFTER`：难度复核；
- `ECON_NO_HL` / `ECON_CURRENT` / `ECON_NEW`：经济复核；
- `ECON_GR`：药园与重铸；
- `ECON_MP`：真气、亭子、灵气充盈；
- 新一轮在上一组上 `copy.deepcopy` 后改，**不要覆盖旧组**，方便对比。

运行（都在 `docs/review/numeric` 下）：

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe sim/run_all.py 2000          # 出图，约 20 秒
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe sim/garden_reforge.py 2000 mp # 最新一组的总账
```

**目标线**：到筑基中位 7–8 局，90% 玩家 ≤ 120 分钟（三种画像：谨慎、贪心、新手）。输出里的"局数 p50 / p90、分钟 p50 / p90"就是对这条线。

**怎么扩展**：
1. 在 `State` 里加计数字段；
2. 在 `Sim.run()` 生成战利品，或在 `Sim.cave()` 回洞府时加一段，用 `P.get("新键")` 判断是否启用，旧参数集不受影响；
3. 写一个对比脚本，输出 json 到 `charts/`。

## 3. 游戏内实测：`tools/scenarios/num_ttk.mjs`

用真实存档状态刷怪，用主角真实的普攻、法术、蓄势斩去打，所有数字都来自运行时（`world.dealDamage`、事件）。

```bash
node tools/run.mjs num_ttk "scene=run&region=tutorial"          # 序章（凡人 + 锈剑，7 组怪连打，读 tutorialLayout.enemyMul）
node tools/run.mjs num_ttk "scene=run&region=r1&only=1"         # 区域一：练一 / 三 / 四 + 青牙
node tools/run.mjs num_ttk "scene=run&region=r2"                # 区域二：练五 / 六 / 七 / 八 + 碧鳞、练九心魔试炼
```

可以叠加的参数：

| 参数 | 作用 |
|---|---|
| `only=1` | 区域一测完不自动切到区域二 |
| `pre=R1-L1,R2-L8` | 只测指定档位（档位在文件顶部的 `PRESETS`） |
| `quick=1` | 跳过 Boss 实战 |
| `elitesOnly=1&trials=3` | 只测精英 / 首领。分"开场 0 势 / 开场满势"两种；输出蓄势斩伤害占比（含打盾）、首领可输出窗口占比，以及有 / 无克制的破盾秒数 |
| `tokens=1`、`armor=wolf,bat` | 运行时覆盖同时出招数 / 霸体，做 A/B 试验，不改文件 |
| `fc=1` | 预测攻速 / 闪身改动（战斗改动落地后已不需要） |
| `xinmoHp=15000` | 试心魔试炼的气血 |
| `tag=xxx` | 输出文件后缀：`work/num_ttk_<region>_<tag>.json` |
| `curve=qingya&levels=2,3,4,5,6,7,9,10&trials=2&timeout=180` | **首领成长曲线**：练二 … 筑基（10 = 筑基）各档。按"正常进度"自动配装备、法术、心法（`curvePreset`），主角**不无敌**，带回春丹 3 枚、开场满势。"莽"和"闪"各打 trials 次，输出胜率、阵亡率、用时、主角掉血、首领剩余血量、打到第几阶段，写到 `work/num_ttk_curve_<boss>.json` |

**输出怎么读**：
- **静态**：每段伤害、"平均几段打死"（按运行时暴击率抽样 2000 次）、每招占主角气血的百分比、法术伤害。
- **实战**："莽"机器人从不闪避；"闪"机器人看到预警 70% 概率在出手前闪开。成群掉血、阵亡率、Q 次数（`qcount`）。

**机器人怎么打**：按住左键追着打；`kit` 模式冷却好就放法术；势成时右键放蓄势斩；序章里会掷金符、吃回春丹。

**测试场地**：入口附近自动找一块半径 7.5 米的平地，每次刷怪前主角回到这里，避免卡在崖上打不到。

跑起来的注意事项：
- 区域一、区域二、序章分三个进程并行跑，各 5–15 分钟；一个进程串跑太久，浏览器可能崩溃（Target crashed）。
- 秒数按游戏内的原始 dt 累计，帧率低也准；顿帧、慢动作都算在内。

**`num_ttk.mjs` 新增（流派配装实测）**：
- `bcurve=1&build=base,jian,fa,bao,shen,shou&levels=6,9&sec=30&els=wood,earth,fire&stimeout=30&tag=x`（`scene=run&region=r2`）：假人 = 区域二狼首，加 `boss` 标签按首领规则结算；**本体**：去盾、气血放大到 60000、主角无敌、开场满势打 `sec` 秒；**破盾**：每种五行给一层护盾（练六 1500 / 练九 2400），本体 1 点，从 0 势开打计秒。输出 `work/num_ttk_build_<tag>.json`，每测完一档就写一次（中途停掉也不丢）。
- 流派配装在 `buildPreset(b, L)`；新数据（新心法、法宝被动、阵法）在页面内 `buildData()` 只改内存。法宝 `artLevel` = 祭炼重数（极品自动扣 bonusLevel）。
- 机器人现在会用法宝 V、阵法 T（聚灵阵布脚下）、真气不够时吃回气丹；结果带真气账 `mp: { spent, gain, casts, denied, pills }`。
- curve 模式也支持 `build=` 和 `bots=masher`（只跑一种机器人，省一半时间）。
- **耗时**：一档（本体 30 秒 + 3 种盾）真实时间约 8–10 分钟（浏览器比游戏时间慢约 5 倍），10 档约 90 分钟——放后台跑，只测关键档（练六 / 练九）。

## 6. 真青牙流派实测：`tools/scenarios/num_qingya_build.mjs`（2026-11-18，05 青牙实测）

基于前任的 `num_qingya.mjs`（真青牙：控制器、石柱、图腾召狼、月光、读条打断、狼威 / 威折 / 处决、二阶段）。新增：
- `build=base,jian,fa,shen,bao,shou&levels=4,5,6,7&sets=bal,orig&bots=masher,dodger,skilled&trials=12`：流派配装（`qyPreset`，00 总纲时间线）× 数值套（`cur` 现行 / `orig` 03 原稿 / `bal` 03 §4.4 平衡后，只改页面内存）；练六另测"无法宝"（`noart=0` 关掉）。
- **同页连打**：每次结束移除青牙、石柱 / 图腾复位（`pl.alive`、碰撞体加回 `ctx.colliders`）、`run.bossSpawned = false`，主角回到 (38, −26) 让关卡重新生成（短版入场）。不用每次重载页面。
- **加速** `turbo=8`：关 3D 渲染 + 每 16 毫秒多推进 8 步；**`performance.now` 换成虚拟时钟、挡掉主循环的步进**（否则受击无敌等真实时间计时全错，见坑）。约 8 倍速：12 次一格 1.5–4 分钟。
- `tweak=exec6,poise130,atk52,hp20000,pots2,fsw60,vaj15`：首领侧 / 部件敏感度（处决比例、狼威阈值、青牙攻击 / 气血、回春丹数、飞剑环身伤害 %、金刚体气血 %）。
- 结果 `work/num_qingya_build_<tag>.json`，**已有的格自动跳过**（可断点续跑）；汇总 `$PY tools/build_growth/qingya_report.py base,jian,...`（Wilson 区间判"在 / 高 / 低 / 疑"）。
- **并行**：`RUN_MAX=0 node tools/run.mjs ...` 不占 `work/.runslots` 测试槽（别的岗位 `RUN_MAX=1` 的回归不会被挡住）；8 核机器上同时开 6–10 个进程可行，每个慢约 30%。批跑脚本例：`work/qy_run.sh <流派>`。
- 杀后台测试进程：MSYS 的 `kill` 杀不掉 Windows 的 node 子进程，用 `taskkill //PID <pid> //T //F`（PID 见 `work/.runslots/*.lock` 或 `wmic process where "commandline like '%num_qingya_build%'" get processid`）。
