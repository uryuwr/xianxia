# 数值策划 · 范例（本项目里做得好、可以沿用的设计）

> 格式：设计 → 为什么好（数据或用户反馈）→ 位置 → 适用场景。

1. **"数据表等级写高"控制缩放斜率**
   - 做法：区域二精英按 9 级写（藤妖 4250 / 狼首 3750），在练五时分别是 1700 / 1500，练八时 3600 / 3190。
   - 为什么好：全局的每级缩放（+15%）不用改，单类怪的成长就能跟上主角在区域二的输出跃升（剑修遗府以后寒冰锥、飞剑）。精英在练八从 1.5 秒拉回 9–10 秒。
   - 位置：`src/data/enemies.js` 的 `vine_elite`、`wolf_elite_r2`。
   - 适用：某类怪需要比全局更陡或更缓的成长时。

2. **不改逻辑，用现有的"通用分发"做按权重的品质掉落**
   - 做法：`GATHER.xxx = { r1: [["xxx_q1", 70], ["xxx_q2", 25], ...] }`，每个 `_qN` 是固定品质的条目；灵草按 `GARDEN` 的表在 `loot.js` 末尾自动生成（`buildHerbGather`）。
   - 为什么好：零逻辑改动就实现了"品种 + 品质分布"；表由数据驱动，改一个权重全局生效。
   - 位置：`src/data/loot.js`。
   - 适用：任何"先抽档再给物品"的需求。

3. **用 `lootSource` 分层掉落**
   - 做法：低阶怪 `mob_low`、异种 `rare_variant`。
   - 为什么好：敌人模块只要填一个字段，掉落就分层了，不用改 `rollLoot`。
   - 位置：`src/data/loot.js` 的 SOURCES、`enemies.js` 的 `def.lootSource`。

4. **转换类资源的硬约束 + 遍历检查**
   - 做法：`HUALING.stones` 对有 xp 的物品按 xp 定价，再用脚本遍历 `ITEMS`，检查"化灵 × 4 ≤ 直接炼化"。
   - 为什么好：彻底堵死套利，而且以后加新物品时脚本能自动发现违反。
   - 位置：`src/data/recipes.js` 的 `HUALING`；检查脚本见经济复核的报告。

5. **机器人画像双轨实测**
   - 做法：同一组怪分别让"莽"（从不闪避，代表最差的新手）和"闪"（70% 预警会闪，代表一般玩家）各打 2 次。
   - 为什么好：一个量就能说清"会不会憋屈"（莽的阵亡率）和"有没有压力"（闪的掉血）。
   - 位置：`tools/scenarios/num_ttk.mjs` 的 `fight({ bot })`。

6. **sim 参数集链式继承**
   - 做法：`REVIEW_AFTER → ECON_NEW → ECON_GR → ECON_MP`，每轮 `deepcopy` 上一组再改，旧组保留。
   - 为什么好：每次改动都能做"改前 / 改后"对比，而且能看出是哪一轮让结果偏离了目标线。
   - 位置：`docs/review/numeric/sim/params.py`。

7. **序章倍率放在关卡数据里，而不是改怪物数值**
   - 做法：`tutorialLayout.enemyMul = { mob: { hp, dmg }, elite: { hp, dmg } }`，流程组刷怪后施加（气血走 `more` 修正、护盾同乘、伤害走 `dmg` 乘区）。
   - 为什么好：同一种狼在序章和区域一可以有两套强度，正式局的平衡不受影响。

8. **增益按比例分档**
   - 做法：灵气充盈的档位 = 本次炼化修为 ÷ 本层所需修为（10% / 25% / 45% / 70% / 100%）。
   - 为什么好：区域一、区域二的含义一致，后期不会永远是最高档。
   - 位置：`recipes.js` 的 `REFINE.buff`。

9. **用真实 `rollLoot` 做部件蒙特卡洛，方案只改内存**
   - 做法：`tools/build_growth/pieces.mjs` 在 Node 里 import `src/game/loot.js`，按关卡实测的每局接触数逐个来源掷真实掉落表；方案（补掉率、选择点、偏置）用 `structuredClone` 备份 `SOURCES / BOSSES / RUINS` 后在内存里改，跑完 `resetTables()`。
   - 为什么好：掉落表一改结论就跟着变，不会和代码脱节；方案对比不用碰 `src/`；1000 次 × 3 画像 × 8 方案几秒跑完。
   - 适用：任何"某件东西第几局能拿到"的问题。
10. **流派测试分"本体 DPS + 各五行破盾"两段，用假人而不是真首领**
   - 做法：`num_ttk bcurve=1`：假人加 `boss` 标签按首领规则结算，去盾放大气血测本体；再每种五行给一层首领每段的盾量、本体 1 点测破盾秒数；最后按首领的气血 / 防 / 护盾序列换算用时。
   - 为什么好：不受首领 AI 流程（睡眠、演出、场地、潜水）干扰；同一组数据能换算到任意首领；一眼看出"差距在本体还是在破盾"。
   - 位置：`tools/scenarios/num_ttk.mjs` 的 `buildCurve`、`tools/build_growth/balance.py`。
11. **真首领的同页连打 + 虚拟时钟加速**
   - 做法：`num_qingya_build.mjs` 每次试验后在页面内复位首领与场地（石柱、图腾、碰撞体、`run.bossSpawned`），不重载页面；加速时关渲染、多推步，并把 `performance.now` 换成随玩法时间走的虚拟时钟、挡掉主循环步进。
   - 为什么好：一格 12 次从约 15 分钟降到 1.5–4 分钟，6–10 个进程并行，一下午能跑完 200+ 格（约 2500 场真首领战）；和不加速对过同一格，结果一致。
   - 适用：任何需要大样本的真首领 / 精英战实测。
