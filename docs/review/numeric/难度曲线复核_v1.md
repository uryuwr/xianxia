## 0. 结论先行

**开局小怪确实太简单，曲线也不正常。** 问题不只是开局，而是整条曲线都平：

1. **每一层的普通怪都是"一套三连就死"**：
   - 练气一层，竹林狼 3 段、0.8 秒；
   - 练气三层，2 段；
   - 区域二首探（练气五层），蝠妖也只要 3 段；
   - 练气八层，还是 1 套以内。
   原因有两个：上一轮评审定的目标本身就是"一套三连之内"；而敌人等级跟着主角层数走（气血每级 +27%），把主角的成长抵消掉了。结果是"变强"的反馈几乎只在装备上。
2. **群体也没有威胁**：一个从不闪避、只按住左键的机器人，打 4–5 只一群的普通怪，掉血 0%。
   - 原因：三连的扇形一次扫中好几只，任何一下都打断它们的蓄力；怪在出手前就被打死或打退了。
   - "压力来自群体"在实际游戏里并不存在，精英是唯一的威胁。
3. **剑气斩（Q）和精英是两个极端**：
   - Q 打单只狼 208 伤害，是狼气血的 347%；三道剑气呈扇形穿透，一下清一片。
   - 同一个 Q 在 6 米外打精英，只有中间一道能命中（两侧剑气偏出 ±1.9 米），护盾没克制时就要磨很久。用户说的"Q 清屏、精英打很久"正是这个原因。
4. **击杀不回血之后**，前期也没有因此变难，因为根本不挨打。
5. **两头偏离**：
   - 序章狼头目对凡人太凶：不闪避的机器人带 2 枚回春丹仍然阵亡。
   - 心魔试炼（洞府 `XinmoTrial`，3000 气血）在练气九层 4 秒就打完了。

**改完以后**（实测）：
- **开局**：序章的狼 3 段一套仍然打死，主角依旧强。
- **区域一第 2 局（练气一层）**：普通狼要 1.85 套（约 5.6 段，2.7 秒），灰狼 1.2 套，石傀 2.9 套；到练气四层降到 1.24 套。区域内能感觉到自己在变强。
- **区域二首探**：蝠妖 1.9 套，藤妖 2.4 套；到练气八层降到 1.67 / 2.1 套。
- **群体**：同一时间只有 1 只出招，标准狼、蝠妖、藤妖出招不再被打断。
  - 一群普通怪：不闪避掉血 6–25%，会闪避掉 2–11%。
  - 精英带怪：不闪避 22–93%，会闪避 13–85%。
  - 这符合"单只更难、群殴更弱"。前期有压力，但只按住左键不会被一群怪秒掉。
- **Q 与精英拉平**：
  - Q 不再一次清屏：一组小怪练气一 / 三层要 4 次，五层 3 次，七层 2 次。
  - 有克制时，精英 8–10 次。
  - 精英实战 7–16 秒，青牙 24 秒，碧鳞 61 秒（都是主角无敌、理想机器人的下限）。
- **不魂系**：
  - 普通怪一下打掉 4–9% 气血，扛 14–24 下；精英一下 8–16%；Boss 重击 13–16%。
  - 闪避机器人在普通群里几乎不掉血。
- **进度**：到筑基局数中位 7–8 局不变。
  - 分钟中位：谨慎 / 贪心 / 新手 = 91 / 94 / 99。
  - p90：102 / 121 / 119。贪心型正好卡在 120 分钟的边上（见 §6）。

## 1. 实测方法（`tools/scenarios/num_ttk.mjs`）

```bash
node tools/run.mjs num_ttk "scene=run&region=tutorial"      # 序章：凡人 + 锈剑，按序章 v2 的 7 组怪连续打
node tools/run.mjs num_ttk "scene=run&region=r1&only=1"     # 区域一：练气一 / 三 / 四层 + 青牙
node tools/run.mjs num_ttk "scene=run&region=r2"            # 区域二：练气五 / 六 / 七 / 八层 + 碧鳞、九层心魔试炼
# 不带 only=1 时，区域一测完会自动切到区域二。其他可选参数：
#   quick=1    跳过 Boss 实战
#   pre=R1-L1  只测某个存档档位
#   tokens=N   / armor=类型    试验用：运行时覆盖同时出招数 / 霸体（不改文件）
#   xinmoHp=N  心魔试炼气血
# 出现 "FAIL " 开头的行时返回 1。目标区间在文件头的 TARGET 里。
```

- **存档档位**：境界、装备、法术、心法、法宝都在 `PRESETS` 里。
  - 装备只带底材按等级、品质算出的属性，不带随机词条，属于偏保守的估计。
  - 攻速和闪身充能读游戏里的成长表（战斗开发已落地）。
- **静态测量**：
  - 主角每段普攻用 `world.dealDamage` 打一只冻结的敌人（不暴击），再按运行时的暴击率 / 暴伤抽样 2000 次，得到"平均几段"。
  - 敌人每个招式各打主角一下，得到"每下占气血多少"。
  - 法术真实施放，统计窗口内造成的伤害（含暴击，单次取样）。
- **实战机器人**：按住左键追着打，第 4 段蓄势斩、法宝自动攻击照常生效。
  - **单怪**：主角无敌，只用普攻。
  - **精英 / Boss**：普攻 + 法术，冷却好了就放。
  - **成群**：主角不无敌，两种机器人各打 2 次取平均。
    - "莽"：从不闪避。
    - "闪"：看到 7 米内的预警，70% 概率在出手前闪开。这个机器人很粗糙，闪完还要走回来，比真人笨。
- **序章**：读 `tutorialLayout.enemyMul` 施加倍率。7 组怪连续打，组间按走路 25 秒回血。开箱后才有回春丹 ×2（气血 < 35% 时吃）和金符 ×3（精英有盾时掷）。莽机器人跑 3 次，闪机器人跑 2 次。
- **Q 次数**：只放剑气斩、冷却清零，两次之间清掉破甲和破盾易伤，模拟 8 秒冷却；数到目标死为止。
- 测试时把流程组新写的序章步骤引擎（`run.pro`）冻住，避免它对测试里的击杀做出反应。

## 3. 对照：设计目标与同类游戏

**设计文档**（v0.3 与 §10）的诉求是：
- 主角强而流畅，但不魂系；
- 要有逐渐变强的正反馈；
- 小怪是"爽"的部分；
- 压力来自群体、精英、五行盾、天时和撤离。

改前的问题是，"爽"做成了"零阻力"，"压力"全压在精英身上。§10.6 自己写的是"新区域 3–4 下、区域末 2 下"，但实际做出来是全程一套，因为等级缩放把成长抵消了。

### 4.4 `src/data/levels/tutorial.js`：序章敌人倍率（流程组照这个读）

字段：`tutorialLayout.enemyMul = { mob: { hp: 0.5, dmg: 0.8 }, elite: { hp: 0.6, dmg: 0.9 } }`

- **作用范围**：只作用于序章刷出的敌人。`mob` 是普通怪；`elite` 是 tags 含 `elite` 的敌人。
- **施加时机**：刷怪后、敌人出手前，按下面三步施加（`num_ttk.mjs` 的 `applyMul` 就是这样实现的，可以直接照抄）：

```js
const m = e.entity.tags.has("elite") ? mul.elite || mul.mob : mul.mob;
// 1. 气血：气血上限 ×hp，当前气血补满
e.entity.stats.add({ stat: "hp", type: "more", value: m.hp - 1, source: "levelMul" });
e.entity.hp = e.entity.stats.get("hp");
// 2. 护盾：已有护盾的 hp 与 max 同乘 hp（护盾在 Enemy 构造时按原气血生成）
if (e.entity.shield) (e.entity.shield.hp = Math.round(e.entity.shield.hp * m.hp)), (e.entity.shield.max = Math.round(e.entity.shield.max * m.hp));
// 3. 伤害：它造成的每一下 ×dmg（core/combat.js 的"总伤害"乘区）
e.entity.stats.add({ stat: "dmg", type: "flat", value: m.dmg - 1, source: "levelMul" });
```

- ⚠ 流程组的 `src/game/run/prologue.js` 现在读的是占位字段 `tutorialLayout.hpMul`，请改读 `enemyMul`。

## 8. 词条池稀释（法剑 5 → 8 条，玉佩 8 → 11 条，法衣 5 → 6 条）

`rollAffixes` 是从池子里等概率不放回抽取，`AFFIXES` 没有权重字段。某一条老词条出现在装备上的概率：

| 栏位 | 灵品（1 条）| 宝品（2 条）| 仙品（3 条）|
|---|---|---|---|
| 法剑（如 +攻击、附灵） | 20% → 13% | 40% → 25% | 60% → 38% |
| 玉佩 | 13% → 9% | 25% → 18% | 38% → 27% |
| 法衣 | 20% → 17% | 40% → 33% | 60% → 50% |

**结论：不调权重。** 理由：
- **期望收益基本不变**：以练三的宝品法剑为例，+攻击 6 约等于 +16% 普攻 DPS；新词条攻速 +6% 约等于 +6%，蓄势斩伤害 +16% 约等于 +4%，气势获取约 +2–3%。随机一条法剑词条的期望 DPS 收益：老池 (16 + 暴击约 3)/5 ≈ 3.8%，新池 (16 + 3 + 6 + 2.5 + 4)/8 ≈ 3.9%。
- **方差变大**："抽中 +攻击"变少了，但这正是普攻流构筑想要的分叉。
- **受影响的是"附灵"**（破盾手段）：仙品法剑上出现的概率从 60% 降到 38%。不过碧鳞有五行坛临时附灵，蓄势斩对护盾 ×2.5 也补了破盾。
- 如果之后试玩觉得 +攻击太难出，需要在 `AFFIXES` 加 `weight` 字段，并让 `rollAffixes` 按权重抽（逻辑改动，归掉落模块）。建议权重：攻击 1.5、附灵 1.3，其余 1。

## 附录 A · 势成不流失 / 右键蓄势斩（战斗 v1.1）对精英与首领的影响（2026-11-17）

**改动**（战斗开发已落地，见 `docs/战斗_气势与身法_v1.md` §6）：
- 蓄势斩改为右键主动释放，气势 ≥ 50 时可放，伤害按比例缩放（50 时 ×0.58，满势 ×1.0）；
- 满势（势成）不再流失，受击也不扣；
- 未满时停手 5 秒后每秒 −8，受击 −6；
- 《满势》攻速加成 +20% → +15%。

**担心的问题**："先在小怪身上攒满，再进精英战"会成为常规打法，精英开场就多吃一刀满势蓄势斩。

**实测**：`num_ttk ... &elitesOnly=1`，每档 3 次，主角无敌，普攻 + 法术 + 势成时右键蓄势斩。对比"开场 0 势"和"开场满势"两种条件。机器人现在会在势成时右键（`fight({ charge, preMom })`）。

| 档位 | 敌人 | 开场 0 势（秒） | 开场满势（秒） | 开场那一刀的伤害（含打护盾） |
|---|---|---|---|---|
| 练一 | 狼头目 825 + 248 木盾 | 14.0 | 20.0 | 160–210 |
| 练三 | 狼头目 1275 + 383 | 14.8 | 18.3 | 60–250 |
| 练四 | 狼头目 1500 + 450 | 9.7 | 18.4（6.7–24.6） | 70–90 |
| 练四 | 青牙 3000 + 2 × 450 | 31.4 | 37.1 | 150–420（整场 2–3 刀） |
| 练五 | 区域二狼头目 1500 + 450 / 千年藤妖 1700 + 510 | 18.4 / 15.1 | 19.1 / 13.8 | 80–290 |
| 练六 | 同上（2063 / 2338） | 16.4 / 17.6 | 18.5 / 20.1 | 100–350 |
| 练八 | 同上（3188 / 3613） | 10.2 / 6.1 | 14.8 / 16.0 | 130–490 |
| 练八 | 碧鳞 12000 + 3 × 2400 | 72.2 | 68.5 | 整场 3–5 刀，375–1058 |

### 读法

1. **开场那一刀没有让精英和首领变快**：除碧鳞快了约 4 秒（5%）以外，各档都持平或变慢。
   - 变慢的原因在机器人：开场先放蓄势斩（约 1 秒的出招，带击退），推迟了法术的开场爆发（寒冰锥 / 剑气斩破盾）。真人至少不会因为这一刀变慢。
   - 我单独检查过：放完蓄势斩后，慢动作和主角状态都按时恢复，不是引擎问题。
2. **估算一刀满势蓄势斩占多少**（运行时属性代入战斗公式）：
   - 伤害 = 横扫 2.4 + 剑气 1.4 = 3.8 × 攻击 × 防御减免。
   - 打护盾 = (2.4 × 0.25 × 2.5 + 1.4 × 0.25 × 1.5) ≈ 2.0 × 攻击 × 防御减免，约为同级精英护盾的 13–16%。
   - 合计约占精英总有效血量（本体 + 护盾按普攻折算）的 3–7%，约 1 秒；占青牙约 4%，约 1.3 秒；占碧鳞不到 3%。
   - 都在单场战斗的随机波动（±5 秒）之内。
3. 势成保留的上限就是一刀：放出后要重新攒，而攒满需要约 3 套连招。所以"攒满再进场"的收益是固定的一刀，不会随战斗变长而增大。

### 结论：数值不需要调整

- 精英护盾对蓄势斩的倍率、精英血量都不改；也**不需要**进入首领场地时清空势成。
- 开场一刀属于"会玩的人的小奖励"，符合"不憋屈、不无脑"。

### 顺带发现（转给战斗开发，不属于数值改动）

- 机器人按"势成就右键"的打法，整场蓄势斩只占碧鳞战伤害的 3–5%（3–5 刀），精英战里只有 0–2 刀。
- 想让蓄势斩成为"主要输出之一"，瓶颈是攒势速度：精英战主要在打护盾，主角无敌时也没有完美闪身的 +25。要加强它，可以：
  - 对精英 / 护盾的命中给额外气势；
  - 或者让势 ≥ 50 时放出的部分蓄势斩也能占更高的输出比例。
- 这两种加强都会改变上面的结论，改完请再跑一次 `num_ttk ... &elitesOnly=1`。

工具：`tools/scenarios/num_ttk.mjs` 新增 `elitesOnly=1`（只测精英 / 首领，两种开场各 `trials` 次）；`fight()` 新增 `charge`（势成时右键）、`preMom`（开场满势）。原始数据：`work/num_ttk_r1_mom.json`、`work/num_ttk_r2_mom.json`。

1. **右键 bug**：战斗开发修复了 num_ttk 机器人"按住左键连段时永远按不出右键"的 bug，现在走右键缓存，刀数按 `player:charge` 事件计数。附录 A 里"精英战 0–2 刀、碧鳞占 3–5%"主要是这个 bug 造成的，**附录 A 的结论作废**。
2. **精英变普通狼**：敌人模块新加的精英规则（每局上限、间距、首领场地）会把测试里反复刷的精英**悄悄换成普通狼**（`E.spawn("wolf_elite")` 返回 140 血的 std 狼）。num_ttk 现在刷怪时带 `forceElite: true`。在这之前跑出的"精英 0.05 秒被打死"不是真数据。

### 处理

- **先回调蓄势斩，再动血量**：如果先加血，等蓄势斩回调以后又会太肉。建议的数（`src/data/player.js` 的 CHARGE / MOMENTUM，归战斗开发）：
  - 精英 / 首领攒势 ×1.25 → **×0.8**；
  - 破盾 +15 → **+5**；
  - 横扫 75 + 3.45 × 攻击 → **30 + 2.6 × 攻击**；
  - 剑气 40 + 1.88 × 攻击 → **15 + 1.2 × 攻击**。
  - 估算：蓄势斩的伤害贡献约 ×0.4，首领占比约 22%，精英约 30–35%（开场满势的一刀在短战斗里仍然占比偏高）。
- **青牙**：和战斗主策一起重做，见附录 C（交付后补）。建议总有效血量约 17000（气血 15000 + 每段护盾 0.1）。数据要等他的机制（失衡、处决、背击）和蓄势斩回调落地后再定。
- **碧鳞和精英的血量**：蓄势斩回调后复测，再决定要不要改。

### B.1 首领输出窗口（敌人模块 RHYTHM 交付后，2026-11-17）

- **口径**：首领不在预警、出招中，没有潜水，**并且在近战距离内**（受击半径 + 2.5 米）的时间占比。主角无敌，普攻 + 法术 + 蓄势斩，各 2 次。
- **青牙（练四）**：58–80%（不论远近 66–84%）。
- **碧鳞（练八）**：66–70%。
- 目标 45–55%，**偏高**。主要来自主角这边的控制：蓄势斩每 3–5 秒一次硬直、破盾眩晕、寒冰锥冻结。
- **先等蓄势斩降频**（战斗主策已定：精英 / 首领攒势 ×0.8、破盾 +5，单刀伤害不动），之后复测。
- 降频后仍高于 55% 时，请敌人模块调：首领喘息 2.25 → 1.5 秒、首领招式冷却 ×0.85；大招后摇 1.4 秒和落空踉跄 0.5 秒保留（这是用户要的可读惩罚窗口）。
