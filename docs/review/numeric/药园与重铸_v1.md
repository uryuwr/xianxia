## 1. 药园 v2（`GARDEN`、`FACILITIES.garden`）

### 1.1 成熟所需出行次数（不施灵土；施了再 ÷1.5，向上取整）

| 种子（`runs`） | 药园等级 | 凡（十年） | 灵（五十年） | 宝（百年） | 仙（三百年） | 极（千年） |
|---|---|---|---|---|---|---|
| 青灵草 / 凝露花 / 寒露草（1） | 0 | 1 | 2 | 3 | 4 | 7 |
| | 1 | 1 | 2 | 2 | 4 | 6 |
| | 2 | 1 | 1 | 2 | 3 | 5 |
| | 3 | 1 | 1 | 2 | 2 | 4 |
| 紫藤 / 赤炎果（2） | 0 | 2 | 3 | 5 | 8 | 14 |
| | 1 | 2 | 3 | 4 | 7 | 12 |
| | 2 | 2 | 2 | 4 | 5 | 9 |
| | 3 | 1 | 2 | 3 | 4 | 7 |

设计意图：
- 一周目（约 8 局）里，十年 / 五十年种子是常态，百年偶尔有。
- 三百年要药园 2–3 级再施灵土才能在一周目内收获。
- 千年属于筑基以后的长线目标。
- 药园升级和施灵土是仅有的两种提速手段。

### 1.2 采集与种子（`loot.js` 由 `GARDEN` 生成）

关卡里的采集点不用改，现有 `qingling / ninglu / hanlu / ziteng / chiyan` 照用：
- `GATHER.<草>` 变成"按区域抽品级档"；
- `GATHER.<草>_q<品级>` 是该品级的灵草，加上各品级的种子。种子独立判定，品级 y 的概率 = `seedDrop[草品级] × seedRarity[草品级][y] / Σ`。
- `GATHER.herb`（关卡没标物种的采集点）和 `GATHER.lingtian` 直接指向品级档，因为 `rollLoot` 的通用解析只解一层。

实测（每项 5000 次 `rollLoot`）：

| 来源 | 灵草品级分布 | 每次掉种子 | 种子品级分布 |
|---|---|---|---|
| 区域一 青灵草 | 凡 75 / 灵 20 / 宝 5 | 0.23 | 凡 70 / 灵 23 / 宝 6.5 / 仙 0.4 |
| 区域二 寒露草 | 凡 60 / 灵 28 / 宝 10 / 仙 2 | 0.26 | 凡 62 / 灵 27 / 宝 9 / 仙 1.4 / 极 0.1 |
| 灵田 区域一 | 灵 76 / 宝 19 / 仙 5 | 0.48 | 凡 40 / 灵 40 / 宝 16 / 仙 3.6 / 极 0.2 |
| 灵田 区域二 | 灵 58 / 宝 29 / 仙 11 / 极 2 | 0.51 | 凡 33 / 灵 38 / 宝 22 / 仙 6 / 极 0.9 |

- **天时 / 灵潮提高品质**：数据里给了 `GARDEN.herbTideShift = { dusk: 0.15, night: 0.3 }`，含义是暮 / 夜采集时有这个概率再升一档。需要掉落模块把天时传给 `rollLoot`，属于逻辑改动；在接线之前不生效。

### 1.3 灵土的定位

- **用途**：
  - 药园扩建：3 + 6 + 10 = 19 份；
  - 高品级种子施肥：每颗 1–4 份；
  - 原有的土符、24 格储物袋、土附灵。
- **来源**：
  - 区域一常见材料池（原有）；
  - **新增采集点**：区域一、区域二各 5 个候选、每局 2 处，每处 1–2 份，掉落表沿用原有的 `GATHER.lingtu`。
  - 10 个点都已用 `num_glows` 校验：可站、不在碰撞体里、可达。区域一分布在溪畔、东坡、山神庙、瀑下、松岭；区域二在竹海南、溪谷、东台、竹海深处。
  - 一周目大约能拿到 25–30 份，够扩建到 3 级，再给几颗高品级种子施肥。

### 1.4 给洞府组的约定

- `GARDEN_PLOTS = GARDEN.plots`（现有代码已经这样读）。`facLevel(garden) = 0` 时也要显示 1 块地并允许种植，`FACILITIES.garden.start` 是 0。
- `plant`：把种子实例的 `rarity` 记进地块。`runs` 改为按 1.1 节的公式计算（需要读 `GARDEN.yearRuns / growth / fertilize`）。施灵土作为种下时的可选项。
- `harvest`：给出的灵草带 `rarity`（按 `harvestQuality`）；`harvestSeed` 的概率再给一颗同品级种子。
- 界面上种子名写成"百年青灵草苗（宝品）"，用 `GARDEN.years[rarity]`。
- 炼丹：火候带宽 × `HEAT.herbBand[投入灵草中的最高品级]`。
- ⚠ 现在的炼器 `consumeInputs` 按"仓库里同种材料的最高品级"决定装备品级。高品级灵草会因此把炼出的法衣、玉佩直接抬到宝品 / 仙品，变成刷装备的路子。**建议炼器只看主材料（第一项），灵草不参与。**

## 2. 炼器鼎·重铸（`REFORGE`）

```js
REFORGE = {
  forge: 1, forgeTop: 2,                       // 炼器鼎 1 级可用；极品要 2 级
  stones: [null, 30, 80, 200, 500],            // 凡 / 灵 / 宝 / 仙 / 极（凡品没有词条）
  items: [null, { tiejing_shi: 1 }, { tiejing_shi: 2, ling_yu: 1 }, { ling_yu: 2, stone_heart: 1 }, { ling_yu: 3, water_jade: 1 }],
  growth: 1.15, maxMul: 4,                     // 价格 = stones × min(1.15^inst.reforged, 4)，向上取整
  special: { mode: "swap", costMul: 2 },       // 特殊词条只能换成另一条特殊词条，价格 ×2
  imbue: "locked",                             // 附灵词条不能重铸（走附灵配方）
}
```

规则：
- 选一条词条，从该栏位的词条池（`AFFIXES`）里重抽属性，**排除这件装备已有的属性**。
- 数值按装备品级档取值 × 0.85–1.15，需要区域系数的乘上 `REGION_COEF`，与掉落时 `rollAffixes` 的规则相同。
- 成功后 `inst.reforged += 1`。
- 特殊词条（心法类）只能和特殊词条互换，普通词条不会变成特殊词条。这样仙品以上的"心法词条"既不会被刷没，也不会被刷出来。

**价格定位**：
- 区域一一局约带回 150 灵石；灵品重铸 30，偶尔用一两次。
- 区域二一局约 350 灵石；宝品一次 80，同一件刷到第 5 次累计约 470。
- 炼丹炉 2 级、炼器鼎 2 级、储物袋这些设施买齐以后，余钱的出路就是重铸。
- 九层封顶以后，灵石已经炼不成修为，sim 里这时会全部拿去重铸。
- 筑基以后（v1 之外）它是主要消耗，仙品一件刷满约 4000 灵石。

## 3. 奇遇·灵田（`encounters.js` 的 `lingtian`）

| 字段 | 值 | 说明 |
|---|---|---|
| `chance` | 区域一 0.2，区域二 0.25 | 每局出现概率 |
| `separate` | true | **单独掷**，不占每局 0–2 个奇遇名额。正反馈奇遇不该挤掉白鹭等剧情奇遇。抽对话奇遇时请跳过它；暂未实现 `separate` 时，`weight: 2` 作兜底占名额 |
| `minRun` | 3 | 区域一第 2 局起（药园开局就有地，需要种子来源） |
| `count` | [5, 8] | 株数 |
| `kinds` | `GATHER.lingtian.r1 / r2` | **品种 + 品级**：每株一个 `lt_<草>_q<品级>` 档，按区域品种份额 × 高一档的品级分布加权。不再用"品种决定品阶"，也没有"珍 / 稀"之类另起的档位 |
| `seedBonus` | 0 | 掉种子 +15% 已经在 `lt_*` 档里 |
| `ambush` | chance 0.4，at [3, 5]，n 3，elite false | 风险：采到第 3–5 株时，40% 惊动 3 只妖兽 |
| `done` | 修为 `enc`、机缘 `enc × 0.5`、记一句 | |

每片灵田的期望：
- 区域一约 15 份灵草，以灵品为主，加约 3 颗种子；区域二约 13 份、约 3.3 颗种子。
- 折成灵石（一半化灵）：区域一约 12，区域二约 35。
- 价值主要在种子。

### 3.1 给委托奇遇组的约定

- `src/game/quests/lingtian.js` 里，`plant.kind` 现在是 `lt_hanlu_q1` 这样的档位。显示名和种子 id 请从里面解析出灵草：`kind.replace(/^lt_/, "").replace(/_q\d$/, "")`。
- 改完后标签不再显示成"灵草"，`seedBonus` 的种子 id 也能找到。
- loop_quests 里的 "lingtian seed events (bonus seedlings)" 现在 FAIL（找不到 `seed_lt_*`），加上这一行解析就好。种子现在主要从采集掉落里出。
