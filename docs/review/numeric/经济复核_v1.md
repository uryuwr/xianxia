# 墨途 · 经济复核 v1（灵值 / 化灵 / 炼化 / 灵石 + 灵光点）

> **起因**（用户试玩反馈）：
> - "化灵只提示灵值，没提示灵石……灵值干嘛用的？灵品是先化灵再用，还是直接炼化？哪个收益更高？"
> - "每次出门路过一个水潭都有个金色的物品，可以化灵得 300 灵石。这种稀有物品不应该随机出现吗？"
>
> **改动的文件**（只改数据）：

> - `src/data/loot.js`：`GATHER` 灵光点改为按品质档抽取。
> - `src/data/items_db.js`：四种灵物去掉写死的品质，修为改为灵品基准。
> - `src/data/levels/r1.js`、`r2.js`：`glows` 候选点。
>
> **校验**：
> - 新增 `tools/scenarios/num_glows.mjs`（候选点可站、可达，分区风险，每局出现概率）。
> - 回归：loop_levels（`bad: []`）、loop_flow_levels、loop_cave 全部 PASS。
> - 模拟器：`sim/economy.py`，结果在 `charts/economy_results.json`。

## 0. 结论

1. **现行公式确实是个大漏洞，比协调举的例子还严重。** 根源在灵值的品质倍率（凡 1 / 灵 3 / 宝 10 / 仙 40 / 极 200）：
   - 它乘在"本身品质就写死的东西"上：灵蚌珠、水灵玉、千年竹心定义里就是宝品，狼王遗骨是灵品，狼王内丹是宝品。
   - 化灵再统一按灵值 × 0.5 折成灵石。
   - 具体例子：
     - 灵蚌珠：直接炼化 35 修为；化灵得 300 灵石，在灵泉 Lv3 能炼成 1200 修为，是 34 倍。
     - 碧鳞内丹：修为 0，但化灵能得 12000 灵石；碧鳞重复击杀有 50% 再掉一颗，可以无限刷。
     - 极品法宝：化灵 51 万灵石。
   - sim 按"理性玩家"跑：
     - 一周目灵石从 1500 涨到 7000–8300；
     - 炼化占全部修为的 85%；
     - 6 局、70 分钟就筑基；
     - 九层封顶后浪费 2500–3500 修为。
   - 修为曲线完全失效。上一轮 sim 根本没建模化灵，等于假设玩家从不化灵，所以没有发现。
2. **新规则**：
   - 灵值只是估价，不是货币；化灵按类别和品质单独定比例；灵石才是货币。
   - 用于修为的东西（妖丹、灵物、聚气丹）：化灵再炼化最多只有直接炼化的 80%（灵泉一级时 40%）。直接炼化永远更划算。
   - 装备、杂物化灵换来的灵石"有用但不暴利"：凡品剑 5、灵品 13、宝品 23（区域二七级宝品 60）、仙品封顶 150。
   - 关键物品不能化灵。
3. **改后 sim**：
   - 到筑基中位 7 / 7 / 8 局，p90 94 / 120 / 115 分钟（谨慎 / 贪心 / 新手），在目标内。
   - 灵石比"不化灵"多 17–23%，全部来自装备和富余材料。
   - 可选设施（炼器鼎 Lv2、32 格袋、药园 Lv2）的购买率从 47–80% 提到 69–98%，上一轮"买不起"的问题顺带缓解了。
4. **灵光点**：
   - 品质改为随机（灵品为主、宝品少见、仙品极少），期望修为与改前持平。
   - 每种灵物有 2 个候选位置，每局从 6 个候选里抽 2 个：每种约 60% 的局出现，每个位置约 33%。
   - 全部在风险 ≥ 3 的分区，或有精英看守。灵蚌池离入口近，所以加了精英守卫。
   - 从此"路过水潭白捡 300 灵石"的情况不会再出现：灵蚌珠化灵现在只有 6–10 灵石，它本来就该拿去炼化。

## 1. 新规则：四个概念各管什么

| 概念 | 是什么 | 用在哪 |
|---|---|---|
| **灵值** | 这件东西"值多少"的统一估价（`valueOf`：基础 × 品质倍率 × 数量 × 等级系数）。**不是货币，不能花** | 风险显示（身陨会丢多少）、结算、委托"满载而归"、储物袋取舍时的参考 |
| **灵石** | 货币 | 升设施、炼丹炼器、买符；也能在灵泉炼化成修为（灵泉 Lv1 / 2 / 3：每块 2 / 3 / 4 修为） |
| **化灵** | 把**用不上的东西**换成灵石 | 装备、多余材料、重复的功法 / 丹方残页 |
| **炼化** | 在灵泉把妖丹、灵物、灵石变成修为 | 妖丹、灵物**直接炼化**；灵石按需炼化 |

### 1.1 `recipes.js` 的 `HUALING`（洞府的 `huaLingStones(inst)` 直接返回 `HUALING.stones(inst)`）

```js
HUALING = {
  rate: { gear: 0.25, artifact: 0.004, scroll: 0.1, recipe: 0.1, herb: 0.25, ore: 0.25, beast: 0.25, talisman: 0.3, pill: 0.15, core: 0, treasure: 0, default: 0.2 },
  rarityMul: [1, 0.8, 0.4, 0.25, 0.1],   // 化灵的实际品质倍率 = 灵值倍率 × 它 = 1 / 2.4 / 4 / 10 / 20
  cap: [10, 25, 60, 150, 300],           // 每件（每份）封顶
  fromXp: 0.2,                           // 妖丹 / 灵物：灵石 = 修为 × 0.2
  fromXpPill: 0.07,                      // 聚气丹：灵石 = 服用修为 × 0.07
  never: ["spirit_stone", "zhuji_dan", "bilin_core", "heshouwu"],
  stones(inst) { … },
};
```

`stones(inst)` 的计算顺序：

1. 关键物品（`tags` 含 `key`）、委托物、灵石本身、`never` 里的 → **0**。界面上应显示"关键物品，不可化灵"，按钮置灰。
2. 有修为的东西：
   - **妖丹 / 灵物**：`xp × 数量 ×（灵物再 × REFINE.treasureRarity[品质]）× fromXp`；
   - **聚气丹**：`use.xp[品质] × 数量 × fromXpPill`。
3. 其他：`min(灵值 × rate[类别] × rarityMul[品质], cap[品质] × 数量)`，向下取整。

**保证**：`化灵灵石 × 4（灵泉最高）≤ 直接炼化`。我对 items_db 里所有带 xp 的物品逐个检查过，没有违反的。聚气丹单独压低，防止"2 颗狼妖内丹（直接炼化 50）→ 极品聚气丹 → 化灵"把妖丹洗成更多修为：改后极品聚气丹化灵 12 灵石 = 48 修为。

### 1.2 给洞府组的契约（facilities.js 由洞府组改，我没碰）

- `huaLingStones(inst)`：你们现在的代码已经优先读 `HUALING.stones`，**不用再改**。loop_cave 的"化灵再炼化 ≤ 直接炼化"检查已通过。
- **`refineValue(p, inst)` 需要加一项**：灵物（`cat === "treasure"`）的炼化修为乘 `REFINE.treasureRarity[inst.rarity || 0]`（凡 / 灵 ×1、宝 ×1.3、仙 ×1.7、极 ×2.2）。
  - 这样随机品质才有意义："仙品灵蚌珠"比"灵品灵蚌珠"多 70% 修为。
  - 妖丹不乘，因为妖丹品质是固定的。
  - 在加上之前也能运行，只是所有品质都按灵品算。
- `canHuaLing(it)` 建议改成 `HUALING.stones(it) > 0`（或单独判断 `key` 标签），这样关键物品的按钮直接置灰，而不是"化灵 +0"。

## 2. 灵光点：品质随机、位置随机、风险换收益

### 2.1 品质（`loot.js` 的 `GATHER`）

用现有的"通用采集"机制（`GATHER[类型] = { 区域: [[子类型, 权重]] }`，`rollLoot` 本来就按权重抽一个），先抽品质档再给物品，不需要改逻辑：

| 灵物 | 灵品 / 宝品 / 仙品 | 数量 | 期望修为（改前固定品质） |
|---|---|---|---|
| 灵蚌珠 | 70 / 25 / 5% | 灵品 1–2、宝 / 仙 1，另有 4–8 灵石 | 44（52） |
| 狼王遗骨 | 60 / 35 / 5% | 1 | 80（80） |
| 水灵玉 | 50 / 40 / 10% | 1 | 239（240） |
| 千年竹心 | 50 / 40 / 10% | 1 | 297（300） |

- 实测 4000 次 `rollLoot('gather_*')`：品质分布与权重一致；化灵期望灵蚌 8.5、遗骨 16、水灵玉 48、竹心 59。
- `GATHER.glow`（没标物种的灵光点，以及炼器鼎残件 / 阵盘领过一次以后的替代）直接指向品质档。原因是 `rollLoot` 的通用解析只解一层；否则领过残件以后的灵光点会掉空。
- items_db 里这四种灵物去掉了写死的 `rarity`，修为改成灵品基准（灵蚌 30、遗骨 70、水灵玉 200、竹心 250）。夜明宝箱抽到的"灵光材料"因此是凡品，炼化修为与灵品相同。
- 旧存档里已有的宝品水灵玉照旧存在；等洞府加上 `treasureRarity` 后会按宝品 ×1.3 计算，影响很小。

### 2.2 位置与风险（`levels/r1.js`、`r2.js` 的 `glows`）

关卡的抽取规则（`src/world/level.js`）是"打乱候选后取前 `pick` 个"，没有权重和概率字段。所以用"每种 2 个候选、6 选 2"来做概率：每种约 60% 的局出现，每个位置约 33%。

| 区域 | 灵物 | 候选位置（分区·风险） | 守卫 |
|---|---|---|---|
| 一 | 狼王遗骨 | 狼谷 [36,-30]（5）；北脊 [-20,-50]（4，**新**） | 精英 |
| 一 | 灵蚌 | 灵蚌池 [-11,23]（溪畔 1）；青岚瀑下 [4,-36]（瀑下 3，**新**） | 灵蚌池**新加精英**；瀑下无守卫（高风险区） |
| 一 | 炼器鼎残件 | 山神庙 [-46,-26]（3）；庙南 [-26,-32]（3，**新**） | 精英 |
| 二 | 水灵玉 | 深潭 [-18,-57]（5）；竹海池西岸 [-73,12]（竹海深处 4，**新**） | 惊动碧鳞 / 精英 |
| 二 | 千年竹心 | [-76,-8]、[-86,-44]（**新**），都在竹海深处（4） | 精英 |
| 二 | 阵盘·剑阵 | 孤峰 [90,-58]；断涧东 [84,-20]（**新**），都是 4 | 无守卫（都要二段跳才能到，本身就是门槛） |

- `num_glows` 校验 12 个候选点：全部可站、不在碰撞体里、从入口可达（阵盘两处需要二段跳，是有意的）；全部有守卫或在风险 ≥ 3 的分区；每种每局出现 60%。
- 注意：炼器鼎残件每局出现的概率从 67% 变成 60%，前两局区域一都没碰到的概率从 11% 变成 16%。炼器鼎 Lv1 的时间点在 sim 里没有变化（sim 没有建模残件的掉落）。
- 被守着的灵光点更多了，区域一每局约多 0.3 个精英。

## 3. 现在的实际规则（回答用户的另外两个问题；数据来自 `loot.js`、`levels/*.js`、`run.js`）

### 3.1 宝箱：位置和品质是固定还是随机？

**位置是随机的**（候选池里抽）：

| 区域 | 普通宝箱 | 灵光宝箱 | 夜明宝箱 |
|---|---|---|---|
| 区域一 | 从 12 个候选里抽 5 个 | 从 4 个高风险候选里抽 1 个 | 入夜（第 12 分钟）时从夜明点里刷出 |
| 区域二 | 从 13 个候选里抽 6 个 | 从 6 个候选里抽 2 个 | 同上 |

协调说"区域一 12 选 6"：实际是总共 6 个，其中 1 个是灵光宝箱，所以普通宝箱 12 选 5。

**开出的东西也是随机的**，按 `SOURCES.chest_*` 每条独立判定：

| 来源 | 灵石（× 区域倍率：一 1、二 2.5） | 材料 | 其他 | 装备（概率，凡 / 灵 / 宝 / 仙 / 极 权重） | 机缘 |
|---|---|---|---|---|---|
| 普通宝箱 | 6–12 | 90%：常见材料抽 2 次 | 25% 丹符（回春 3 : 回气 2 : 遁地 1）；8% 丹方残页；二区 6% 火符残页 | 10%：55 / 35 / 10 / 0 / 0 | — |
| 灵光宝箱 | 12–22 | 稀有材料 ×2；60% 常见材料 | 30% 丹方残页；二区 35% 火符残页 | 40%：0 / 50 / 40 / 10 / 0 | +5，满了兑现 |
| 夜明宝箱 | 25–45 | 稀有材料 ×2；30% 灵光材料 | 二区 40% 火符残页；6% 心法 | 70%：0 / 20 / 52 / 27 / **1.5** | +10，满了兑现 |

灵潮（晨 1 / 午 1.2 / 暮 1.5 / 夜 2）放大可堆叠物品的数量，不改变品质。

### 3.2 怪物掉落

| 来源 | 内容 |
|---|---|
| 小怪 | 60%：1–3 灵石；50%：本区域专属材料 1 份；6%：装备（70 / 25 / 5）。**保底**：连续 40 只没出灵品以上装备，下一件至少灵品 |

- 定义里写死品质的灵物：已改，见 §2。
- "灵潮 / 机缘提高品质"：现在的代码没有实现（`rollLoot` 不读 tide）。如果要做，建议掉落模块在暮 / 夜把灵光点品质档的权重整体后移一档，这是逻辑改动，我没做。
- 其他掉落率与上一轮评审一致，没有改。

- 贪心型 p90 正好 120 分钟，与难度复核时一样，主要由入夜局的时长决定，与经济无关。

## 5. 给玩家的引导（洞府组 / 流程组放进游戏）

### 5.1 一句话说明（物品详情、灵泉 / 化灵界面的"？"）

- **灵值**："这件东西值多少"的估价。身陨时损失多少、委托"满载而归"都按它算。它**不是钱，不能花**。
- **灵石**：修仙界的钱。升设施、炼丹、炼器、画符都要用；用不完也可以在灵泉炼成修为。
- **炼化**（灵泉）：把妖丹、灵物、灵石化为修为。**妖丹、灵物请直接炼化，这样修为最多。**
- **化灵**（储物）：把用不上的东西化成灵石。适合多余的装备、材料、重复的残卷。

### 5.2 怎么处理（一张表）

| 东西 | 建议 | 原因（界面上显示的数字） |
|---|---|---|
| 妖丹、灵物（狼王遗骨、灵蚌珠、水灵玉…） | **直接炼化** | 显示"炼化 +N 修为"和"化灵 +M 灵石（≈ M×灵泉倍率 修为）"，前者总是更多 |
| 聚气丹 | **服用**（每层限 3 枚），超出的留到下一层 | 化灵很亏 |
| 碧鳞内丹、千年何首乌、筑基丹等关键物品 | **留着** | 不可化灵 |
| 用不上的装备 | **化灵** | 换灵石升设施；宝品以上先看看是否比身上的好 |
| 多余的草药、矿石、兽材 | 先留够炼丹 / 炼器的份，**多余的化灵** | 一份 1–10 灵石 |
| 灵石 | 先留够下一个想升的设施，**其余炼化** | 灵泉等级越高，每块换的修为越多 |

### 5.3 界面要点

1. 化灵按钮和详情里只写"**→ 灵石 N**"（灵石图标），**不要只写灵值**。
2. 灵泉的炼化列表里，每件写"**炼化 +修为 N**"。妖丹 / 灵物如果玩家去化灵，弹一次提示："直接炼化可得 N 修为，化灵只换 M 灵石（≈ K 修为）。确定化灵？"（`refineCompare` 已经算好了）。
3. 灵值改叫"估价"或在旁边加注"（估价）"，储物袋顶栏写"估价 X · 灵石 Y"。
4. 第一次回府（觉醒那一次）的玄机子台词里，加一句："妖丹灵物，放进灵泉直接炼化；用不上的家什，化作灵石，好修缮洞府。"
5. 关键物品的化灵按钮置灰，悬停提示"关键物品，不可化灵"。
