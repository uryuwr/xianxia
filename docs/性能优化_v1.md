# 性能优化 v1（《墨途》出行局 / 界面切换）

> 结论先说：卡顿的主因有两类。一是**集显 GPU 每帧 45–54ms**（1080p 实际分辨率下：全屏水墨后期逐像素算十几次噪声、4096 柔和阴影且全图敌人每帧都进阴影和主画面、4×MSAA 半浮点渲染目标），只能跑 20 帧上下；二是**周期性尖峰**——特效材质用完就释放，导致同一个着色器反复重新编译（集显上每次 60–170ms，战斗 5 秒内能出现 12 次），再加上敌人第一次在新区域寻路时 BFS 现算格子（20–25ms）。
> 优化后：着色器编译尖峰和寻路尖峰都消掉了；全图画面外的敌人不再画，draw call 从 390–470 降到 90–180；水墨后期在像素级不变的前提下快了约 10ms（集显）；新增 高 / 中 / 低 / 自动 画质档位，集显默认"中"，帧率不够会自动降到"低"。

## 1. 测量方法

| 项 | 说明 |
|---|---|
| 机器 | i7-10700K；独显 RTX 3070；**集显 Intel UHD 630**（`IGPU=1` 让 Chromium 带 `--force_low_power_gpu` 用集显渲染，UHD 630 比常见笔记本的 Iris Xe 还弱 2–2.5 倍，当作"普通集显"的下限） |
| 分辨率 | 窗口 1536×864、`DPR=1.25`（等于 1080p 屏 125% 缩放，Windows 笔记本最常见），部分对照用 1280×720 / DPR 1 |
| 工具 | `tools/scenarios/perf_probe.mjs`（主探针）、`perf_tiers.mjs`（各档 GPU 对照）、`perf_parity.mjs`（画面一致性 + 着色器 A/B 计时）、`perf_quality.mjs`（画质档位可运行测试）。`tools/run.mjs` 新增环境变量 `IGPU=1`、`DPR=1.25` |
| CPU 帧耗时 | 包装 `input.update`（帧首）与 `input.endFrame`（帧尾），即主循环一帧的 JS 耗时（含提交 WebGL 命令）；各模块的 `update` / `render` / `shadowMap.render` 分别计时 |
| GPU 耗时 | `EXT_disjoint_timer_query_webgl2` 包住 `ink.render`。无头浏览器帧间隔锁在约 31ms，GPU 闲时会降频，循环里测到的 GPU 时间偏大，所以另做**基准**：暂停玩法，同一画面背靠背渲染 30 帧取计时中位数（`bench`）；各档对比用 `perf_tiers` 在同一画面交替 3 轮取中位数，排除频率波动 |
| 尖峰 | 每段记最慢 3 帧的模块拆分、新编译的着色器程序（是哪个网格的材质）、`PerformanceObserver(longtask)`、CDP CPU 采样（`PROFILE=1`）按函数自身耗时排行 |
| GC | `performance.memory` 堆增长率（MB/s）与回收次数 |
| 场景 | r1 / r2 各：入口开阔地走动、植被最密处（按实例统计 12 米格最密）、战斗（刷 8 只、每 0.25 秒放一个法术 / 法宝 / 阵法 + 普攻，不足 6 只补刷）、入夜走动、夜战、储物袋 / 天机镜打开、界面切换（结算 → 洞府 → 出行准备 → 出行局）、新特效（见 §6） |

运行：`node tools/run.mjs perf_probe "scene=run&region=r1&slot=3"`；常用组合：
`IGPU=1 DPR=1.25 W=1536 H=864 QUALITY=medium STAGES=open,combat node tools/run.mjs perf_probe "scene=run&region=r2&slot=3"`
（`ABLATE=1` 消融、`PROFILE=1` CPU 采样、`QUALITY=orig` 还原优化前的渲染配置做对照）。原始数据在 `work/perf/*.json`。

集显（UHD 630，r2 入口，1920×1080 实际像素）每帧 GPU **44.3ms**，消融拆分：

| 消融项 | 帧 GPU | 节省 |
|---|---|---|
| 基准 | 44.3 | — |
| 水墨后期换成直接拷贝 | 30.8 | **13.5**（逐像素 13 次值噪声 + 5 层 fbm + 10 次深度采样） |
| 关阴影 / 阴影不更新 | 31.2 / 33.7 | **13.1 / 10.7**（4096 PCFSoft，植被投影占 8.5） |
| 关 MSAA | 36.3 | 8.0（4×、半浮点颜色 + 浮点深度） |
| 不画植被 | 35.4 | 8.9 |
| 分辨率 ×0.75 / ×0.5 | 31.2 / 21.5 | 13 / 23 |

另外，敌人网格与描边壳都关了视锥裁剪（`frustumCulled=false`），**全图 30–40 只敌人每帧都进主画面和阴影**：同一画面（r2 入口）剔除前后的 GPU 从 53.6ms 降到 34.3ms（集显），draw call 393→106。

|---|---|---|

## 3. 优化项与前后数据

### 3.1 着色器程序常驻 + 进局预热（消除编译尖峰）
- `src/render/perf.js` `keepPrograms(renderer)`：材质 dispose 时如果它是某个程序的最后一个使用者，就把它留作"保活"（每个程序留一个，上限 200），程序和 ShaderMaterial 的着色器阶段缓存都不释放，同样的特效下次直接复用。
- `src/render/prewarm.js`：进出行局时加载画面盖着，在镜头前临时摆出构筑特效、共用特效、敌人预警、刀光 / 剑气 / 墨痕池、施法预览叠加层、拾取 / 护盾 / 弹道同参数材质，**每种在场敌人临时切成半透明**（倒地化墨 / 留尸用的着色器变体），先 `renderer.compile`（并行编译，期间暂停主循环 3D 渲染），再按水墨管线完整画一帧（程序首次使用、阴影深度变体、ANGLE 顶点格式变体都在这一帧完成）。首局约 0.55s（集显 0.58s），之后 20–120ms。
- 数据（集显 r2）：战斗长任务 **12 次 59–125ms → 0**；夜战 8 次 → 0；入口走动的 164ms 编译帧 → 0。独显 r1 入口 50ms 帧 → 消失。最终跑测所有段落"新编译程序"列表为空。

### 3.2 水墨后期：纸纹预烘焙（像素级不变）
- 只与屏幕坐标有关的噪声（色阶分层、墨线抖动、笔锋粗细、飞白、纸纹纤维、暗角）在尺寸变化时用同一公式烘进两张贴图（A：32 位浮点，B：8 位），逐像素只取两次；崖下雾的 fbm 只在 `low > 0` 时算；末尾重复的颜色采样复用。
- `perf_parity`：同一帧原始 / 优化着色器逐像素比较 **最大差 1/255**（8 位贴图存墨线抖动会有 0.003% 像素描边翻转，所以 A 用浮点）。
- 同会话 A/B（集显 1920×1080）：**39.5 → 29.3ms/帧（−10ms）**；独显 1.6 → 1.5ms。

### 3.3 画面外的敌人 / 尸体不画、不推进骨骼动画
- `EnemyDirector.updateView()/inView(p, r)` 每帧算一次镜头视锥；`Enemy.animate()`：球（半径 3 + 6×体型，含影子余量）不在视锥里就隐藏根节点、不推进 mixer（时间累计，回到画面时补上，循环动作看不出）。AI、出招计时不依赖动画，玩法不变。倒地动作照常推进（留尸姿势要对）。
- 留尸（容器模块已做骨骼 / 矩阵冻结）在 `containers.update` 里同样按视锥隐藏。
- `perf_parity`：剔除前后同一帧逐像素 **最大差 1/255**（影子余量足够）。
- 数据：draw call r1 入口 313→88、r2 入口 393→106、r2 战斗 465→179；集显 GPU r2 入口 53.6→34.3ms（同一渲染配置）。30 具尸体在画面外：326–369 → 46–85 draw call，CPU 3.7→2.0ms。

### 3.4 寻路（src/game/enemies/nav.js，玩法结果不变）
- `cell()` 查碰撞体改为查 4 米分桶（`sync` 时已建，桶覆盖"半径 + 余量"的外接方框，与逐个遍历结果相同）；`segHits` 去掉每次 `new Set`；BFS 队列用扁平数组。冷 BFS **24ms → 8ms**。
- 流场只取决于目标格和边的通断（边只在 `block()` / 换关卡时变，那时清空），所以一直复用到被清空，不再每 0.6 秒按时间重算。
- `prebuild(bounds)`：进局时（加载画面）把关卡范围内所有格子和边一次算好（r1 58ms、r2 99ms），战斗中新区域 BFS 只剩 1.5–5ms。
- `canReach(pos, target)`：撤离选点"能不能走到候选点"不再对每个候选点建整张流场，BFS 碰到自己所在格就停（答案与 `reachable(pos, flow(target))` 相同，算完整张的照常缓存）。
- 数据：独显战斗 nav 单帧 19.6–22.5ms → 最大 3.9ms。

## 4. 画质档位

设置页（标题 / 暂停菜单共用的设置面板）新增"画质：自动 / 高 / 中 / 低"，存 `moxian.settings.quality`（与流程组、瞄准模块合并写入，不覆盖其他字段）。实现：`src/render/quality.js`。

| 档 | 渲染分辨率 | MSAA | 阴影贴图 | 植被 | 墨线采样 |
|---|---|---|---|---|---|
| 高 | min(DPR, 1.5)（原来是 min(DPR, 2)） | 4× | 4096 | 全密度、全部投影 | 8 向 |
| 中 | min(DPR, 1)，即按 CSS 像素 | 2× | 2048 | 草 / 小石 / 竹叶 70% | 8 向 |
| 低 | min(DPR, 1) × 0.75 | 无 | 1024 | 上述 45%，植被不投影 | 4 向（十字） |
| 自动 | 起始档按显卡猜：Intel / 核显 Radeon / 移动端 → 中，软件渲染 → 低，其他 → 高；出行局 / 洞府里帧间隔中位数持续 > 20ms（< 50 帧）就降一档，只降不升；降到的档记在 `moxian.settings.qualityAuto`，下次启动直接从这档开始，在设置里重新点"自动"会清掉 | | | | |

- 抽稀只作用于没有碰撞体的纯装饰实例（草、小石、竹叶），实例顺序先用固定种子打乱再截断，空间上均匀；高档不打乱不抽稀，与原画面一致。
- 自动档在自动化测试（`navigator.webdriver`）里不降档，保证回归画面可比；`window.__autoQualityTest = true` 可在测试里打开（`perf_quality.mjs` 用到）。
- 接口：`__game.setQuality("medium")`、`__game.quality`（mode / tier / pixelRatio / 最近一次自动降档）。

## 5. 还剩的瓶颈

1. **集显"高"档仍是 25–42ms**：高档保留原画质，给独显用；集显由自动档落到中 / 低。竹林最密处中档 21ms（UHD 630），主要是植被投影（4096 时 8.5ms）和竹叶 alpha-test 的过度绘制。进一步可以做静态阴影缓存（静态物与角色分两张阴影图），改动大，未做。
2. **首次进洞府 320–450ms**（只第一次）：洞府模块同步建场景（fbm 215ms）、立绘 / 纸纹预烘焙（`toBlob` 446ms，在 requestIdleCallback 里一次做完）、首见着色器 104ms。建议洞府组把预烘焙逐张分到多个空闲回调、建场景分帧或放进过场遮罩里，并在场景建好后调 `prewarm` 同样的思路（`renderer.compile` + 暂停 3D 一帧）。
3. **进局加载 0.5–1.1s**（集显首局约 1.1s）：着色器预热 ~0.55s、寻路预算 ~0.1s、天机镜底图 ~0.15s（含 `readPixels`）。都在加载画面里，第二局起预热只要 20–120ms。
4. **留尸在画面内的 draw call**：每具约 8–9 个（身体 + 描边壳 + 阴影），30 具都在画面里时 +300 draw call、独显 CPU +2ms。建议留尸关掉投影（半透明墨色剪影本来影子就该淡），或者定格后合并成静态网格。
5. 集显上偶发一次 80ms 级帧（多次复跑不能复现，不是着色器编译、不在 JS 里），疑似驱动 / GPU 进程侧，继续观察。
6. CPU 侧现在最大项是 `updateMatrixWorld`（骨骼与全场景矩阵，CPU 采样约 2%）：静态地形 / 植被可以关 `matrixWorldAutoUpdate`，收益约 0.1ms，有误伤风险，未做。

## 6. 新特效 / 新界面的开销（协调通知的 5 项）

|---|---|---|

## 7. 新特效和新 UI 的性能规范（以后的新功能都按这份来）

**预算**（中档、普通集显笔记本）：主循环 JS ≤ 8ms、GPU ≤ 12ms；单个新功能每帧 CPU ≤ 0.3ms、常驻 draw call ≤ 10（同屏峰值 ≤ 30）、全屏或大面积透明层 ≤ 1 层。

1. **材质 / 着色器**
   - 不要每次放特效就 `new ShaderMaterial` / `new MeshBasicMaterial`：做成对象池（参考 `player_fx.js` 的刀光池），颜色、进度走 uniform。
   - 新的着色器（或新的材质参数组合：`transparent`、`side`、`map` 有无、蒙皮 / 实例化）要加进 `src/render/prewarm.js`，否则第一次出现时集显卡 50–170ms。`keepPrograms` 只是兜底（上限 200 个程序）。
   - 运行时不要切 `material.transparent` / `defines` / `side`（这些是着色器变体）；确实要切，就在预热里切一次。
2. **几何体**：不每次 new；用单位几何体 + `scale`；数量多的用 `InstancedMesh`；不要每帧改顶点（贴地预览类除外，且只在可见时改）。
3. **对象池与上限**：粒子一律走 `ctx.vfx.burst`（实例化，全局上限 600）；网格特效池子大小写死（刀光 8、剑气 2、墨痕 6 的量级），满了复用最早的；DOM 浮字 / 提示做元素池（参考 `feedback.js`）。
4. **每帧禁止**：在 update 热路径里 `new Vector3/Matrix4/Color`、数组字面量、闭包，`filter/map/sort/[...spread]`，`querySelector`，`innerHTML`，`getBoundingClientRect / offsetWidth / getComputedStyle`（强制重排）。临时向量用模块级变量；尺寸在打开 / resize 时读一次缓存。
5. **DOM**：只在值变化时写（缓存上次的值，参考 `runhud.set/setVar`、`imbue.js`）；动画只动 `transform / opacity / CSS 变量`；进度类每帧事件要限频（≥0.5% 变化才写）；不要对大面积元素做 `filter / backdrop-filter / box-shadow` 动画。
6. **离屏渲染 / Canvas**：离屏渲染只在进入时做一次，且放在加载画面里；`readPixels` 只此一次；Canvas 2D 重绘 ≤ 10Hz 且只在数据变化时（用 stamp），单次 ≤ 0.5ms。
7. **3D 对象**：骨骼网格画面外不画、不推进动画（参考 `EnemyDirector.inView`）；不再动的骨骼冻结（参考 `containers.freeze`：矩阵与骨骼贴图只算最后一次）；慎用 `frustumCulled = false`（会每帧画、还进阴影 pass，必须自己做剔除）；`castShadow` 只给需要的，小装饰、透明物、地面贴花不投影。
8. **透明大面片**：同一位置叠加 ≤ 2 层，半径有限；不要全屏透明 quad（后期效果加进 `ink.js` 的同一个 pass）。
9. **寻路 / 查询**：一帧里不要对多个目标各做一次 `nav.flow`；只问"能不能到"用 `nav.canReach`；碰撞 / 范围查询用分桶，不逐个遍历几百个碰撞体。
10. **自测**：新功能合入前跑 `perf_probe`（`STAGES` 选相关段落，必要时加 `IGPU=1 DPR=1.25 W=1536 H=864 QUALITY=medium`），确认：cpu p95 没涨超过 0.5ms、draw call 在预算内、`compiles` 为空、`longTasks` 为空、alloc 没明显上涨。
