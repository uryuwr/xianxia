## 2. 方法（纯程序，无手工）

### 2.1 骨骼和动画：不重做，直接复用

`blender/refine_v1/lib_refine.py` 的 `load_legacy_hero()` / `load_legacy_creature("build_qingya.py")` 在 Blender 里**执行原脚本**（去掉末尾的导出调用；`lib_creature.build_creature` 临时换成只收参数的函数），得到原骨架 + 全部动作（含次级动态烘焙的飘带 / 袖 / 下摆 / 剑穗）。原文件一个字不改。

蒙皮：新网格每个顶点先判"属于哪个部件"（取最近的、带 part 标签的建模图元），再套**原脚本同一个**部件→骨骼距离权重公式（主角 5 次方 / ε 0.006 / 袖骨 ×0.85，青牙 4 次方 / ε 0.01），最后沿网格边平滑 2–6 次（部件交界处不撕裂），每顶点保留 4 根骨。`png/hero_slash.png`、`qingya_bite.png` 是命中帧截图。

### 2.2 形体：距离场（SDF）平滑融合 → Surface Nets 高模

`blender/refine_v1/lib_sdf.py`（纯 numpy，可单测）：

1. 图元：圆锥胶囊 `sd_round_cone`、椭球、圆角盒、椭圆截面放样管 `sd_loft`、圆锥链 `chain`；用多项式 smooth-min（`smin(a,b,k)`）融合、`smax` 挖减（眼窝、口裂、耳窝、收腹）。
2. 每个**材质组**（一个连续表面，如 fur_qing、bone_armor、robe_white）在规则网格上求距离场（每个图元只算自己的包围盒）；窄带内叠加程序化位移（衣褶、骨甲麻点、束腰横褶）。
3. Surface Nets 抽等值面 + 沿梯度投影到零面 → 高模（每组 3–40 万顶点，体素 1.1–7 mm）。
4. 薄处会出非流形边 → 减面前先 **OpenVDB 体素重网格**成封闭流形（`decimate(voxel=)`），再 Decimate collapse 到目标面数。

青牙的毛：先把基础体粗网格化，在表面按"毛流场"（背部向后、腹侧向后下、腿向下、肘后飞毛、胸前垂毛、头部短毛）泊松撒点，每点长一束**扁椭圆截面、根埋皮里、梢部翘起、两侧略弯**的毛束（约 500 束），束与束之间的凹缝在曲率图里就是墨线。颈后长鬃（4 排 48 束）、颊鬃、尾梢是另一层材质 fur_light。

主角的头：主管 2026-11-18 决定改走 **MPFB（MakeHuman）CC0 基础网格**（`blender/refine_v1/mpfb_head.py` 生成 → `work/refine_v1/mpfb_head.npz`）：对齐到原头骨（眼高 1.60、头顶约 1.735）→ 左右镜像平均 → 下颌向中线收（V 形）→ 眼周 / 唇 / 鼻翼区域拉普拉斯抹平 → 去掉眼球与口腔、补洞、把眼窝和口裂压到前面只留 1–2 mm 浅凹（眼睛是画的、嘴闭合）→ Catmull-Clark 两级细分做上色高模 → 对称减面到 1,100 面。脸部顶点法线向一个椭球的法线靠（`soft_normals`，导出为自定义法线），不烘法线贴图、不烘 AO / 墨噪点。

### 2.3 贴图：顶点上"画"，再从高模烘到低模

每个高模顶点上用 numpy 算：AO（Cycles 烘到顶点色，不同阶段的子网格互不遮挡）、曲率（离散平均曲率，按 85 分位数归一，与体素大小无关）、毛束 / 发束编号与根→梢参数，再由角色脚本的 `paint()` 出：

- **固有色**（PBR 用）：底色 ≈ 游戏 PALETTE 色；毛梢亮根暗、束间缝积墨、背深腹浅、眼周墨纹、骨甲污渍、下摆墨染、五官笔触。
- **墨图** `*_ink`（B 模式用）：R = 笔触墨（束间缝、五官、骨甲刻线），G = 曲率（0.5 中性，<0.5 凹缝），B = AO。
- **ORM**：R = AO，G = 粗糙度，B = 金属度（只有剑身 = 1）。

然后所有低模一起 Smart UV + 打包成一张图集（脸 ×2.6、眼 ×2.5、发 ×1.5 的密度权重），Cycles"选中→活动"逐组烘焙：切线空间法线、以及上面三张（自发光烘焙，读顶点色），烘焙 margin = 0、numpy 合成 + 外扩 24 像素。烘焙在 RTX 3070（OptiX）上跑，Blender `-t 8`。

思路参考了听雨园（MIT）`src/materials/baker.js` 的"高度场 → 法线 / 缝隙积灰 / 边缘磨损"；**未复制其代码**（它烘的是可平铺材质，本项目烘的是展 UV 的角色图集，实现完全不同）。

### 2.4 三种着色（`assets/char_mats.js`）

- **A 现行 3 阶 toon**：材质名 → PALETTE 纯色（与 `src/game/player.js` / `enemies/enemy.js` 相同），不读贴图；精细版主角的 skin 用"亮 / 中"两阶渐变（不出现把脸切两半的硬明暗线）。
- **B 水墨写意**：MeshToonMaterial + 法线贴图（主角衣服 ×0.45）+ 墨图（AO 压固有色、凹缝压暗、凸棱提亮、笔触墨），固有色贴图按 albK 混入 PALETTE 色。固定程序键 `jx-char-B`，参数全走 uniform（需加进预热）。
- **C 写实 PBR**：glTF 原材质（baseColor / normal / ORM，aoMapIntensity 0.6），交给 ink.js 后期。
- 描边壳：现状模型沿用游戏值（主角 0.018、青牙 0.016）；精细版细节多，反向外壳会从鼻下、唇缝、毛束凹缝穿出黑块 → 主角 0.007、青牙 0.011，**主角的脸 / 手不套描边壳**（轮廓交给水墨后期的深度描边）。

## 3. 每一步的命令

```bash
B=D:/tools/blender-4.5.16-windows-x64/blender.exe
# 主角的头（只在改 MPFB 参数时重跑；插件装在独立目录，不碰用户的 Blender 配置）
BLENDER_USER_CONFIG=D:/tools/mpfb2/config BLENDER_USER_EXTENSIONS=D:/tools/mpfb2/extensions $B -b -t 8 --python blender/refine_v1/mpfb_head.py
$B -b -t 8 --factory-startup --python blender/refine_v1/build_hero_v2.py            # ≈ 6.5 分钟 → assets/hero_v2.glb + 贴图
$B -b -t 8 --factory-startup --python blender/refine_v1/build_qingya_v2.py          # ≈ 8 分钟  → assets/qingya_v2.glb + 贴图
#   -- --hi 只出高模预览（work/refine_v1/*_hi.png）；-- --quick 粗体素快速迭代
$B -b -t 8 --factory-startup --python blender/refine_v1/ink_webp.py -- qingya_v2    # 墨图 PNG → 1024 WebP（主角脚本已自动出）
npx vite --port 5191 --strictPort --force                                           # docs/ 不在 vite 监听里，改了 js 要重启
node docs/art/精细化小样_v1/char_preview/shoot.mjs [hero|qingya|名字…]                # → png/*.png（一个浏览器实例，跑完即关）
node tools/art_refine_v1/build.mjs                                                   # art-env 的总页面打包
```

资源约定（主管 2026-11-18，用户反馈 CPU 跑满后）：Blender 一律 `-t 8`（16 逻辑核留一半给用户）；Cycles 烘焙走显卡（`lib_refine.enable_gpu()`：OptiX 优先、失败退 CUDA，只启用 RTX 3070，再失败退 CPU）；同一时间只跑一个 Blender、只开一个截图浏览器。改用显卡后单个角色构建 6.5–8 分钟，大头是单线程的 numpy 距离场与减面，不是烘焙。

## 5. 面数 / 贴图 / 骨骼与同屏代价

| | 三角面 | 骨骼 | 图元（draw） | 贴图 | glb |
|---|---|---|---|---|---|
| 林墨 现状 | 5,324 | 33 | 10 + 10 描边 | 无 | — |
| 林墨 v2 | **7,698** | 33（不变） | 10 + 9 描边（脸不描） | 1024² × 3 内嵌 + 墨图 1024 | 1.5 MB |
| 青牙 现状 | 2,376 / 2,480 | 25 | 本体 5 + 骨甲 1（+ 描边同数） | 无 | — |
| 青牙 v2 | **11,540 / 12,160**（文件内共 13,660） | 25（不变） | 本体 6 + 骨甲 1 / 裂板 2 + 眼焰 1 | 2048² × 3 内嵌 + 墨图 1024 | 3.8 MB |

- 显存（RGBA8 含 mip）：1024² ≈ 5.6 MB/张、2048² ≈ 22.4 MB/张。林墨 4 张 ≈ 22 MB；青牙 3 × 2048 + 1 × 1024 ≈ 73 MB（落地建议降到 1024，≈ 22 MB；45° 镜头下青牙在屏幕上约 150–300 像素，1024 足够）。
- 顶点开销：描边壳与本体共享几何、各画一遍；同屏林墨 + 青牙 ≈ (7.7k + 11.5k) × 2 ≈ 38k 蒙皮三角面，单帧 GPU 开销可忽略；骨骼数没变，动画 LOD / mixer 开销不变。
- 新着色器：B 模式 1 个程序（`jx-char-B`），A 模式沿用 `toon()`；要加进 `src/render/prewarm.js`（性能优化 §7）。
- **建议的新预算**（性能工程复核）：主角 ≤ 8k（主管已定）、贴图 1024；首领 ≤ 8k + 1024 图集——青牙要达标需把毛束从 ~500 束降到 ~200 束更大的片、鬃毛减一排、裂板减面，预计能到 7–8k 而观感损失不大；普通怪不走这条线（同屏 30+ 只）。

## 6. 和现状的差异（一句话版）

- 林墨：球头 + 刘海块 + 方块袖 → 有脸型、有画出来的五官、有发束与发髻、有衣料厚度和褶、有剑的结构；剪影基本不变。
- 青牙：胶囊 / 尖刺拼接 → 连续肌肉骨架 + 满身毛束笔触 + 有工艺感的骨甲；现状那一排白色尖刺鬃改成了青白长鬃团（45° 俯视里仍是"宽肩 + 骨板 + 头后浅色鬃"）。

## 7. 局限（如实）

1. **林墨**：袖口端面是平的（4 mm 体素下薄壁掏空会碎，只能用中衣色端面假装"袖里"）；C 模式袖上还有一点 AO 灰；脸在 3/4 侧光下仍有一阶中间调（已用两阶渐变 + 椭球法线压弱，正式的"脸部阴影阈值图"（SDF face shadow）未做）；手是距离场做的，握剑的指头近看较粗。
2. **青牙**：面数超标（见 §5）；B / C 下整体偏暗、毛束梢部在描边下略碎；尾巴偏细长；头相对身体略小；二阶段裂板的发光脉在 45° 镜头下不如现状的裂缝醒目。主管让本轮先放一放，未再迭代。
3. 两者都还是"程序化能到的程度"：没有手绘贴图、没有毛片 alpha（全是几何）、没有布料模拟（衣褶是静态位移 + 原有次级骨骼）。
