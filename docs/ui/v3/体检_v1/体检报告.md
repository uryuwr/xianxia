## 1. 血条为什么是黑的（来龙去脉）

1. **源头是设计文档 v0.3**：`docs/设计文档_v0.3.md` §5.5（第 194 行）写"HUD 极简：左上角气血和真气是两道墨痕"。`src/ui/hud.js` 按这句写的（文件头注释仍是"两道墨痕"）：气血 = 焦墨渐变 #121416 → #2b2e31，真气 = 青色，掉血余迹 = 淡朱 rgba(210,50,30,.35)。
2. **风格指南后来改了，但 hud.js 没跟着迁**：`docs/UI风格指南_v1.md` §3.1（`--zhu` = "确认印、主角、危险、HP"）、§5.9（`.ink-bar.hp` 朱、`.qi` 石青）、§5.16（气血 / 真气 = 朱 / 石青）都定了朱；§13.3 的迁移表把 `hud.js` 列在要换成 `.hud-vital` 的清单里，v2 示意图 `docs/ui/v2/hud.html` 用的也是 `.ink-bar.hp`（朱）。但 hud.js 至今是自己的一套 CSS：多边形 clip-path 条、矩形径向渐变底板，没有用 ink 套件。
3. **后来的模块把"黑"放大了**：`momentum.js` 在气血 / 真气下面加了气势条，用的是焦墨 `--ink-stroke-bar`；首领条（2026-11-17）气血也做成了墨（为了让狼威的朱更跳）。于是左上两条黑、顶上一条黑。
4. **没有任何"有意保留黑色"的记录**：`docs/knowledge/UI设计/` 各文件、`docs/ui/v2/` 各方案、`docs/review/ui/`（空）里都没有；仓库只有一个提交（v1），查不到更早的改动。结论：**是迁移遗漏，不是有意的决定**。
5. **黑色的理由（如果当初是有意的）该怎么评估**："墨痕"在单色水墨画面里确实最"像画"，对比度也最高（实测 P10 7.3）。但它的问题不在"看不见"而在"分不清"：同一组里气血与气势同色同形，层级原则（生死信息越允许朱色）也被反过来了——现在最醒目的朱色给了掉血余迹和敌人血条。方向丙「墨血转朱」保留了这个设想（满血墨、五成起转朱），供你对比。

## 2. 量法（可复现）

- **背景统计**：`measure.py` 对 现状 / A / B / C 四张底图按 HUD 分区统计亮度 P5 / P50 / P95 和纹理强度（边缘检测均值）。
- **实测对比度**：`shoot.mjs` 把 HUD 按原参数复刻叠到底图上，对每个 `[data-m]` 元素截三张同位裁片（A 前景隐藏、B 前景染品红当遮罩、C 原样），`measure_dom.py` 只在字形 / 条形核心像素上算 C 对 A 的 WCAG 对比度，取 **P10**（最差的一成像素）与中位数。结果在 `measure_dom.json`。
- 门槛：文字 ≥ 4.5:1（XAG 101，按最差背景）；18.66px 粗 / 24px 以上大字与图形元素 ≥ 3:1（WCAG 1.4.3 / 1.4.11）。
- 局限：B / C 是 30×30 米山神庙小样，不是整张关卡；"夜"是把 B 压暗 45% 的示意，不是游戏夜里的后期。

## 5. 请你选

1. **气血组用哪个方向？** 甲 朱墨两笔 / 乙 印记 / 丙 墨血转朱 / 保持现状。**推荐甲**：风格指南原定配色，版式不动，只换颜色、条形和底衬；朱只出现在"你的命"上。乙更有分量但左上多三方印、和首领条的印挤；丙满血时仍与首领条、气势同色，"黑色奇怪"没解决。
2. **残血要不要屏幕四缘淡朱墨？** 要（≤30% 常驻淡淡一圈 + 受击闪一下）/ 只要受击闪 / 不要。**推荐要**。
3. **小字底衬用哪种？** 一 字随墨晕 / 二 天头地脚 / 只把字加深加大、不加底。**推荐一**；二的 P10 最好（天时 4.22、技能字 4.0），但上下各压掉约 100px 画面，要美术一起看整体。
4. **敌人头顶血条用墨还是朱？** 墨（与首领条一致）/ 朱（保持"敌人 = 红"）。**推荐墨**；无论哪个，精英紫建议去掉。
