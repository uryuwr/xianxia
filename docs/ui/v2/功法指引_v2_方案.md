## 0. 问题

用户原话：「法术类型是否能增加些……也没有目标指引，野外能否掉落功法、功法残页用于参悟法术？」；「残页多少合成完本没提示、去哪兑换没提示」。

功法体系 v2 已经把法术加到 12 门、来源铺到野外（残页 / 名门功法 / 异种 / 首领首杀 / 突破赠予）。界面要回答三件事：

1. **这一门从哪来**：地点、敌人或容器、概率档、残页进度（2/4）、悟性能补几页；
2. **我要去的地方缺什么**：去处的护盾分布 ↔ 我缺的克制五行 ↔ 能补上这个五行的法术与去处（例：竹海·溪谷 火盾 4 成，你缺水 → 寒冰锥 · 剑修遗府 / 止水诀 · 残页 1/5）；
3. **凑齐了去哪参悟**：统一句式（与丹方残页一致，见 §5）。

现状：`src/ui/loadout.js` 的功法匣对未学的法术只写「未领悟」；悬停卡有「克 X 盾 · 本去处有没有 X 盾」；出行准备有「护盾 / 已带」两行（`shieldLines`），已带里会写「✗ 缺水」，但到此为止。

## 1. 三个方向共用的东西

| 项 | 做法 |
|---|---|
| 假数据 | 练气六层：已学剑气斩 / 缠藤诀 / 火符 / 土遁护体，Q 剑气斩、E 缠藤诀；残页 掌心雷 2/4、止水诀 1/5、落石诀 3/3（已集齐）、火鸦 1/4；悟性 4。练气三层：只有剑气斩、土遁护体，掌心雷 1/4、落石诀 2/3，悟性 1 |
| 缺口规则 | 去处的每种盾（精英分布 + 首领各段）→ 要的五行（金克木、木克土、水克火、火克金、土克水）→ **已带**的法术里有没有这一行（土遁护体不造成伤害，不算）。没有 = 缺口；缺口下列出这一行**还没领悟**的法术，排序：已集齐 → 本去处可得 → 名门功法 → 残页差得少的 |
| 来源行 | 地图小图标（`items_map.webp`：精英 / 妖兽 / 首领 / 宝箱 / 灵光宝箱 / 夜明宝箱 / 遗府）+ 地点 + 怎么得 + 「本去处」（石绿）或去处名 + 概率档 |
| 概率档 | **只写字不写百分比**：必得（固定 / 首探 / 首杀 / 赠予，朱）· 常见（≥30%）· 偶得（10–30%）· 罕见（<10%），墨色由浓到淡。理由：数值会调，字档稳定；搜打撤里玩家要的是「值不值得绕路」，不是期望值计算。精确百分比留作选择题 4 |

| 未得的签 | 意象技能图标的**墨拓剪影**（同一图标并墨，圆相转清墨）；凝锋诀 / 藤引 / 止水诀 / 火鸦 / 地行术还没有技能图标，草图用一个字兜底（锋 引 止 鸦 行），落地前要在 `tools/icons/skillicons.js` 补 5 个模板 |
| 颜色 | 五行色只用 `loadout.js` 的 `EL`；缺口用朱、顺路可收 / 可参悟用泥金；不涉及品级 |
| 草图标注 | 蓝色圆圈数字标出「这次新加的地方」，正式落地没有 |

## 3. 推荐：**C 为主 + A 的来源签**，B 以后再做

1. **用户的问题是「去哪打」**，答案的时机是出门前：去处、护盾、带什么都在出行准备里决定（装配 v2 已定「只在出行准备里装配」）。C 把缺口直接翻译成「下一步去哪」，并带进局内舆图，是三者里唯一闭环到局内的。
2. **A 的改动顺带做**：功法匣本来就列 12 门，未学的副标题写来源 + 残页点、悬停卡加来源段，成本很低，能覆盖「没缺口但想收集」的情况；C 的纸条和 A 的悬停卡共用同一套来源行、残页点、句式（`srcRows / dots / pagesLine`）。
3. **B 收集感最好，但和决策分离**；天机镜刚落地，功能再加一个应用要等用户对天机镜的使用习惯稳定。建议把 B 留作「图鉴」类扩展（以后心法、阵法也可以进谱）。如果用户更想要一处「全看」，B 也可以替代 A。
4. 叙事内外：缺口签、纸条是叙事外（决策信息，必须清楚）；舆图小签是空间型（手卷上的签条），与地图图标同一套「剪影 + 纸签」。

## 4. 给用户的选择题

1. **主方案**：A. 只改功法匣（最小）；B. 天机镜「功法谱」；C. 出行准备缺口签 + 舆图小签（推荐，可与 A 组合）；D. 三个都要（C + A 先做，B 下一轮）。
2. **局内舆图要不要挂来源小签**：A. 要，只挂缺口相关的（推荐）；B. 要，挂所有未领悟法术的来源；C. 不挂，只在出行前提示；D. 只挂玩家手动「追踪」的那一门（B 方案的按钮）。
3. **概率怎么写**：A. 只写档位字「必得 / 常见 / 偶得 / 罕见」（推荐）；B. 写百分比「25%」；C. 平时写字档，悬停 / 天机镜详情里写百分比。
4. **「已集齐 · 去仓库参悟」提醒放哪**：A. 出行准备一行 + 洞府「今日可办」（推荐，不加常驻红点）；B. 只在仓库里提示；C. 集齐那一刻（局内拾到最后一页）就弹「回洞府可参悟」通知，回洞府后再提醒一次。

## 5. 统一句式（与丹方残页一致）

| 场景 | 句式 |
|---|---|
| 进度中 | `残页 x/N · 集齐后到洞府仓库参悟`（丹方：`丹方残页 x/N · 集齐后到洞府仓库研读`） |
| 已集齐 | `残页 N/N · 已集齐 · 到洞府仓库参悟` |
| 悟性可补 | 跟在后面：`· 悟性可补 k 页`；k = min(⌊悟性 / 3⌋, N − x)，**x ≥ 1 才显示**；x = 0 时写「悟性要有 1 页实物才能补」 |
| 名门功法 | `名门功法 · 一本即成`（加门槛：`· 需二段跳 ✓ / ✗`） |
| 赠予 | `突破赠予 · 法术栏开而无功法可装时` |
| 已学 | `已领悟 · 二重 · 装在 Q 栏` |
| 重复残页 | 仓库参悟时：`重复残页 ×2 → 悟性 +2`（已学会或超出所需） |

局内拾到残页的通知也用第一行（`止水诀残页 · 2/5 · 集齐后到洞府仓库参悟`），仓库「参悟」按钮不足时的提示从 `残卷不全：1/5` 改成同一句。

## 7. 性能（`docs/性能优化_v1.md` §7）

- 全部是出行准备 / 天机镜 / 舆图这类**打开时构建**的界面：来源表、缺口、排序在打开时算一次（静态来源表可模块级缓存，按去处 key）；切去处 / 钉选才重建对应块。
- DOM 只在变化时写：悬停卡只在「换了条目」时写 innerHTML 与位置（草图 `mouseover` 里比较 id，相同直接返回）；功法匣滚动位置只在钉选 / 去处变化时设一次，不读布局循环。
- 舆图小签：地图打开时连同其他图标一起画（canvas 或 DOM 一次性），拾到残页时只改那一张签的文字；不做每帧动画、不加 filter / box-shadow 动画（纸签阴影是静态 drop-shadow 在小元素上）。
- 草图里的 `inkui.decorate()` 每次重绘全页扫描，落地时改成只对新建的纸面调用。
- 图集：草图的 `icons.js` 是从当前 `src/ui/icons/items.json` 摘的坐标（main 2048×1664）；`loadout_v2/icons.js` 是旧图集坐标，已经对不上（见 UI 坑）。
