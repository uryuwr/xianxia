## 0. 问题

- 出行准备（`src/ui/screens/prep.js`）里的法术栏只能看、不能改；心法没有选择入口。
- 局内由 `src/game/run/run.js` 的 `loadoutOf()` 把"已学会"的法术按顺序补进空栏，心法栏为空时也会用已领悟的心法补上。
- 设计意图（设计文档 v0.3 §4.1、"防止废技能"）：法术少而精、冷却长；精英和首领带五行护盾，只有相克的五行能高效破盾（现行数值 `SHIELD_TUNE`：克制 ×2，其他五行 ×0.2，普攻 ×0.25）。所以**带什么法术出门，取决于要去哪里、会遇到什么盾**，这是搜打撤"出门前规划"的核心决策之一。

## 1. 三个方向共有的东西

| 锁定栏 | 清墨圆相 + "锁"字 + 一行小字"练气 X 层解锁"；点锁定栏、往锁定栏里拖，都会提示同一句话 |
| 技能签 | 一笔圆相 + 意象图标（`iconForSkill`，用户已选定）+ 同色淡晕。法术与阵盘的圆相用五行色，和 HUD 技能栏一致（金 #9a7d34、木石绿、水石青、火朱砂、土赭石）；法宝用品级色（只取 `RARITY`），仙 / 极加角印；心法用浓墨 |
| 操作 | 拖签入栏；栏间拖动换位；拖出栏外卸下；点选（先点签再点栏，或先点栏再点签）；悬停法术按 Q / E / R、悬停阵盘按 T 直接装入；Esc 取消选中 |

| 本区域常见护盾 | 每个去处列出"谁 · 在哪 · 什么盾 · 多寡"，给一句建议（"南半多土盾 → 宜带木行；北半火、土各半 → 水 + 木"），再算一行"已带"覆盖：`土盾 ✓ 缠藤诀 · 火盾 ✗ 缺水 · 木盾 ✓ 剑气斩`。建议里提到、已领悟但没带的法术给一个"换上" |

护盾数据来源：青岚山外精英狼妖头目木盾、首领青牙木 → 土两段；竹海·溪谷 7 处精英点取 3，北 / 中 5 处火或土随机、南半 2 处只出土盾（`levels/r2.js elites`），按点位折算土盾约六成、火盾约四成；首领碧鳞火 → 土 → 木三段。

## 2. 三个方向

### 方向一 · 出行·随身（入口 a）—— 推荐
`a_xingqian.html` → `png/loadout_v2_a_xingqian.png`（默认）、`png/loadout_v2_a_hover.png`（悬停寒冰锥）

- 底子就是现在的出行准备：扇面去处、去处列表、写意立绘、行囊纸笺、"启程"朱印都不动。
- **随身功法栏**在立绘下方，分三组，组间一道竖笔：Q / E / R ｜ T 阵盘 + 右键法宝 ｜ 心法一 / 心法二。和装备词条重复的心法在栏里灰显，并盖一方小朱印"叠"。
- **功法匣**：立绘右侧侧挂一张纸笺，可收起，默认展开在"法术"页签；四个页签是法术 · 心法 · 法宝 · 阵盘。
  - 每条是"签 + 名 + 一行小字"；已装的标朱点和栏位。
  - 未领悟的灰显并写出处；心法页顶上写"身上：青锋剑「锋锐」· 水灵佩「流云身法」"。
- **去处信息**多了三行：
  - "护盾"：竹海标"土 6 成 / 火 4 成"，并给两句建议；
  - "已带"覆盖：`土盾 ✓ 缠藤诀 · 火盾 ✗ 缺水 · 木盾 ✓ 剑气斩、剑阵`；
  - 建议里已领悟没带的法术给"换上寒冰锥"：先放空栏；没有空栏，就替换在本去处克不到任何盾的那一个。
- 好处：
  - 选去处、看护盾、换法术都在同一屏，决定就在出门前那一刻；
  - 护盾 ✓ / ✗ 加"换上"，把相克变成一个动作；
  - 沿用现有版式，改动面最小。
- 代价：
  - 这一屏更挤，行囊被压窄，委托区要挪（可以放到功法匣收起时的位置，或者做成行囊纸笺的第二页）；
  - 功法匣和立绘争中间；
  - 心法、法宝要切页签才看得到，护盾建议只管法术。

`c_wuxing.html` → `png/loadout_v2_c_wuxing.png`（从出行准备打开）、`png/loadout_v2_c_cave.png`（从洞府打开，悬停寒冰锥）

- **左侧"本去处"纸笺**：每组敌人写清谁 · 在哪 · 什么盾 · 多寡；"宜带"三行，各标已带 / 未带。

- 好处：
  - 把"敌人逼你换手"画成了图，缺哪一行最醒目；
  - 每个五行只有一个法术，签固定在节点上，等于把相克教学做进了界面；

  - 法宝、心法、聚灵阵不在盘上，被挤到侧边，像两套逻辑；

## 3. 入口推荐：(a) 出行准备里装配，洞府不单独开页

理由：

1. **决策和信息在同一屏。** 带什么法术取决于去哪儿、遇到什么盾；去处是在出行准备里选的。把装配放在别处，玩家要么先背下护盾再回洞府改，要么在出行页只能"快速换"，规划被拆成两半。
2. **所见即所带。** 搜打撤里出门前的最后一屏就是"清单确认"（随身装备、行囊、锦囊都在这里）；法术、心法、阵盘也是随身之物，放在同一张清单上最自然，不需要第二套保存逻辑。
3. **少一个入口。** 洞府已有灵泉、丹器房、仓库、天机镜、出行台五处，再加一页"功法"会稀释；而且洞府里本来不打仗，平时没有理由去改装配。
4. **洞府里只在两个时刻给快捷入口**（复用同一张功法匣，不另做一页）：
   - 参悟出新法术 / 心法之后：仓库"参悟"成功的提示里加一个"装上"（有空栏就直接放进去，没有就打开功法匣）；
   - 心魔试炼（练气九层 → 筑基）开打前：确认框里放"调整功法"。
5. 版式以方向一为主，把方向三的"缺哪一行"表达并进去：去处信息里的"已带"一行就是五行盘结论的文字版；如果用户喜欢五行盘，也可以把它做成功法匣里"法术"页签的背景图（法术按五行方位摆放），不单独成页。

## 4. 给用户的选择题

1. **入口**：A. 只在出行准备里装配（推荐）；B. 洞府·静室单独一页，出行只快速换法术；C. 两边都有完整装配。
2. **版式**：A. 方向一"功法匣"纸笺（列表）；B. 方向二"周天图"（栏位挂在立绘经络上）；C. 方向三"五行盘"（法术按五行方位摆放）。也可以组合，例如"方向一的功法匣 + 方向三的五行盘作法术页签的背景"。
3. **空栏要不要自动补**：A. 不自动补，空栏就是空栏，出行页给"R 栏空着"的提醒（推荐）；B. 只在"参悟新法术 / 突破解锁新栏"那一刻自动放一次，之后完全由玩家决定；C. 保持现状，局内每次都按已学会的顺序补满。
4. **心法同名**：被装备词条提供的心法，A. 灰显但允许装入，装入时提示"同名不叠加，这一栏等于空着"（草图做法）；B. 直接禁止装入；C. 不灰显，只在悬停里说明。

## 5. 实现要点（给后续开发）

### 5.1 数据放哪里
- 存档已有 `profile.build = { spells: [null, null, null], formation: null, xinfa: [] }`（`src/core/profile.js`），`loadoutOf()` 读它。建议**沿用这个字段**并固定形状，不新起 `profile.loadout`，省一次存档迁移：
  ```js
  profile.build = {
    spells: [id | null, id | null, id | null], // Q E R；未解锁的栏也保留值（不会被清掉），解锁后直接生效
    xinfa: [id | null, id | null],             // 两栏，定长
    formation: id | null,                      // 阵盘 = 已领悟的阵法 id（flags.learned.formations）
  };
  ```
  如果更想要 `profile.loadout` 这个名字，就在 `loadProfile` 里把 `build` 改名一次，字段相同。
- **法宝不进 build**：法宝是物品，仍然是 `profile.equip.artifact`（物品实例，带 uid、品级、祭炼等级、认主 / 本命，身陨时按 `gearRisk` 规则可能遗落）。装配界面的"法宝"栏只是 `equip.artifact` 的另一个入口，和储物袋 v2 随身栏里的"宝"是同一份数据。
- 可装配的来源：法术 `flags.learned.spells`、心法 `flags.learned.xinfa`、阵法 `flags.learned.formations`（仓库参悟时写入，`facilities.js study()`）；法宝 = 仓库 / 身上 `cat: "artifact"` 的物品。
- 校验（读档与装配时）：同一法术不能占两栏（放入时自动互换）；id 不在已领悟列表里就清掉；心法栏里与装备词条同名的不报错（同名不叠加由 `applyLoadout` 处理，界面只提示）。

### 5.2 局内能不能换
- **法术、心法、阵盘：局内不能换，只在出发前定。** "带什么出门"才是决策；局内能随时换，护盾就不再逼玩家规划，五行符 / 法剑附灵这些"没带对时的补救"也失去意义。
- **法宝：沿用装备规则**（储物袋 v2 局内可以把捡到的法器换上），因为它是物品，和法剑、法衣一致。
- 装备上的特殊词条心法照旧：局内换装备时 `SkillSystem.update()` 每 0.2 秒检查 `gx_<id>`，自动生效 / 撤掉。
- 局内暂停菜单可以**只读**显示当前装配与护盾克制，帮助回忆。

### 5.3 和 `run.js` 自动补栏的关系
- 现状：`loadoutOf()` 对空栏按 `flags.learned.spells` 顺序补位；心法栏为空时整栏用已领悟心法补上。有了装配界面后，这会让"故意空着"的栏在局内被填上，**出行页看到的和局内用到的不一致**。
- 建议：`loadoutOf()` 只读 `profile.build`，不再补位（`spells` 原样、`xinfa = build.xinfa.slice(0, xinfaSlots)`），并把"补位"挪到两个写存档的时刻：
  1. 参悟新法术 / 心法 / 阵法时：有解锁的空栏就写进 `build`（第一次学会剑气斩就自动在 Q 栏，新手无感）；
  2. 突破解锁新栏时（练气三层、四层、七层、八层）：从未装的已领悟里挑第一个写进新栏，并提示"新开 R 栏，已放入寒冰锥，可在出行时更换"。
- 老存档迁移：第一次读档时把当前 `loadoutOf()` 的补位结果写回 `build`，玩家看到的与之前局内一致。
- 出行页启程前检查：有解锁的空栏、但还有未装的已领悟法术时，"启程"印旁边写一行"R 栏空着"（不拦）。

### 5.4 其他
- 解锁文字统一从 `progression.js unlocks` 算（HUD 的 `SkillBar.lockText` 已这样做）；`skills.js REALMS` 里"练气五层 / 筑基"的旧解锁表只剩原型构筑面板在用，落地时不要再引用。
- 伤害数字按当前境界的 `heroStats` 现算（草图用基础属性；落地应加上装备、法宝被动后的法力 / 攻击，与 `SkillSystem` 结算一致）。
- 护盾提示的数据最好由关卡数据生成（`levels/*.js elites` 的 `shield`、`enemies.js` 的 `shield / shieldPhases`），不要手写在 UI 里；`REGIONS` 可加一个 `shieldHint` 文案字段，供"南半多土盾 → 宜带木行"这类一句话建议。
- 草图里的公用逻辑（`loadout_v2/data.js` 的 `place / swap / clear / pool / coverage / tipHTML`）基本可以照搬成 `src/ui/loadout.js`，界面层只换版式。
