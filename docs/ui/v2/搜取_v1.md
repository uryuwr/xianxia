> UI 设计主导，已落地。用户需求：击杀后尸体留在原地，按 F 搜，弹出格子，每格依次转圈探明，按颜色看品质；宝箱同理。

## 1. 交互

```
妖兽倒下（有掉落）→ 尸身定格成淡墨剪影，脚下一圈淡墨圆相，上方"F 搜 · 竹林狼妖遗骸"
F       → 容器旁浮起一小幅宣纸：格子全被墨封；神识一笔依次绕行每格，画满一圈墨封化开、字现
点格子  → 取这一件（飞入右上储物袋）
F       → 全取（已揭示的立刻取；还在探查的揭示后自动取）
Esc / 走动 / 受击 → 收起；进度保留（当前格已转的部分也保留），下次 F 从断点继续
取空    → 尸身立刻化墨散去（约 1.2 秒，墨烟同前）、容器释放；宝箱保持"已开启"
```

- 没有掉落的妖兽不留尸、不给提示，照旧倒地 1.5 秒化墨散去。
- 搜的时候世界不暂停——这是搜打撤的风险；受击（伤害 > 0）立刻收起，免得被打死在格子窗里。
- 奇遇 / 委托给的东西仍落地自动拾取（那是选择的结果，不是搜刮；奇遇标记也正好站在那个位置）。
- 采集（灵草、矿）保持即时采集，不进容器。

## 2. 视觉：墨封宣纸格

| 部分 | 做法 |
|---|---|
| 宣纸小幅 | 半透明纸色（α .82）+ 纸纹 + 窄纸条毛边（`--ink-deckle-slip`），外缘一圈 α .16 的墨边；约 230×200（1280×720 基准，随 `--mk-scale` 缩放）。浮在容器右侧 64px，靠右边缘（右侧留出天机镜 / 灵值的 230px）换到左侧，上下夹在顶部 HUD（110）与技能栏（130）之间；跟随容器的屏幕位置 |
| 标题 | 楷书 18px："竹林狼妖 · 遗骸"、"灵光宝箱"；下面一道淡墨细笔 |
| 神识小印 | 右上：一方圆印"识"（淡金 #a8862f）+ 行书数字（当前神识） |
| 格子 | 一笔圆相（`--ink-enso-1/2/3` 轮换），50px；占 2 格的物品是横向长圆，占 4 格的是 2×2 大圆；不画方框 |
| 墨封 | 一团浓墨：外层淡墨晕（`--ink-wash-round`，α .55）+ 内层浓墨点（`--ink-splash-1/2`，α .84，带飞白小点），每格随机转角 |
| 探查 | 一缕淡金神识（rgba(217,180,94,.95)）沿圆相一笔绕行（conic 渐变 × 圆相 mask，只改 `--v`），笔尖一点光（亮度与大小随品质：凡 .55 → 极 1.0 / 1.4 倍） |
| 揭示 | 墨封放大 1.4 倍淡去（"从中心散开"），字由 .82 倍长出；圆相换成品质色并弹一下；外圈晕开同品质淡彩（凡品不晕） |
| 仙品 | 笔走到 78% 处停一下（停 14% 的时长）再收笔；揭示时一团泛金的光外扩 |
| 极品 | 笔在 72% 处停得更久；合拢时八点朱金墨星径向迸开，世界顿帧 0.07 秒 |
| 预感 | 神识 ≥ 40：墨封下隐约透出品质色（2.4 秒呼吸）；强度 = 0.25 + 0.75 ×（神识 − 40）/ 80，最高 1（神识 120） |
| 已取 | 圆相褪成清墨、字淡到 .16；右下数量与晕都收起 |
| 放不下 | 格子左右抖一下，底部小字转朱"储物袋放不下"；物品留在格子里 |
| 底部 | 墨笔小字："全取 F"、"余 N 格未明 / 余 N 件"、"收起 Esc"，不做按钮框 |
| 收起原因 | 容器上方浮一行小字：受击 = 朱"受击 · 搜取中断"，走动 = 墨"走动 · 收起" |

**颜色只有一套品质**：圆相色、淡彩晕、字色、预感色、仙品泛金、极品朱金全部由 `src/core/items.js` 的 `RARITY` 推导（`src/fx/rarity_tint.js`：降饱和 25%、压暗、提亮），`src/ui/gather_ui.js` 启动时生成 CSS。神识的淡金是"神识"这个属性的颜色，不代表品质。

**尸身**：倒地动画放完（1.3 秒）后定格，toon 材质改成淡墨 #5b6064（α .85），后期墨线照常；取空后转 #9a9890（α .45）并立刻消散：身体 1.2 秒淡出并溅一团墨。脚下一圈凡品色淡墨圆相（精英 1.2 米、首领 1.6 米），不剧透品质。

**宝箱**：第一次 F = 开箱（掀盖、墨气、光——颜色按凡品，开之前不剧透）并打开格子窗；箱子从此保持"已开启"（`src/fx/gather_fx.js`），取空后交互标记移除。

## 3. 探查时长与神识

- 每格时长 = 基础 × 100 / (100 + 神识)；基础（按品质）凡 0.35 / 灵 0.5 / 宝 0.8 / 仙 1.2 / 极 1.8 秒；格间停 0.12 秒，打开后首格前停 0.18 秒。全部在 `src/game/run/containers.js` 的 `SEARCH` 里可调。
- 神识 `sense`：

| 来源 | 数值 | 写在 |
|---|---|---|
| 境界 | 凡人 0；练气一层 0，每层 +8（九层 64）；筑基 100 | `src/data/progression.js`（growth 追加 sense） |
| 玉佩词条"神识" | 灵 8 / 宝 12 / 仙 20 | `src/data/loot.js` AFFIXES（追加，只出在玉佩） |
| 心法《灵台》 | 神识 +30；探查完成时 10% 顺带探明下一格 | `src/data/items.js` XINFA `lingtai`；残卷 `xinfa_lingtai`（`items_db.js`）掉落：灵光宝箱 4%、遗府重探 10% |
| 凝神丹 | 本局神识 +20（出行前服用：带进出行局的第一枚在入图时服下） | `items_db.js` `ningshen_dan`；`recipes.js` 丹方 `ningshen`（凝露花 ×3 + 寒露草 ×1，炉 1 级，开局就会），`PILL_RULES.preRun` 追加 |

- 数值感受：练气一层宝品 0.8 秒、一个 6 格的狼妖尸约 3 秒；练气九层（64）快 39%；筑基（100）减半；筑基 + 灵台 + 仙品玉佩 + 凝神丹（170）只要原来的 37%。预感从练气六层（40）开始出现。
- 显示：洞府灵泉·静室左页"神识 N"，右页"破境所得"多一行神识；装备详情的词条显示"神识 +X"（`STAT_NAME` 追加）；局内只在宣纸格右上角显示，不加 HUD 条。

## 4. 规则与上限

- 尸体：有掉落才留；**取空后立刻化墨散去**（`SEARCH.corpseFade` 0.15 秒后开始，`fadeDur` 1.2 秒），容器同步释放；探查完但因储物袋满还有东西没取的一直保留，直到取空；本局最多约 30 具（`SEARCH.maxCorpses`），超出时最早取空的那具先散。地图的妖群"斩"按"遗骸取空或没有遗骸"打勾，兼容。
- 关键物品（`tags: ["key"]`）取出时进护身格（不占储物袋）；灵石等可堆叠物品照储物袋堆叠规则；放不下就留在容器里，并走原来的"储物袋已满"提示。
- 序章：锈剑放在溪边的一个容器里（"溪边的锈剑"），狼妖固定掉落放进最后倒下那只的尸身；"拾取"步骤的事实照常记录（`run.emit("pickup")`），宝箱步骤照常（`run.emit("chest")`）。

## 5. 接口（给流程组 A / 地图 / 其他模块）

`run.containers`（`src/game/run/containers.js`，`Containers`）：

| 方法 | 说明 |
|---|---|
| `on(fn)` → off | 订阅事件 `fn(type, data)`（见下表） |
| `open(c)` / `close(reason)` / `toggle(c)` | 打开 / 收起 / F 的行为（没开 → 开；开着 → 全取） |
| `take(c, i)` → bool | 取第 i 格（必须已揭示）；成功发 `take`，放不下发 `full` 并调用 `run.onBagFull` |
| `takeAll(c)` → n | 取所有已揭示的，并让之后揭示的自动取（窗口开着时） |
| `openChest(m)` | `run.interact` 的宝箱分支调用：第一次掷掉落（序章用 `pro.chestLoot`）、藏关卡模型、发 `run.emit("chest", m)` |
| `fromDrop(e)` | `loot:drop` 的处理：带敌人实体 → 留尸；否则落地 |
| `stash(pos, items, {label, glyph})` | 把物品放进 pos 附近的容器（附近有未取空的尸 / 遗物就追加；刚倒下的敌人就留尸；否则放一个遗物包） |
| `status(c)` | `{ id, kind: "corpse"\|"chest"\|"cache", label, pos, total, hidden, shown, taken, searched, empty, open, container }`——**未搜 = `!searched`，已搜 = `searched`，取空 = `empty`**（地图用） |
| `all()` | 全部容器的 `status` |
| `near(pos, r)` | 最近的容器 |
| `lootNow(c)` | 测试 / 调试：立刻揭示全部并走正常 `take`（会发 `pickup` 事件） |
| `openC` | 当前打开的容器（没有为 null） |
| `list` | 容器数组；容器的交互标记 `c.mark`（`kind: "loot"`，宝箱沿用原来的 `kind: "chest"` 标记，开过后 `m.container` 指向容器、`m.verb = "搜"`） |

事件：

| type | data | 时机 |
|---|---|---|
| `add` / `remove` | `{c}` | 容器出现 / 消散（追加物品也发 `add`） |
| `open` / `close` | `{c}` / `{c, reason}` | reason: `esc` `move` `hit` `far` `state` `empty` `switch` |
| `searchStart` | `{c, i, slot, need, resume}` | 第 i 格开始探查；`resume` = 从断点继续 |
| `progress` | `{c, i, slot, v}` | 每帧 0~1（同一个对象复用，监听者不要保存） |
| `reveal` | `{c, i, slot, inst, rarity, echo?}` | 第 i 格揭示（`echo` = 灵台顺带探明） |
| `take` / `full` | `{c, i, inst}` | 取走 / 放不下 |
| `interrupt` | `{c, reason}` | 受击 / 走动打断（随后会有 `close`） |
| `empty` | `{c}` | 取空 |

`slot = { inst, size, state: "hidden"|"search"|"shown"|"taken", t, need }`。可调参数都在 `SEARCH`（时长、神识公式 `SEARCH.sense(run)` / `SEARCH.need(inst, run)` / `SEARCH.foresee(run)`、上限、保留时间）。`run.senseOverride` 可在测试里直接指定神识。

## 6. 性能

- 尸身交接后骨骼只算最后一次（`skeleton.update` 换成空函数）、整棵节点矩阵冻结，30 具尸体不占每帧的骨骼与矩阵更新；动画混合器不再更新。
- 每帧逻辑不拷贝数组；`progress` 事件复用同一个对象；窗口每帧只改有变化的 CSS 变量（变化小于 0.5% 不写），跟随位置只在像素变化时写 transform，`--mk-scale` 只在打开时读一次。
- 揭示动效只动 opacity / transform；采下用的圆相按品质放进对象池复用；同时最多 6 个飞入储物袋的格子。

## 9. v2：物品签格子 · 先露形后显色（用户已确认草图 `docs/ui/v2/loot_v2/index.html`，已落地）

- 名称行：格子里不再有字；悬停或揭示时宣纸底部显示"名称 · 品质 · ×数量"（名称字色取 RARITY），平时是"余 N 格未明 / 余 N 件 · 点选取物"；放不下时朱字"储物袋放不下"。
